# 回看过去

## 步骤

1. 运行 `kaitu status --json-out`，确认当前目标与用户时区。
2. 把过去 N 天换算成明确的起止日期，包含今天时说明。
3. 先明确用户关心的目标，不扩大到全部人生总结。
4. 运行 `kaitu record list workout --from 起日 --to 止日 --json-out`。
5. 按问题查询 meal、sleep、activity、metric 或 event。
6. 读取 reviews/daily/、reviews/weekly/ 和 reviews/monthly/ 中覆盖该区间的文档。
7. 用 `kaitu chats search "目标关键词" --json-out` 检索历史对话。
8. 必要时换用具体项目、障碍或习惯关键词继续搜。
9. 搜索结果按日期筛选，正文不足时读对应 chats/ 消息。
10. 对照当时计划与实际行为，避免只拿今天的目标评判过去。
11. 先列事实时间线，再列支持程度不同的原因解释。
12. 缺记录与没做是两回事，需要时简短追问。
13. 多个来源冲突时写清冲突，别自行选择方便的说法。
14. 每个重要判断带记录日期或来源路径。
15. 把用户原话、记录事实和 Agent 推测分开表述。
16. 给出一到三个能验证原因的小动作。
17. 用户要保存时写入相关复盘文件。
18. 保存后运行 `kaitu validate`。
19. 再运行 `kaitu snapshot -m "Agent 保存了阶段回看"`。

## 确认点

回答本身无需确认；若建议改变规则或目标，先确认再改。

## 交付

直接回答原因与证据边界，避免把相关性当成确定因果。
