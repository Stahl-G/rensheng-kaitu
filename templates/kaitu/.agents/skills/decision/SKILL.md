# 辅助决策

## 步骤

1. 读取 decisions/module.json、已有决策目录与相关记忆。
2. 明确要决定的问题、截止时间和可逆性。
3. 用 `kaitu chats search "决策关键词"` 找已有约束，避免重问。
4. 创建或沿用 decisions/<slug>/，不覆盖旧决策。
5. 列出真实可选方案，包括暂不决定的后果。
6. 只询问会改变选择的预算、时间和必须满足的条件。
7. 把判断标准分成硬约束与偏好，标准来自用户。
8. 核实当前会话实际可获得的事实，资料不足写待补。
9. 对每个候选给出收益、成本、风险与关键未知数。
10. 不编造报价、资格、官方政策或模型意见。
11. 需要第二意见时先说明范围，只有具备可用工具时才调用其他模型。
12. 把分析写入 decisions/<slug>/analysis.md，并保留实际来源。
13. STATUS.md 的 next 放需要补的证据或用户拍板事项。
14. 用户未选定前，明确保留为待决定。
15. 用户选定后记录选择、理由、日期与放弃其他方案的原因。
16. 列出可观察的复议条件，避免无条件反复推翻。
17. 需要落实时只生成下一步，外部付款、预订或联系另行授权。
18. 运行 `kaitu validate decisions`。
19. 运行 `kaitu snapshot -m "Agent 更新了决策档案"`。

## 确认点

用户本人确认最终选择；涉及规则、目标或外部动作按对应确认处理。

## 交付

给出建议及取决于什么，保留用户的最终决定与复议条件。
