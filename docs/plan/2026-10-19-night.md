## 规则

1. **分支**：每个仓库一条 `codex/night-1019`，一个任务一个提交（提交说明以任务号开头），开一个草稿 PR 持续更新。不合并、不 force push、不动别人的分支。
2. **检查**：主仓库按 desktop-next.md 开头的命令；iOS 跑 KaituKit 测试和 `scripts/run-ui-check.py`。红了不提交。
3. **数据**：只用合成数据（`schemas/fixtures/phone/`、合成工作区），不碰真实工作区和凭据。
4. **格式**：PRD §6 和 `schemas/` 不改；需要改写进晨报等用户定。
5. **不做**：不上传 App Store Connect、不提交审核、不改签名和 Bundle ID、不发布 kaitu.si、不发 Windows / Mac 安装包。
6. **卡住**：同一个错修三次不过，或一个任务超过预估两倍，停下写进晨报，做下一个。
7. **写法**（AGENTS.md 第 5 条）：
   - 入口校验一次，里面不再查；不为不可能的情况写分支、错误类型、重试。
   - 一个实现不建 protocol；没有调用者的参数和抽象不写。
   - 先搜仓库有没有现成的函数，不复制粘贴。
   - 界面请求只读内存；慢活放后台。
   - 测试只测行为，一个行为一个测试。
   - 能删就删；新增远多于删除时在提交说明里解释。
   - 宽窄屏不写 `if wide { A } else { B }` 换整棵树（WIDE-duo.md「不要做」）。
