# 功能需求：新手引导（「孙宇晨的方法」）

- 版本：v0.1（草案）
- 日期：2026-10-15
- 所属：PRD §0 北极星「任何人都能用孙哥方法用 AI」；PRD §3.3 场景 1「第一次使用」
- 相关：`docs/design-brief.md`（DSH 版界面中的对话抽屉与首次使用）、`templates/kaitu/.agents/skills/onboarding/SKILL.md`、HANDOFF D20（Google Drive 模式）、D21（项目模块）

---

## 1. 背景与问题

产品目标是：用户**不用看四个多小时的访谈**，打开开图、跟着引导走，就知道怎么用孙宇晨的方法用 AI。

当前工作台（`kaitu init` 后的空工作区）首页只有一张「从这里开始」卡片，列了三步：导入 ChatGPT 记忆、去「我的」看档案、对 Agent 说「早上好」。新用户实际走会卡在三处：

1. **只说了点哪里，没讲方法。** 用户不知道孙宇晨是怎么用 AI 的，也不知道这套东西能帮自己做哪些事。
2. **第 3 步过不去。** 「对 Agent 说早上好」要求用户自己在某个文件夹里打开 Codex 或 Claude Code，页面顶部只显示一串绝对路径。
3. **空页面没有引导。** 各页没有数据时只显示「还没有……」，用户不知道该做什么。

## 2. 目标与非目标

**目标**

- G1：30 秒内让用户明白「孙宇晨的方法」是什么，以及开图怎么帮他照做。
- G2：用户选一件最想先做的事，引导直接带他做第一步，而不是让他自己找功能。
- G3：带用户连上 AI 助手（本机 Codex / Claude Code，或通过 Google Drive 的云端助手），拿到第一份「今天」计划。
- G4：任何页面空着的时候，都告诉用户「孙宇晨怎么做 → 你在这里怎么做」，并给出可点的第一步。
- G5：用户先打开 AI 助手而不是工作台时，助手讲的方法和给的选择与工作台一致。

**非目标**

- 不做视频、动画教程，不引用大段访谈原文。
- 不在本功能内实现内置对话（DSH 阶段再做，见 §9）。
- 不收集任何使用数据或埋点。

## 3. 成功标准

| 标准 | 检验方式 |
|---|---|
| 不看访谈、不读 README 也能上手 | 找 3 名没看过访谈的新用户，只靠界面引导，在 **10 分钟内**完成：导入记忆（或跳过）→ 连上 AI 助手 → 拿到第一份「今天」计划。至少 2 人完成 |
| 看完能说出方法 | 看完 3 屏后问「这套方法是什么」，用户能用自己的话说出「数据交给 AI、AI 给计划和日报、我只看和确认」中的至少两点 |
| 引导不打扰老用户 | 已看过引导的工作区，重新打开不再弹出；清单全部完成后自动收起 |

## 4. 用户流程总览

```
第一次打开工作台
  └─ ① 方法介绍（3 屏，约 30 秒，可跳过）
       └─ ② 你想先从哪件事开始？（多选卡片）
            └─ ③ 进入「今天」页，顶部出现「开始清单」
                 ├─ 导入 ChatGPT 记忆
                 ├─ 连上 AI 助手
                 ├─ 拿到第一份「今天」计划
                 ├─ 你选的事的第一步（每选一项一条）
                 └─ 第一次晚间复盘（拿到首份计划后出现）
各页面空状态 → 迷你引导（孙宇晨怎么做 → 你怎么做 → 按钮）
「我的」→「孙宇晨的方法」：随时重看 ①②
```

## 5. 详细需求

### 5.1 方法介绍（3 屏）

**触发**：打开工作台时，工作区的 `onboarding.introSeenAt` 为空。全屏覆盖显示，底部有进度点、「下一步」「跳过」。跳过与看完都记为已看过（写 `introSeenAt`），跳过时直接进入 ②。

**文案定稿（实现时直接使用；改文案只改 §6.1 的内容文件）**

第 1 屏：**他是怎么用 AI 的**

> 孙宇晨把生活交给 AI 管，自己只做三件事：
>
> ① **把数据都给 AI**：吃饭拍照、戒指记录睡眠、训练记下重量
> ② **AI 每天给他计划和日报**
> ③ **他只花 10% 的时间看结果、做调整**
>
> 「90% 的时间让 AI 开，我自己 10% 的时间调一下 AI。」（访谈节选，00:21:16）

第 2 屏：**开图帮你做同样的事**

> （循环示意图）随手记录 → AI 助手整理 → 早上给你今天的计划 → 你点确认 → 晚上 AI 助手帮你复盘
>
> 你的数据只存在你自己的电脑上。

第 3 屏：**你想先从哪件事开始？**（即 ②，见 §5.2）

**规则**

- 3 屏总阅读量控制在 30 秒以内：第 1、2 屏各不超过 80 个汉字（不含引语）。
- 第 1 屏角落固定小字：「灵感来自邵艾伦 × 孙宇晨的访谈，开图与二人无关联」。
- 界面文案使用正式姓名「孙宇晨」，不用「孙哥」（PRD §0 命名约束）。
- 全程不出现技术词：MCP、API、JSONL、git、frontmatter、终端命令（命令只出现在 §5.4 的「复制」按钮内容里）。「Agent」在界面上统一写作「AI 助手」。
- 支持键盘（←/→/Esc）；系统开启「减少动态效果」时不做切换动画。

### 5.2 起步选择（7 张卡片）

可多选，至少选 1 张才能「开始」；也可点「先随便看看」不选，直接进入「今天」。

| id | 卡片标题 | 一句话说明 | 对应访谈功能（PRD §4） | 选择后写入 | 首个动作（清单里的一条） |
|---|---|---|---|---|---|
| `fitness` | 练出薄肌 | 记训练、看体重体脂变化，AI 帮你安排下次练什么 | #2、#5 | `health/STATUS.md` 增加一条 next：「记录第一次训练」 | 去「健康 · 训练」记一次训练 |
| `eat-sleep` | 吃好睡好 | 记饮食和睡眠，AI 帮你算热量和蛋白质 | #3、#4 | `health/STATUS.md` 增加 next：「导入健康数据或记一餐」 | 导入 Apple Health，或记一餐 |
| `know-myself` | 了解自己的现状 | 把你的情况交给 AI，攒够数据后给你一份现状分析 | #1 | `me/STATUS.md` 增加 next：「补全档案」 | 导入 ChatGPT 记忆并补全档案 |
| `news` | 每天看行业动态 | 选几个关注的方向，AI 每天给你一份简报 | #7 | `feed/STATUS.md` 增加 next：「选关注方向」 | 在「动态」选关注方向 |
| `learn` | 学一样新东西 | 告诉 AI 想学什么，它帮你整理资料、纠正误解 | #8 | `learning/module.json` 不变；`NOW.md` attention 增加：「告诉 AI 助手你想学什么」 | 对 AI 助手说「帮我学 ___」 |
| `decide` | 想清楚一个决定 | 先把选项看全，再做决定 | #9 | `NOW.md` attention 增加：「告诉 AI 助手你在纠结什么」 | 对 AI 助手说「帮我决定 ___」 |
| `project` | 推进一个项目 | 记下手上的项目，AI 帮你盯进度 | D21 项目模块 | `NOW.md` attention 增加：「告诉 AI 助手你在做的项目」 | 对 AI 助手说「帮我建一个项目 ___」 |

说明：

- 访谈中的 #6 日程与 #10 复盘不单独成卡，它们是每天的固定节奏，体现在清单的「第一份计划」「第一次晚间复盘」两条里。
- 选择写入的 next / attention 条目使用固定 id `onboarding-<卡片 id>`（据此去重），带 `by: "onboarding"`，与普通条目一样可完成、可删除。attention 条目的 `kind` 为 `"onboarding"`。整次选择只生成一个版本，可在「历史」里恢复。
- 在界面上点选即视为用户本人确认，不再弹二次确认（PRD §7.5 的确认要求在此满足）。
- 本功能**不**直接修改 `me/goals.json`。目标由 AI 助手在后续对话中提出、用户确认后写入。
- 「项目」模块若尚未实现（模板中暂无 `projects/`），`project` 卡片隐藏。

### 5.3 开始清单

**位置**：「今天」页顶部，取代现有「从这里开始」卡片。

**条目与完成条件**（完成状态全部从工作区现有数据**实时计算**，不单独存储）：

| 条目 | 显示条件 | 完成条件 | 按钮 |
|---|---|---|---|
| 导入 ChatGPT 记忆（约 2 分钟） | 总是 | `memory/` 中有至少 1 条记忆，或用户点了「我没用过 ChatGPT」 | 开始 → 设置 · 导入 · ChatGPT 记忆 |
| 连上 AI 助手 | 总是 | 满足任一：MCP 服务记录到过客户端连接；任一记录 `by` 为 `agent`；`NOW.md` 由助手生成过 | 怎么连 → §5.4 面板 |
| 拿到第一份「今天」计划 | 总是 | `NOW.md` 存在 `generated_at` | 复制这句话给 AI 助手：「早上好，帮我安排今天」 |
| 你选的事的第一步（每项一条） | 用户在 §5.2 选了对应卡片 | 见下表 | 对应页面 / 复制句子 |
| 第一次晚间复盘 | 「第一份计划」已完成 | `reviews/daily/` 下有至少 1 份日报 | 复制：「复盘一下今天」 |

起步卡片的完成条件：

| id | 完成条件 |
|---|---|
| `fitness` | `health/data/workouts/` 至少 1 条有效记录 |
| `eat-sleep` | meals 或 sleep 至少 1 条有效记录 |
| `know-myself` | `me/profile.md` 与模板内容不同 |
| `news` | `feed/feeds.json` 中关注方向或订阅源非空 |
| `learn` | `learning/` 下至少 1 个主题目录 |
| `decide` | `decisions/` 下至少 1 个决策目录 |
| `project` | `projects/` 下至少 1 个项目目录 |

**行为**

- 已完成的条目打勾并移到清单底部；全部完成后显示一次「都完成了，接下来每天早上说一句『早上好』就行」，次日起不再显示。
- 清单右上角「隐藏」：写 `onboarding.checklistHiddenAt`；之后可在「我的 · 孙宇晨的方法」恢复。
- 复制按钮复制的是一句完整的话，复制后提示「已复制，粘贴给你的 AI 助手」。

### 5.4 连上 AI 助手

点「怎么连」打开侧边面板，按检测结果显示对应说明：

| 情况 | 检测方式 | 面板内容 |
|---|---|---|
| 本机装了 Codex 和/或 Claude Code | core 在 PATH 中查找 `codex`、`claude` | 「复制启动命令」按钮（内容见下），三步图示：打开终端 → 粘贴 → 对它说第一句话 |
| 已开启 Google Drive 模式 | 读取 Drive 模式状态（D20） | 「在 Grok Bot / ChatGPT Dots 里连上 Google Drive，然后对它说：」+ 复制「请读 kaitu/AGENT-README.md，然后带我开始使用开图」 |
| 都没有 | — | 两个选项：① 安装 Codex 或 Claude Code（官方安装页链接）；② 开启 Google Drive 模式（跳转设置） |

启动命令按系统生成，路径来自当前工作区，带引号：

- macOS / Linux：`cd "<工作区路径>" && codex`（或 `claude`）
- Windows PowerShell：`cd "<工作区路径>"; codex`

面板底部固定第一句话的复制按钮：「请读 AGENTS.md，然后带我开始使用开图」。

顶部现有的「和 Agent 对话：在 <路径> 打开 Codex 或 Claude Code」提示条改为一个「连上 AI 助手」按钮，打开同一个面板；清单中「连上 AI 助手」完成后，提示条隐藏。

### 5.5 空状态引导

所有页面（及健康的 4 个子页）没有数据时，统一显示一张引导卡，结构固定：

```
孙宇晨是这样做的：<一句话>
你可以：<一句话>            [主按钮]
或者对 AI 助手说：「<一句话>」 [复制]
```

文案定稿：

| 位置 | 孙宇晨是这样做的 | 你可以 | 主按钮 | 对 AI 助手说 |
|---|---|---|---|---|
| 今天 · 时间线 | 每天早上让 AI 根据日程和身体状态排好当天 | 让 AI 助手给你排今天 | 复制这句话 | 早上好，帮我安排今天 |
| 健康 · 训练 | 每次训练记下动作、组数和重量，下次加一点 | 记下这次训练 | 记录训练 | 今天深蹲 3 组每组 12 个，60 公斤 |
| 健康 · 饮食 | 饭前饭后各拍一张照片，让 AI 算热量和蛋白质 | 记一餐，或导入饮食应用的数据 | 记一餐 | 午饭吃了一份鸡胸肉饭 |
| 健康 · 睡眠与活动 | 戴戒指记录睡眠和消耗，和饮食合起来看 | 导入 Apple Health 数据 | 导入 | （无） |
| 健康 · 身体指标 | 定期记体重体脂，每半年拍照对比；主动去医院查血脂血糖 | 记一次体重，或上传体检报告 | 记录 | 帮我看看这份体检报告 |
| 动态 | 自己刷加上 AI 帮着抓，盯住最感兴趣的方向 | 选几个关注方向 | 选方向 | 帮我每天整理 AI 和科技新闻 |
| 我的 | 先把自己的情况交给 AI，攒几个月数据再让它分析 | 导入 ChatGPT 记忆，补全档案 | 导入 | 根据我的情况帮我补全档案 |

### 5.6 重看入口

「我的」页增加入口「孙宇晨的方法」：可重看 3 屏介绍、重新选择起步卡片（追加，不删除已有条目）、恢复已隐藏的清单。

### 5.7 AI 助手侧保持一致

- 引导内容只有一份（§6.1），`AGENTS.md` 生成器与 onboarding 技能读取同一份内容。
- onboarding 技能的开头改为：先运行 `kaitu onboarding status`；若 `introSeenAt` 为空，用第 1、2 屏的内容讲三句话，再列出 7 个起步选项让用户选；用户的选择通过 `kaitu onboarding start <id...>`（或 MCP 工具 `onboarding_start`）写入，效果与工作台点选完全一致。
- 助手完成清单中的事项后，不需要额外标记，清单状态由数据实时计算。

## 6. 数据与接口

### 6.1 引导内容

`packages/core/src/method.ts` 导出只读常量 `METHOD`：

```ts
{
  intro: [{ title, lines: string[], quote?: { text, ts } }, ...],   // 第 1、2 屏
  disclaimer: string,
  starts: [{ id, title, summary, interviewRefs: number[], effect, firstStep, done }, ...],
  emptyStates: { [slot: string]: { how, you, action, say? } },
  firstSentence: string
}
```

界面、`AGENTS.md` 生成器与技能共用。文案修改只改这一个文件。

### 6.2 状态存储

`.kaitu/config.json` 新增可选字段 `onboarding`，同步修改 `schemas/config.schema.json`：

```json
"onboarding": {
  "introSeenAt": "2026-10-15T09:00:00+08:00",
  "starts": ["fitness", "news"],
  "skippedImport": false,
  "checklistHiddenAt": null
}
```

只存「用户做过的选择」，不存「完成状态」。Drive 模式下该字段跟随 `.kaitu/config.json` 留在本机。

**数据规范的小改动（PRD §6，需用户确认后实施）**：`status.schema.json` 的 `next[]` 与 `now.schema.json` 的 `attention[]` 各增加可选字段 `by`（字符串，取值 `user` / `agent` / `onboarding`）。现有 schema 未禁止额外字段，但应显式写明，并同步更新 `AGENTS.md` 生成模板中对这两类条目的说明。

### 6.3 core 函数

| 函数 | 作用 |
|---|---|
| `onboardingStatus(ws)` | 返回引导状态与清单各条目的完成情况（按 §5.3 实时计算） |
| `markIntroSeen(ws)` | 写 `introSeenAt` |
| `applyStarts(ws, ids)` | 校验 id，追加写入 §5.2 的 next / attention 条目（已存在同一条则跳过），更新 `starts`，整次生成一个版本，版本说明「新手引导：选择从 练出薄肌、每天看行业动态 开始」 |
| `detectAgents(ws)` | 返回本机是否有 `codex`、`claude`，以及 Drive 模式状态与各系统的启动命令 |
| `setOnboardingFlag(ws, flag, value)` | 处理 `skippedImport`、`checklistHiddenAt` |

MCP 服务在客户端初始化时记录 `clientInfo.name` 与时间，供「连上 AI 助手」判断（存本机状态目录，不进版本历史）。

### 6.4 工作台接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/onboarding` | `METHOD` 内容 + `onboardingStatus` + `detectAgents` |
| `POST /api/onboarding/seen` | `markIntroSeen` |
| `POST /api/onboarding/start` | body `{ ids: string[] }` → `applyStarts` |
| `POST /api/onboarding/flag` | body `{ flag, value }` |

写接口沿用现有的串行写入与来源校验。

### 6.5 命令行与 MCP

- `kaitu onboarding status [--json]`、`kaitu onboarding start <id...>`、`kaitu onboarding reset`（清空 `onboarding` 字段，用于测试与重新体验）。
- MCP 新增工具 `onboarding_status`、`onboarding_start`。

## 7. 隐私

- 不发送任何数据。完成情况、选择都只在本机。
- 若需要统计「从打开到拿到首份计划用了多久」，只用 `introSeenAt` 与 `NOW.md` 的 `generated_at` 在本机计算，在 `kaitu doctor` 中显示，供用户测试时人工记录。

## 9. DSH 阶段的变化

`docs/design-brief.md` 规划了 DSH 版的底部输入条与右侧对话抽屉。届时：

- §5.1、§5.2 不变，作为 DSH 前端插件重新实现，内容仍取自 `METHOD`。
- §5.4「连上 AI 助手」从清单中移除（内置对话即已连上）；保留「也可以用 Codex / Claude Code / 云端助手」作为高级选项放在设置里。
- 清单中的「复制这句话」改为「点一下直接发给 AI 助手」，抽屉自动展开（与 design-brief「首次使用：抽屉自动展开」一致）。
- 当前 Preact 工作台按 GOAL 的约定不打磨样式，本功能在其中做到可用即可；`METHOD`、状态、core 函数与接口在 DSH 阶段直接复用。

## 10. 测试

按 HANDOFF §8 的测试原则，只写以下行为测试：

- `onboardingStatus` 在空工作区、样例工作区、各条目刚好满足条件时的结果。
- `applyStarts` 重复调用不产生重复条目；整次只生成一个版本，恢复该版本后条目消失。
- `detectAgents` 在 PATH 中有 / 无 `codex`、`claude` 时的结果，以及含空格路径的命令引号。
