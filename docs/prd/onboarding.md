- 版本：v0.5
- 日期：2026-10-16
- 产品依据：[PRODUCT.md](../PRODUCT.md)（北极星首批：搬进来就看得见、剪贴板整理、资料包、状态如实、英文界面）

## 目标与成功标准

新用户把一件正在推进的事带进开图，保存原文、核对草稿、采纳一个下一步，三分钟内获得第一份自己的进度。
搬记忆是并列入口；选事情、接数据、选 AI 从今天页清单按需进入，不阻挡第一次采纳。

首发验证三分钟内保存自己的内容、采纳一个下一步并找到依据，记录求助次数与卡点。
保留体验标准：3 名新用户中至少 2 人在 10 分钟内完成一个可用的记录或导入动作、找到清单并理解下一步。
真人任务观察不能由自动测试或 Agent 自评替代。已有数据的工作区换电脑不自动弹引导。

## 首次流程

### 欢迎与说出想改变的一件事（默认入口）

欢迎说明：让 AI 持续了解你，把想改变的事变成能推进、能查回的个人进度。首批同时照顾已有 AI 计划和仅用过 chatbot 的用户。第一步直接写或粘贴对话，约三分钟。

主问题为「最近有什么想改变，却一直没推进？」。三个示例按钮分别填入吃饭训练、工作方向、作品集内容，不自动保存。核对页及依据按原文角色标记区分对话与自述。

粘贴一段对话或写下想改变的事。先调用现有 captureNote 保存至 inbox/notes，再整理。
已连接问问时复用 Ask 会话生成草稿；DSH 使用当前原生会话，matter-draft 保存待核对建议。
未连接 AI 时，草稿页标题为「写下你的目标和一个下一步」，下方是剪贴板整理：复制 core `matterPrompt` 生成的整理提示词（含原文），发给常用的 AI，再把回答贴回。
`pasteOnboardingMatter` 宽容解析中英文标签（【目标】【现状】【下一步】【路径】/ [Goal] [Now] [Next] [Path]）或 JSON，忽略前后客套话和代码块，得到与 AI 整理相同的待核对草稿；两条以上路径时不预选下一步。读不到目标、下一步或路径格式不对时说明缺了哪项，原文不动。
也可以由用户手工填写当前目标、已知现状、一个下一步。字段均可修改。
已连 AI 且不清楚该做什么时，AI 生成 2–3 条可能路径，名称、适合理由、未知和低成本小实验全部供核对。路径存于既有 proposed 建议的 Markdown 正文，没有预选项。用户选中后填入小实验，可继续修改；未选择不能采纳这组建议，仍可只保存原文。

只有「采纳这个下一步」才添加一条待办；「只保存原文」不生成待办。其他建议保留在原文，不自动采纳。
重复采纳同一段原文返回已有待办，来源用现有 task.source，目标、现状和结果用 task.notes。
采纳时把目标登记进 me/goals.json：同名的进行中目标直接复用，否则新建，只用 id、title、status 三个既有字段。
id 写成 `<来源>-<YYYYMMDD>-<6 位摘要>`（来源为 note、conversation 或所选 AI），界面据此显示「你写下的 · 10/16」等来源；待办 notes 加一行 `目标编号：<id>`。采纳后原文归档，不再算待整理。
AI 草稿复用 me/STATUS.md 的 proposed 下一步与 ref，目标和现状放 Markdown 正文，不增加数据字段。

今天页在清单上方展示刚采纳的下一步、目标与原文依据。原文归档后仍可读回。
「完成并记一句结果」和「改到以后」均通过已有任务追加修订；提交检查当前修订号，刷新后结果保持。

### 从常用的 AI 搬来记忆（并列入口）

先选最常用的 AI：ChatGPT、Claude、Gemini、豆包、其他（只列有长期记忆的 AI；DeepSeek 聊天不跨对话记忆，不单列）。
界面展示该 AI 的「记忆在哪」提示，以及 PRD 附录 A 的提示词，支持复制。
用户发给原来的 AI，把回答粘贴回来，也可以同时粘贴 ChatGPT「管理记忆」列表。

点击预览后按类别分组，默认全选，每条可取消勾选。
目标、项目、在考虑的事三组每条带去处选择，默认分别是「设为目标」「建为项目」「放进方向」，也可改成「记为记忆」。英文提示词与类别见 `onboarding-en.ts`，解析同时认中英文类别。
按 `[类别] 内容 （时间）` 逐行解析，支持半角括号、列表前缀和纯文本行。
已知类别映射到现有 preference、fact、context、person、decision 五种类型，原分类仍供预览分组。
未知类别和不合格式行原样保留为 context，不自动丢弃标题、说明或其他文字，由用户决定保留。
时间保留在记忆正文中，导入日期使用现有 created/updated 字段，不新增数据字段。
与已有记忆正文完全相同的候选和本批重复项去重。

行尾括号只有像日期时才当作「记下的时间」，「（优先 macOS）」「（取决于孩子入学）」这类条件留在正文里。已有记忆只和要记成记忆的条目去重，同样的话仍可设为目标、项目或方向。
确认只接受这次预览的候选 ID，记忆调用现有 importMemories；进目标、项目、方向的原文行整段存进 `inbox/notes/done/<日期>/`（kind 为 import），日期和条件都能查回；项目按完整内容判断重复，截短的标题撞名时加序号；目标写入 me/goals.json（id 前缀为所选 AI），项目用 createProject 并在 notes.md 写来源，方向用 create_direction（用户已在预览确认，by 为 user，动机写「从 X 搬来：」加完整原文）。同名的目标、方向不重复建。工作区没有方向模块时，「在考虑」默认记为记忆，确认前先检查，不会写一半报错。全部在一个 batchSnapshot 里，整批一个版本。
来源为「从 ChatGPT 搬来」等用户所选 AI，预览后的取消勾选不会被重新加入。
确认时再次剔除已经写入的相同正文。返回 before 和 version，可从历史恢复导入前版本。
预览令牌 30 分钟后失效，成功后消费，取消时清理暂存。

可选入口「导入 ChatGPT 数据导出包」复用 importChatgptConversations 的预览与确认，不把对话记录冒充为已提取的记忆。

## 今天页的可选面板

各面板顶部「← 回到今天」、底部「完成」，均不推进到其他必经步骤。

### 先管哪些

可多选，也可先随便看看。
下表说明产品关系，运行时标题、提示词、数据源与映射只定义在 core 的 ONBOARDING 常量中。

| 选项 ID | 事情 | 需要的数据源 | 写入下一步的模块 |
|---|---|---|---|
| me | 了解自己的现状 | 邮件和聊天 | me |
| projects | 推进手上的项目 | 项目 | projects |
| health | 吃好、睡好、练好 | Apple 健康 | health |
| finance | 管好钱 | 账单与持仓、邮件和聊天 | finance |
| calendar | 把日程排明白 | 日历 | calendar |
| explore | 想清楚一个方向 | 无须先接数据 | explore |
| news | 每天看点有用的资讯 | 关注方向 | feed |

选择写入对应模块 STATUS.md 的 next，固定 ID 为 `onboarding-<选项 ID>`。
每次选择整批至多一个版本，相同 ID 已存在时不覆盖、不重复添加。重新选择不删除旧下一步。
只用既有 id/title/status 字段，不修改规则或目标。

### 接上数据

只展示所选事情需要的数据源，合并重复项。每项可跳过，也可全部先跳过。
所有导入与设置都先预览，再由用户确认写入。

| 数据源 | 现有入口 | 完成依据 |
|---|---|---|
| 日历 | ICS 订阅 | 有有效 event 记录或订阅已成功同步 |
| Apple 健康 | export.zip / export.xml 预览、确认 | 有健康记录或体检数据 |
| 账单与持仓 | 现有 financeImportPreview / Commit / Discard | 有财务记录 |
| 项目 | 本机文件夹与项目档案预览、确认 | 项目有本机链接或有效 GitHub 快照 |
| 邮件和聊天 | AI 与连接中的渠道设置 | 已收取邮件、聊天摘录或有效对话消息 |
| 关注方向 | 关键词预览、确认，追加到 feed/feeds.json | 有关键词、订阅源或资讯数据 |

项目的 GitHub 核验与同步复用现有项目接口；连接渠道不等于已经收取数据。
财务只列已有适配器支持的格式，不扩大声称支持的银行或平台。

### 选一个 AI

- 用开图里的「问问」：进入 DeepSeek API Key 配置。
- 在原来的 AI 里继续：进入「AI 与连接」的资料包（launch L3.1），复制给原来的 AI，回答贴回后进入上面的核对页。
- 先不用 AI：直接使用记录与导入。

选择 AI 方式不等于已经连接成功。配置回读、MCP 初始化或 DSH 工具实际调用留下本机连接回执。
不因引导选择自动创建计划或自动任务，已有自动任务继续走产品现有设置流程。

## 「开始使用」清单

「今天」页顶部显示完成数 / 总数与进度条，每项提供一个「去做」入口。
清单固定六项，接数据在没有选择事情时不可点击。

| 条目 | 完成依据 | 动作 |
|---|---|---|
| 带来一件事并采纳第一个下一步 | 带有原文来源和目标的实际待办 | 带来一件事 |
| 让开图认识你（可选） | 至少一条记忆 | 搬记忆 |
| 选你想先管的事 | 本机已选事情 | 选事情面板 |
| 接上数据 | 已选事情要求的数据源都有数据；不需要来源的选项直接满足 | 接数据面板 |
| 选一个 AI 帮你整理 | 连接回执、agent 记录或计划生成时间 | AI 面板 |
| 拿到第一份今天计划 | NOW.md 的 generated_at 或已确认/完成的计划块 | 计划入口 |

完成状态不保存。恢复或移除数据后，再查询会重新计算。
跳过是本机选择，独立返回 skipped，不算完成，不把进度填满。
全部完成时清单可自动收起，用户仍可从首次使用入口重看。

## 状态与共用内容

`packages/core/src/onboarding.ts` 的 ONBOARDING 是运行时内容唯一来源。
本地接口、DSH 服务、CLI 和 MCP 返回它，AGENTS.md 生成器直接引用，技能从 status 的 content 读取。
共享页面组件使用同一份返回值，不复制一套数组和提示词。

本机选择存于 `localStateRoot()/onboarding/<工作区路径标识>/choices.json`。
只保存 seenAt、starts、skipped、memoryAi、aiChoice。连接回执单列 ai.json，预览有独立令牌文件。
不进工作区、不改 config.json、不修改 schemas 或 PRD §6。
测试及隔离运行可用 KAITU_LOCAL_STATE_DIR，core 调用也可传 stateRoot。

只有本机没有选择记录、且工作区没有用户资料时，showGuide 才为 true。
初始模板、生成入口和技能不算用户资料。已有记忆、项目、记录、档案、笔记等会阻止自动弹出。
reset 只清除本机选择，不删资料、不清除实际连接证据，也不撤销已写下一步。
已有数据时重走引导由用户主动打开，不能靠 reset 强制自动弹出。
