- 版本：v1.0 草案，2026-10-16
- 状态：已确认（2026-10-16，§9 四项均已定）
- 依据：[市场与体验调研](../research/market-and-ux-2026-10-16.md)、[安全审查](../acceptance/security-review-2026-10-16.md) 与 [第二轮复查](../acceptance/security-followup-2026-10-16.md)、端到端验收 r1/r2、当前 main

## 1. 首发要证明什么

**首批用户**（用户确认 2026-10-16）：两类人都要照顾。

- **A. 已经在用 AI 规划事情的人**：用 ChatGPT、Claude 等讨论过计划，希望把资料整理好、把目标推进下去。手里有可以带进来的对话和 AI 记忆。
- **B. 用过 chatbot、但没想到 AI 能用来管理人生的人**：会用 ChatGPT、豆包、Kimi 问问题，没有持续用 AI 管饮食、作息、训练、日程或长期方向的习惯，手里多半没有「人生计划」的对话可带。

**不是首批用户**：完全没用过 AI 聊天的人。首发不为他们降低到教用 chatbot 的程度。

**他们现在的替代做法**：A 继续在原来的 AI 对话里问，计划放进笔记或待办；B 偶尔问一次 AI，问完就散了。多装一个应用，就多一份要维护的东西。

**开图首发只证明一件事**：

> 让 AI 持续了解你，把想改变的事变成能推进、能查回的个人进度。

（A 类用户的说法可以更具体：「把你和 AI 聊过的计划，变成能持续推进、随时查回的个人进度」，用在「带来一段对话」入口旁。）

「AI 可以换，人生进度不能丢」保留为品牌句，但首发用一个能演示、能测的循环来支撑：

```
说出想改变的一件事（或带来一段 AI 对话）→ 核对开图整理出的现状 → 选一个下一步
        → 记下实际结果 → 下次同一个或另一个 AI 接着帮你
```

首发的一切取舍都服务这个循环。健康、财务、足迹、资讯等能力保留，用户已有相关资料时自然出现，**不进入首次使用的必经路径**。

## 2. 现状（main，2026-10-16）

已合并：今天 · 开图 · 资料 · 问问四个入口与 V2 界面；问问的默认/完整 Agent 两种模式；日历 ICS 订阅；资讯「有用 / 不相关」；邮件（IMAP）、Slack、飞书只读采集；微信、支付宝、银行、券商账单导入与 Yahoo 参考价；银行邮件进待核对；iCloud / Google Drive 存放位置；引导后端（搬记忆、清单状态）。

进行中：安全整改（两份审查的全部阻断项 + 私有待办改存本机，已获批准）；引导界面、资料页每行三个、可缩放世界地图。

已知差距（来自调研与验收，本文 §3 逐条处理）：

- 「用你已有的 AI」实际走不通：接手说明只是复制一个本机路径（`connections.ts`），普通 ChatGPT 网页拿到路径并不能读开图。
- 保存后的回执只有「已保存原文，等待 AI 整理」，用户不知道何时整理、由谁整理、结果在哪。
- 首页下一步多数只能「查看」，跳到整个模块；记进展要转去聊天。
- 隐私文案没有区分「存在本机」「同步到你的云盘」「这次发给模型」。
- 端到端验收尚未在发布候选提交上完整通过（r2 因构建错误阻断，已在 b452dba 修复，待 r3）。

## 3. 发布前必须完成（P0）

每项都有验收标准。全部通过、并经 §5 的发布门槛后才发布。

### L1 安全与隐私阻断清零

默认模式联网是用户 2026-10-16 的产品决定。搜索默认走当前对话服务商，复用对话 Key，不新增接收方；用户可另配 Perplexity、Exa 或 Tavily。防外发依赖系统提示词与公网地址校验，属于已接受的风险。

- 两份安全审查中标为确认漏洞的项全部修复并有回归测试：记录路径越界、默认模式 AI 读到程序密钥或改写状态目录、仅本机项目的待办及关联探索外泄、日历订阅访问本机或内网、导出带出程序文件、银行通知重复进入普通收件箱、财务提交读取未上传文件、模式切换竞态。
- 私有待办按已批准方案改存本机：迁移包含全部修订与删除标记，先验证本机副本再清除共享原件，可中断恢复；PRD §6、schemas、AGENTS.md 生成模板同步。
- 完整 Agent 模式保留，二次确认文案写清它拥有与当前系统用户相同的命令和文件权限，可能读到本机任何文件。

**验收**：用含唯一合成标记的私有项目、任务、方向、客户资料走一遍 MCP、公开状态、OVERVIEW、Drive/iCloud 实际文件及全部历史修订、导出包，标记都不出现；本机照常读写与恢复。四项检查与依赖公告检查通过。

### L2 隐私说明与真实数据流一致

- 全产品统一三种去向的说法，不混用：**存在这台电脑**、**同步到你的云盘（iCloud / Google Drive）**、**这次发给 AI（哪个服务）**。「只读写开图资料」只描述访问范围，不能暗示资料不出本机。
- 问问输入框、AI 与连接、存放位置三处，显示当前去向：用哪个模型服务、AI 能读的资料范围、哪些被排除（仅本机项目、密钥）。第一次扩大范围（开启完整 Agent、开启云盘同步、连接外部 AI）时明确提示一次，之后不打扰。
- 项目设为仅本机时提示：「这个项目的待办以后只在这台电脑上，以前同步过的副本请到云盘清理」。
- 新增一页简短的隐私说明（何时、向哪里、发送什么），从设置 → 关于进入，内容与代码行为逐条对应。

**验收**：5 位测试用户中至少 4 位能正确说出资料存在哪里、哪些会发给 AI。

### L3 用已有的 AI 接着做，真的走得通

拆成两条准确命名的路径，取代现在的「复制工作区路径」：

1. **在原来的 AI 里继续（手动接续，零配置）**
   - 开图生成一份**经过筛选的简短资料包**：当前目标、最近进展、要处理的下一步、相关依据摘录；不含仅本机项目和敏感字段，用户可预览、删减后再复制。
   - 用户在 ChatGPT / Claude 等原对话里粘贴使用，再把 AI 的回答**粘贴回开图**，开图按核对流程（见 L5）变成待确认的更新。
   - 明确告诉用户这是手动接续，不需要 API Key，也不是「已连接」。
2. **连接支持的客户端（自动读写）**
   - 只列**实测通过**的客户端，每个给分步说明。首发名单：Claude Desktop / Claude Code、Codex（本机 MCP）；Grok、ChatGPT 经 Google Drive 接力（§9 已定）。
   - 每个连接显示真实状态：未连接 / 只读可用 / 可写回 / 最近一次同步时间。
   - 「测试连接」用一条合成记录验证读回（和写回，若支持），通过才显示已连接；复制路径不算连接成功。

3. **问问直接用电脑上已有的 Agent（不填 Key）**（首发暂缓，2026-10-16 用户决定；未完成的实现留在 `codex/local-agents` 工作树）
   - 「连接 AI」除了填 API Key，再给一项「用电脑上已有的 AI」：自动检测本机已登录的 Claude Code、Codex、Gemini CLI 等，以及任何支持 ACP（Agent Client Protocol）的 agent（填启动命令）。对话、模型和计费都走用户自己的订阅。
   - 做法参照 Open Design（Apache-2.0）的运行时适配层：每个 CLI 一份声明（检测、启动参数、输出流格式），通用引擎负责启动、流式输出、取消和续接；ACP agent 走标准 stdio JSON-RPC。
   - 默认模式仍只读写开图资料、可以联网、不能运行命令，按各 CLI 原生的权限和沙箱参数映射；做不到这条边界的 CLI 只在完整 Agent 模式下可选，并写明原因。
   - 另提供 `kaitu acp`：用 DSH 的 ACP 服务端，让 Zed 等支持 ACP 的编辑器把开图当 agent 用（使用开图里已连接的模型）。

**验收**：一位从未配置过 MCP 的 ChatGPT 用户，能说清在哪聊天、AI 能看到哪些资料、结果怎样回到开图，并独立完成一次接续。

### L4 首次三分钟得到一个属于自己的下一步

调整已做的四步引导，使首次价值更早出现（§9 已定）：

- 欢迎页之后的第一步给两个入口，默认第一个：
  - **带来一件想推进的事**：主问题「最近有什么想改变，却一直没推进？」，直接写（B 类用户的主路径），也可以粘贴一段和 AI 的对话（A 类用户）。下方给几个示例，覆盖三种状态：想改善却坚持不了（如吃饭和训练）、对现状不满又不知道有哪些选项（如工作方向）、已经有一件事要跟进（如作品集）。
  - **从常用的 AI 搬来记忆**：现有提示词与粘贴预览（ChatGPT、Claude、Gemini、豆包、其他）。
- 先保存原文，再给出可修改的「当前目标 / 已知现状 / 一个下一步」。对话里的所有建议**不会**自动变成用户承诺，下一步由用户采纳。没有模型时可以手工写下目标和下一步。
- 用户写的是「不知道该做什么」一类的状态，且已连 AI 时，先给 **2–3 条可能的路径**：为什么适合你、还有哪些不清楚、一个成本低能观察结果的小实验；用户选一条，再变成下一步。重要选择由用户决定。
- 「先管哪些」「接上数据」「选一个 AI」移到今天页的「开始使用」清单里按需完成，不阻挡第一次得到下一步。
- 问问空状态的示例问题改为按用户实际已有资料生成，不出现与用户无关的训练、财务、东京足迹示例。

**验收**：新用户在三分钟任务里保存自己的内容、采纳一个下一步并能找到它的依据；记录求助次数与卡点。

### L5 每次输入都有明确回执

- 每条输入（随手记、粘贴的对话、AI 回答、导入、外部采集）显示同一套状态：**已保存** → **需要连接 AI / 可以现在整理** → **需要你核对** → **已更新**。每个状态写明原因和可以做的事。
- 自动整理关闭时，不显示「等待后台处理」；可点「现在整理」。
- 更新完成后显示：更新了什么、查看原文、查看结果、撤销。失败重试复用同一条记录，重复点击不产生重复任务。
- 复用现有来源、修订与版本机制，不另建一套记录。

**验收**：用户能区分「原文已保存」和「正式资料已更新」；关闭自动任务时不出现等待提示；重复点击不重复。

### L6 首页的下一步能直接处理

- 每条下一步按状态给一到两个直接操作：**采纳**、**完成并记一句结果**、**改到以后**；「查看」跳到这条具体记录，而不是整个模块。
- 新增项目、改日期、记进展有简单表单，不需要模型；复杂梳理才转问问。
- 最重要的一件事用一句话说明为什么是它，用户可以换。
- 完成一次尝试不自动判定假设成立（沿用现有规则）。
- **确认日程时加入系统日历**（用户确认 2026-10-16）：用户点「确认」的时间段（有明确起止时间的日程建议、排了时段的下一步），同时写进 macOS「日历」App 里一个独立的「开图」日历，随 iCloud 到 iPhone 和手表提醒。
  - 只写用户确认过的；AI 待确认的建议不写，没有时间段的待办不写。
  - 事件备注带关联目标和一句「做完回开图记一句结果」。
  - 开图记住每个时间段对应的日历事件：改期就更新，取消或拒绝就删除，不重复写入；不碰用户的其他日历，不做双向同步，不接 CalDAV / Google 日历写权限。
  - 第一次写入时系统会问是否允许开图控制「日历」；用户拒绝、或在非 macOS 上，退回生成 .ics 交给日历 App 导入。设置里可以关掉这个功能。

**验收**：在今天页两次操作内处理一条已确认的下一步，刷新后结果一致；不连模型也能记进展。确认一条日程后，「开图」日历里出现对应事件；改期后事件时间同步变化，取消后事件消失，重复确认不产生重复事件。

### L7 自动任务看得见

首发默认询问是否开启每日整理和早间计划，所以至少要做到：

- 设置里每项显示上次运行时间与结果（成功 / 失败及原因）、下次运行时间、时区，以及「现在试一次」。
- 先实测并写明电脑睡眠、关机、重启时任务的实际行为，文案不承诺做不到的「每天自动」。

**验收**：手动触发一次成功、一次失败（断网），两者都能在设置里看到结果和原因。

### L8 端到端验收全部通过

- 在发布候选提交上重跑端到端验收（r3），覆盖原生 Kaitu.app 窗口、浅色 / 深色、最窄窗口，以及问问权限、日历、财务样例导入、邮件实收、iCloud 往返、引导与 L3–L7 的新流程。凭据由用户在隔离测试 App 中自填。
- 所有测试使用隔离的临时 HOME，不碰个人工作区（b452dba 已加全局隔离）。

**验收**：r3 报告无「不通过」；「跳过」仅限用户明确不提供凭据的平台，并在发布说明中标注未验证。

### L9 发布工程

- 独立 Kaitu.app：用户签名与公证（用户执行）、DMG、首次启动无需终端；版本号与更新方式写明。
- README 与 App 内首屏改用 §1 的定位句和循环演示；不使用「独家」等无法证实的说法。
- THIRD_PARTY_NOTICES 覆盖全部新依赖与移植代码（OpenClaw MIT、double-entry-generator Apache-2.0 等）。
- 首发只发 Kaitu.app；DSH 插件继续维护（§9 已定）。

## 4. 首发不做（P1 及以后）

- 跨类型统一搜索、来源 / 时间筛选、问问 / 今天 / 资料共用结果卡。
- 一分钟回顾（发生了什么 → 观察到什么 → 继续还是调整）。
- 查看记录时推荐两条相关旧资料。
- 自动任务完整运行记录与结果会话入口。
- 钉钉采集、移动端伴侣 App、HealthKit 自动同步、Pro 付费。
- 不新增一级导航，不新增模块。

## 5. 发布门槛

同时满足才发布：

1. L1–L9 验收全部通过，四项检查与依赖公告检查通过。
2. **5 位目标用户的 10 分钟任务观察**（A 类 2–3 人：每周已在用 AI 规划事情，可带一段非敏感旧对话；B 类 2–3 人：用过 chatbot、没有用 AI 管理生活的习惯；同时提供统一合成材料）：
   1. 写下一件想改变的事（A 类可改为保存一段已有对话），找到原文；
   2. 核对整理结果，拒绝一条故意设置的错误推断；
   3. 选一个下一步，记录一次实际结果；
   4. 说出资料存在哪里、哪些会发给 AI；
   5. 用所选接续路径，让下一次 AI 对话读到最新进度。

   门槛：每项任务至少 4/5 人独立完成；没有未解决的阻断级卡点（用户无法继续或误以为已保存 / 已连接）。5 人用于发现障碍，不用于估算转化率。
3. 观察中发现的阻断级问题修复后，对相关任务补测至少 2 人。

## 6. 发布后 7 天跟进（不作为发布门槛）

- 用户是否主动回来更新实际结果、能否从上次继续、是否减少了在原 AI 里重复解释。
- 访谈问「你为哪件事回来、哪一步仍在原工具里完成」，而不是「喜不喜欢」。
- 付费意愿与渠道放到跟进之后再验证。

## 7. 度量（本机计算，不埋点上传）

首发不收集使用数据。测试期间由观察员记录，或从本机数据计算后人工抄录：

- 首次得到有用下一步的耗时；
- 求助次数与位置；
- 误以为「已更新 / 已连接」的次数；
- 找回依据是否成功；
- 7 天内回来更新结果的人数。

## 8. 实施顺序

1. L1（进行中）与 L8 的测试隔离（已完成）。
2. L3、L4、L5：一次完整的「输入 → 核对 → 行动 → 结果 → 接续」使用循环，作为一个批次实施并验收。
3. L6、L7、L2 文案统一。
4. r3 端到端验收 → 5 人观察 → 修复补测 → L9 发布。

每批由 Codex 实施，Claude 审查、跑四项检查、合并；界面以原型为准，原型先改、确认后再实施。

## 9. 已定事项（用户确认 2026-10-16）

1. **首次使用**：按 L4 实施。欢迎页后默认入口是「带来一件正在推进的事」，「从常用的 AI 搬来记忆」并列；选事情、接数据、选 AI 移进今天页的「开始使用」清单。原型已按此更新（顶栏「第一次打开」可走一遍）。
2. **首发外部客户端**：Claude Desktop / Claude Code、Codex 走本机连接；Grok、ChatGPT 走 Google Drive 接力；其余首发不列。另外所有用户都可用「在原来的 AI 里继续」手动接续。
3. **发布形态**：首发只发独立 Kaitu.app。DSH 插件形态继续维护、保持可用，不作为首发对外渠道。
4. **价格**：首发完全免费，不带 Pro；Pro 留到 7 天跟进之后再定。
