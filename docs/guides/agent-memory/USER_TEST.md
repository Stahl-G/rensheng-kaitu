# 用户亲测：旧库作基准，新库承接真实项目

最终范围：保留现有 my-ai-memory 作为基准，新建 PRIVATE kaitu-ai-memory。维护者仅交付提示词，没有读取真实项目或私库，没有创建新库、上传或迁移资料，也没有启动模型测试。合成资料/fake-gh 只作为历史开发检查，不是本次体验验收。

1. 用户亲自启动第一个 Agent。它先列出指定真实项目的必要读取文件、用途和全新记忆目录；用户在该会话确认后才读。先展示提取的真实进度、决策、失败尝试、阻塞、完整下一步及来源，不读取或复制 my-ai-memory 来冒充初始化。
2. 用户核对摘要，并明确确认精确 owner/kaitu-ai-memory、PRIVATE、文字范围及写入路径后，首位 Agent 才初始化一次和正常推送。目标已存在则停下核对，不能重复 init 或覆盖。保留旧库、旧目录、README/AGENTS/CLAUDE 和全局设置。
3. 用户核对新库是否准确保留关键事实、时间和来源，可自行参考 my-ai-memory 基准。要让 Agent 读取旧库做比较，必须另在该会话确认旧库具体读取范围；默认不访问、不复制、不迁移，也不把旧库资料传给其他 Agent。
4. 首位 Agent 生成填好新库 URL 和项目 slug 的接入提示词。用户把它交给自己选择的两个全新 Agent；各用独立会话和克隆目录，只从新库读取获准范围。先独立复述进度、决策、失败、阻塞及完整下一步，再比较理解；不给它们前一 Agent 的口头答案。
5. 用户指定一项真实小任务、执行 Agent 和写回路径。依原规则写真实结果并正常同步，再由另一 Agent 在授权范围内读回，核对来源、follows 和剩余下一步。未授权写回时只读等待，不把技能安装、Git 成功当完整接续。

只按实测记录通过、失败和未测。不自动安排并发测试，不配置 OAuth，不操作 App。首次初始化和后续接入都由用户亲自执行；具体项目、owner 与接收 Agent 待用户确认。
