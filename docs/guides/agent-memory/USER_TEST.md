# 你亲自测试：复用真实记忆，先比较理解

主要验收使用你自己的 ai-memory。具体是否为现有 `my-ai-memory`、精确仓库、项目、允许路径与接收 Agent 尚待你确认。当前没有自动读取、上传真实资料，没有创建新测试仓库，也没有启动自动模型验收。

1. 你先确认精确库、同一个项目、必要入口与日志范围，以及两个可接收这些资料的 Agent。远端 Agent 可能会把获准内容带入它自己的运行环境；只向你指定的接收方提供范围，不由维护者转发真实资料。
2. 在第一个全新会话粘贴短接入入口。目标确认后只读；已有目录保留原样，独立 clone 使用你确认的新目录，不初始化、不迁移、不覆盖。得到带具体来源的现状、失败尝试、阻塞、完整下一步和未知项报告。
3. 在第二个全新会话使用另一份独立目录，读取你批准的同一项目。不给它第一个 Agent 的答案，先取得独立理解报告。可用 Codex、Claude、Devin、Cursor 中你实际指定的两个，不预先替你选择。
4. 你比较两个报告的来源、时间、失败记录和下一步，指出误读；只读结果不能算写回已通过。尚未给出明确目标时，两边都等待，不能猜库名或自行创建。
5. 再由你指定一个真实小任务、执行 Agent、允许改动与写回路径。按原库规则记录真实结果；没有写回约定就先展示具体 diff/路径供确认，不能重铺模板或引入新 handoff 格式。若授权同步，核对本地变更、普通推送及远端提交，冲突保留双方。
6. 最后由另一个 Agent 在授权范围内读回实际结果，引用新来源，说明任务完成与剩余事项。只记录实际通过、失败、未测；技能存在或 Git 成功不能代替理解和接续验收。

合成 Git/fake-gh 文件链只保留为既有开发检查，不能作为本次真实资料的最终验收。当前不安排并发测试、不配置 OAuth、不创建新库。确实另建全新记忆库时，必须另有明确目标和范围授权，再使用 NEW_MEMORY.md。
