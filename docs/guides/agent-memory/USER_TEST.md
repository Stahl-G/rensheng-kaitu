# 实际使用顺序

这是可直接工作的接入流程，不要求先做合成项目、两个 Agent 的理解考试或特定验收任务。

1. 把短初始化入口交给能操作本机文件和终端的 Agent。它先自动检查工具、已有 gh 登录和当前目录。你已经指定的项目直接采用；否则它浅层发现常用开发目录的 Git 项目，给短清单供选择，可多选，不要求你提供完整路径、现状或文件清单。
2. 选定后，它自动读取相关项目说明、进度、决策、交接及近期真实 Git 记录，自己提取带来源的进度、决定、失败尝试、阻塞与下一步。普通只读不反复确认；只有缺关键信息才提具体问题。
3. 真正上传前，你只核对一份合并预览：精确 PRIVATE 目标、记忆新目录、选中项目及拟保存的文字摘要与排除范围。默认 kaitu-ai-memory；有账号、重名或范围歧义才处理选择。官方登录、新增授权、安装及系统权限仍正常办理。
4. 确认后，助手初始化并正常同步，回读项目文件和远端提交，生成已填好地址的接入提示词。任何现有目录和仓库保留，不覆盖、不自动迁移；不上传代码或凭据，不改全局规则。
5. 把生成的接入提示词交给其他 Agent 或设备。它自动核对目标、克隆到安全目录、读取所选项目并引用来源复述上下文，接着处理你已给的任务；没给任务才问下一步。结束依原规则写候选/交接，按已有授权同步；新上传范围一次合并确认。

你可以观察它是否准确提取并接续真实进度、决策、失败和下一步，以及结果是否正常写回并能由下一 Agent 读到。只按实际结果说明成功、失败、未测；不要用技能存在或 Git 成功代替接续证据。需要比较多个 Agent 时可自行使用独立会话与目录，但这不是接入前置条件。
