# 云端接力协议：租约锁 + 记录只追加

- 状态：设计已定，待实现（2026-10-15，用户确认「租约锁 + 记录只追加」）
- 目标：电脑关机时，Dot、Grok、ChatGPT 等云端 Agent 通过 Google Drive 轮流接手，不用用户重讲，也不互相写坏数据。
- 验收：[acceptance/cloud-relay.md](acceptance/cloud-relay.md)；实现任务：[briefs/cloud-relay.md](briefs/cloud-relay.md)。
- 关系：在 [drive-sync.md](drive-sync.md) 的收件箱设计上增加两样东西：交接记录（只追加）和一把锁（只管少数状态文件）。

## 1. 为什么要改

现在的规则是：云端 Agent 只往 `inbox/agents/` 新建文件，合并进记录、刷新 `OVERVIEW.md` 都由本机 `kaitu` 完成。电脑一关，A 写进去的内容就一直待在收件箱里，B 读到的 `OVERVIEW` 还是旧的，接不上力。

## 2. 文件分三类

| 类别 | 文件 | 谁能写 | 怎么写 |
|---|---|---|---|
| **只追加**（不用锁） | `inbox/agents/*`（记录、记忆、简报、笔记、日程建议）<br>`handoffs/YYYY-MM/<时间>-<agent>.md`（新增：交接记录） | 任何 Agent | 只新建、文件名唯一、不改已有文件 |
| **状态**（必须持锁） | `NOW.md`、各模块 `<模块>/STATUS.md`（含学习、决策、共享项目） | 当前持锁者 | 改之前重读，只改需要改的部分 |
| **只由本机生成**（云端只读） | `OVERVIEW.md`、`AGENT-README.md`、`AGENTS.md`、`*/data/`、`me/goals.json`、`me/rules.md` 以及其余文件 | 本机 `kaitu` | 不变；目标和规则仍然要用户确认 |

记录只追加的意思是：云端 Agent 不直接改 `data/`，而是把记录交进收件箱。本机开机后统一写入，并存版本。
新增的「交接记录」也只追加，是接力时最主要的信息来源：

```markdown
---
agent: grok-bot
at: 2026-10-16T09:12:00+08:00
---
## 做了什么
- 记录午饭（inbox/agents/grok-bot-20261016T0912.records.jsonl）
- health/STATUS.md：「周四练背」标记完成，新增「周六有氧 30 分钟」
## 下一步
- 周六有氧 30 分钟
## 未决 / 需要用户
- 无
```

## 3. 锁：`LOCK.json`

放在工作区根目录：

```json
{ "holder": "grok-bot", "purpose": "更新健康下一步",
  "acquired_at": "2026-10-16T09:10:00+08:00", "expires_at": "2026-10-16T09:25:00+08:00" }
```

1. **取锁**：读 `LOCK.json`。文件不存在，或 `expires_at` 已过，就写入自己的锁，有效期最长 15 分钟。
2. **确认**：写完等几秒再读一次，`holder` 仍是自己才算拿到；否则视为没拿到。
3. **持锁**：只改状态类文件，每个文件改之前先重读；超过 10 分钟没改完，就把 `expires_at` 往后延。
4. **放锁**：把 `expires_at` 改成当前时间。不删除文件，因为有的连接器不一定能删。
5. **没拿到锁**：不改状态文件。仍然可以只追加：交记录、写交接记录，在交接记录的「未决」里写明想改什么。告诉用户「某某正在更新，稍后再试」。

锁靠各 Agent 自觉遵守，Drive 也没有原子写入，严格来说做不到绝对互斥。个人自用时，同一时刻通常只有一个 AI 在工作；定时任务把时间错开即可。真出了冲突，用 Drive 的文件历史恢复；本机开机后也会检查冲突副本。

## 4. 接手时的读取顺序（写进 `AGENT-README.md`）

1. `AGENT-README.md`（本文规则）→ `LOCK.json`
2. `OVERVIEW.md`，记下它开头的生成时间
3. `NOW.md`、相关模块的 `STATUS.md`
4. `handoffs/` 里比 `OVERVIEW` 新的交接记录（按时间排序，最多读最近 10 份）
5. `inbox/agents/` 里还没处理的文件。**这些也算现状**，只是还没合并进记录

回答「现在进度如何」时，要把第 4、5 步的内容和 `OVERVIEW` 合起来看。结束前，只要动过任何东西，都要写一份交接记录。

## 5. 本机 `kaitu` 也守同一把锁

- 写 `NOW.md` 或任何 `STATUS.md` 之前取锁，`holder` 为 `kaitu-local`。别人持有未过期的锁时：后台处理就推迟到下一轮；工作台操作提示「<holder> 正在更新，稍后再试」。
- 本地模式（不在 Drive 里）不需要锁，行为不变。
- 处理收件箱时一并读取 `handoffs/`：`OVERVIEW` 增加一节「最近交接」，列最近 3 份；交接记录本身保留在原处，不移动。
- `kaitu doctor` 新增两项检查：
  - 状态文件旁出现 Drive 冲突副本（例如 `STATUS (1).md`），报告让用户处理；
  - `LOCK.json` 格式错误，或锁已过期却还写着持有人，只提示，不算错误。
- 云端 Agent 改动的状态文件，由本机已有的「外部修改 30 秒防抖自动存版本」接住，版本说明里注明「云端改动」。
