# GitHub 工作区备份与 Git 归属保护

基线 main `d876dd7`；分支 `codex/private-workspace-sync`。本机与界面验证使用临时工作区、合成资料及 mock；后续经用户批准，新建专用私库完成真实合成往返，见下节。没有上传个人工作区，未替换任何日常安装。

## 已完成

- `Workspace.migrateHistory` 在共同入口核对历史归属，保留无 remote 用户仓库与 worktree 的 `.git` 指针。新内部历史带归属标记；旧版未标记的 loose 历史须整条提交链属于开图、根提交为开图初始化。无法明确归属的仓库留在原位。重定向到本机 state 的旧历史迁移验证通过。
- 「个人 → AI 与连接」提供可选 GitHub 备份：文字与结构化资料开关、状态、手动同步、断开、从备份恢复到新目录并打开。
- 复用现有 GitHub token 本机存储，用 GitHub Git Data API 读写专用备份仓库；首次连接 / 切换时检查私有性，公开仓库默认不开上传。常规同步没有仓库可见性请求。
- 独立后台同步，不进入本地保存队列。缓存未变 blob，未改动时不产生新提交；更新远端使用非强制分支更新，远端先改动时重试。
- 依照记录 ID 及 rev 对照共同基线，覆盖同月及跨月份的修改 / 删除；普通不相交记录可合并。冲突时保留两份并暂停上传，选择前检查本机文件是否又有编辑，处理前副本留在本机。
- `.git`、`.kaitu` / 被重定向的 state、隐藏目录、凭据、媒体等不上传。用户已有 Git 仓库的 remote、index、分支不用于备份。
