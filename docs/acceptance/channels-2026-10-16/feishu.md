# 飞书交审

实现：@larksuiteoapi/node-sdk WSClient 订阅 im.message.receive_v1，支持群聊与机器人私信、文本与 post 富文本、提及规整。
握手完成才显示已连接，重连中显示断开状态；SDK 负责心跳与重连，终止性连接失败使用本机退避重试。
测试连接同样接收已授权账号的事件，避免测试期间丢弃消息。断开会等待接收队列结束，关闭连接并删除本机凭据。
不会启动原先会回复消息的 FeishuChannel，也没有消息发送、已读、编辑、附件下载或模型调用。

来源：参考 OpenClaw 2026.10.4 `extensions/feishu/src/client.ts` 的 WSClient 与生命周期回调，
`extensions/feishu/src/post.ts` 的富文本载荷/语言包/元素处理。精简到独立 feishu.ts，保留 Adapted from 文件头。
没有复制代理/插件框架、发送、会话处理和媒体下载。MIT 全文已在根目录 THIRD_PARTY_NOTICES.md。
账号、应用密钥与最近消息 ID 环在 localStateRoot/collectors/，600 权限；投递复用现有 `.note.md` 格式和 date 字段。

接收范围已在最小设置入口与 docs/channels.md 说明：机器人所在群与发给机器人的私信。
群聊只开 group_at_msg 权限就只收 @消息；全量群用户消息需要企业批准 group_msg 权限。
没有读取个人其他会话的用户 token 或绕过权限的读取方式。

未做：不做平台历史回补；离线消息是否重投取决于平台。
事件仅有 message_id，当前 SDK 没有按该 ID 获取消息分享链接的接口，因此保留会话链接和消息 ID，不能精确跳到原消息。
不下载非文本原件。真实企业应用发布、群权限、长连接断线恢复与会话链接打开尚未实测。

验证：每渠道仅一个合成行为测试。飞书用假的长连接验证群 post 与私信进入收件箱、重复不重写、
长正文尾部不落工作区、App Secret 不进工作区或接口返回、断开后不再接收。
全部目录均为临时目录，不连接真实账号、不操作个人工作区或 ~/.kaitu-app。
桌面 ESM 打包加载检查发现飞书 SDK 在加载时使用 __dirname，原有打包缺少该 CommonJS 全局而启动失败。
package-kaitu.mjs 的四个 Node 入口统一补 __dirname / __filename 与 createRequire 桥接，不依赖用户另装 SDK。
修复后重新运行构建、类型检查、lint，均通过；全量测试 49 个文件、134 项通过（单 worker，保留原有 15 秒超时）。
按实际打包配置生成包含三渠道的桌面 local.mjs 并在 Node 中加载成功，不代表真实平台握手或原生桌面验收。
隔离本地接口返回三渠道列表；Chrome 已确认飞书表单与接收限制可见，没有填写真实凭据。临时页面与服务已关闭。

手动验证：在隔离工作区配置测试企业应用，发布并开通只读接收权限，订阅长连接事件。
分别发一条机器人私信、一条所在群的 post、一次 @消息；核对笔记来源、发件人 ID、时间、280 字摘录和会话链接。
关闭开图后再打开，确认消息重推不重复；断开账号后再发消息，核对不会新增笔记。
同时开 App 与 DSH，确认同一个 App ID 只有一个采集器。钉钉未做。
