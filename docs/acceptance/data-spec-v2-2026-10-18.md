## 性能与完整检查

机器：Apple M1 Max，arm64，Node 26.11.1。合成规模：300 项目、20000 条记录、2000 篇原文。
投入查询只读状态文件与清单，不读取指标记录和原文。

| 指标 | 实测 | 门槛 |
|---|---:|---:|
| listInvestments 首次未缓存读取 | 37.51 ms | 50 ms，满足 |
| listInvestments 缓存后 30 次平均 / 最大 | 5.25 / 7.32 ms | 50 ms，满足 |
| completionRate（20000 次打卡，1000 次调用平均） | 0.03108 ms/次 | 0.1 ms/次，满足 |
| completionRate（30 次打卡，10000 次调用平均） | 0.00147 ms/次 | 0.1 ms/次，满足 |

首次投入读取需要解析 300 份 STATUS frontmatter；缓存后只读取文件状态与解析缓存。
文件缓存沿用工作区现有策略，刚修改的文件在 2 秒内不缓存，缓存后采样等待了该窗口。
最终数字在完整检查结束后针对最终代码测得。此前并行构建和测试期间首次读取曾达 68.54 ms，
说明本次结果不代表并行负载下每次调用的最坏时延。

完整检查：`pnpm build && pnpm typecheck && pnpm lint && pnpm test` 全部通过。
最终全量测试：86 文件、237 项通过，105.42 秒。
main `119a3b9` 独立临时副本的全量测试：84 文件、228 项通过，252.64 秒。
本次相对 main 的墙钟时间增幅为 -58.27%，未超过 15% 门槛，不据此声称测试执行性能提升。
两边沿用同一 Vitest 配置（2 workers）；机器同时存在其他任务的构建和测试，墙钟时间只代表本次单次实测。
