## 用户可见行为

设置 → 关于 → 开图功能更新：检查更新 → 下载更新 → 重启应用。
显示功能版本、固定内核版本；底部另标安装版本，避免把宿主和功能包版本混在一起。
更新后可以恢复上一版功能。这个操作只切换代码，不把用户资料回退到旧状态。

设置 → 语言默认跟随系统：中文系统用中文，英语和其他语言系统用英语。
桌面读取 app.getPreferredSystemLanguages() 的第一项；Web 使用浏览器首选语言。
不再根据工作区是否有资料强制选择中文，也不再把自动识别结果保存成固定语言。
早期偏好只有 locale，无法分辨过去是自动写入还是用户手动选择，因此保留旧值，可选择跟随系统解除固定。

## 更新边界

- 固定部分：DSH 0.2.0-rc.2、Electron、原生启动器、加载器和宿主协议桥接。
- 功能包：开图界面、资料服务、Agent 工具、技能、模板、schemas 和配套资源，前后端一起更新。
- 更新内容写入本机 App 状态目录的 updates/dsh-0.2.0-rc.2-host-1，不写入工作区或 .app。
- 发布清单用 Ed25519 签名，下载包校验清单中的 SHA256；校验发生在安装入口。
- 安装完成后切换版本指针，保留旧版本。运行中的应用保持当前功能，重启后加载新版本。
- 需要新 DSH、原生依赖或启动器变化时，重新适配并升级完整宿主，不走这条功能更新通道。
- 旧安装没有新加载器，首次需要安装一次新宿主。正式发布还需要确定 HTTPS 更新源与正式公钥。

最终测试 ZIP：11,900,937 字节，约 11.35 MiB。RC 号仅标识本轮本机测试包，不是对用户发布的版本。

## 验收过程与边界

测试 App 位于工作树 dist/update-check/Kaitu.app，使用全新临时 HOME、App 状态目录和工作区。
为了区分正在使用的日常 App，测试副本使用独立 bundle ID ai.kaitu.update-test，只做 ad-hoc 本机签名。
原生工具曾丢失测试启动环境而打开日常工作区，发现后未在该窗口执行写操作，立即停止相关测试进程。
该次启动可能产生应用自身的缓存或状态写入，未声称整个日常目录逐字节未变。
随后把临时 HOME、App 状态与工作区路径固定在测试副本启动器里，后续重开和验收都回到测试资料。
这段测试启动配置只在本轮副本中，未写进产品启动器源码。

原生工具出现过 ScreenCaptureKit -3811/-3812 和旧应用标识缓存，恢复后继续用原生窗口完成操作，没有用浏览器替代原生验收。
曾发现 Electron 入口等待 ready 导致启动阻塞，已改为异步启动，后续实际启动通过。
本轮没有验证正式 HTTPS 托管端、Developer ID 签名正式宿主或正式密钥轮换；不把本机成功写成已对外上线。
