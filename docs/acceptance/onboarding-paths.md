# 首批两类用户的引导调整交审

本轮先合入最新 `origin/main 60fe7ac`（含 `92edcf3`），合并提交 `4eae99e`。原型以 main 为准。
本说明接续 [首发引导交审](onboarding-launch.md)，覆盖其中原先未纳入的「想改变的一件事」与可能路径。

## 实现

- 欢迎文案、入口、主问题和三个示例与新版原型一致。示例只填入输入框，用户仍需确认保存。
- 同一入口允许手写或粘贴对话。服务端从原文角色标记判断输入类型，核对标题、依据和今天卡片随之变化。
- 已连接 AI 时，整理提示要求对不明确方向给 2–3 条可能路径；明确事项继续给三项草稿。
- 路径包含名称、适合原因、尚不清楚的条件和低成本小实验，不默认选择。选择后填入下一步，用户仍可修改再采纳。
- 未连接 AI 时只提供手工三项，不显示路径。DSH 通过已有会话与待确认工具写回，同一页面回读。
- 路径复用 `me/STATUS.md` 的 proposed 下一步及 Markdown 正文，来源仍指向收件箱原文。
  没有新增工作区字段、config 字段或 schema，也未改 PRD §6。
- 采纳时核对所选路径的完整内容，拒绝过期卡片；只生成用户明确采纳的一条待办，保留修改后的下一步与所选路径依据。
- 产品定义、引导 PRD、onboarding 技能和 AGENTS.md 生成说明同步更新。

## 接口补充

沿用本地 product 接口与 DSH Remote 的来源校验、串行写入和既有方法名。

| 方法 / 返回值 | 变化 |
| --- | --- |
| onboarding.content | 增加 welcome、matter 的共享文案与示例 |
| onboardingMatterSave / Read / Organize | 返回 `kind: note 或 conversation`；草稿可带 paths |
| onboardingMatterDraft(source, draft) | draft 可含 2–3 个 `{name,fit,unknown,experiment}`；有路径时 next 必须为空 |
| onboardingMatterAdopt(source, draft, path) | 第三个参数为选中的完整路径或 null；有路径时必须选择当前有效卡片 |
| onboarding.draft / next | 返回输入 kind，供标题与依据呈现 |

独立版 Ask 和 DSH 的工具参数均接同一份服务端校验。CLI matter-draft 同样支持 paths。
`paths`、`kind` 是接口对象，不是新增的持久化记录字段。

## 实际验证

2026-10-16，以构建后的 kaitu ui 共享页面，在两个临时合成工作区运行。
本机引导状态、Ask 状态和渠道状态均指向临时目录；未选真实工作区、未填写真实凭据、未调用外部模型。
连接 AI 的一侧使用合成 AskRuntime 返回事件，实际经过 Ask 会话、草稿写入和页面回读。

1. 欢迎主文案和第一项说明正确；三个按钮分别填入原型示例，未自动提交。
2. 无 AI，手写不明确的工作方向：显示手写核对标题和依据、手工填写说明，无路径卡片。
   填写后采纳，今天页出现一条下一步，来源指向原文。
3. 合成已连接 AI，同样输入返回三张路径卡；没有默认选项，下一步为空且采纳禁用。
4. 刷新并从今天重新打开，三张路径完整回读，仍未默认选择。
   选择「试一段研究工作」后实验填入下一步，再改为「先花半小时写一个熟悉问题的研究提纲」并采纳。
5. 后端回读确认只存在一条待办，标题是用户修改值；source 指向原文，notes 保留目标、现状和所选路径依据。
6. 作品集对话示例显示对话核对标题和依据，明确事项无路径卡片；点「只保存原文」后待办仍为一条。
7. 桌面三列卡片、390×844 单列布局与表单可用。临时截图为
   `/tmp/kaitu-paths-desktop.png`、`/tmp/kaitu-paths-mobile.png`，不提交原始数据与日志。

手动复验可按以上顺序，以临时工作区启动 kaitu ui。真实模型连接后分别输入明确事项和不知道做什么的状态，
确认只有后者出现可能路径，且不选择就不能采纳；选择、修改、采纳后检查今天卡片与原文。
