# Windows 共用界面基础规则与现有 Drive 接入

本轮先按用户要求审查代码，再做视觉验收。延续 RC4 同一份 core、React、DSH 插件和功能包，没有增加 Windows 后端分支或 npm 包。

## 代码中定位的问题

| 位置 | 原因 | 修正 |
|---|---|---|
| `Prototype.module.css` 的通用表单 | 所有 input 都获得 40px 文本框高度，所有 label 都竖排；影响存放位置与资料包勾选等多个入口 | 文本控件与 radio、checkbox、range、file、color 分开；降低基础规则的优先级，让页面控件控制自身布局；资料提供方用两列排版 |
| 两个客户端打包脚本 | 在 esbuild 并行加载回调里向数组追加 CSS，输出顺序由回调完成顺序决定；同优先级的基础规则与页面规则可能互相覆盖 | 插件与独立应用共用一个样式收集器，固定地图基础样式、共享样式、页面样式的输出顺序 |
| 导航和问问高度 | 导航依赖两边 flex 内容宽度，问问用多套固定像素扣减 viewport 高度，还有 560px / 460px 最小高度 | 导航两边用等宽轨道；应用、内容区、保留会话的包装层和聊天区用连续 flex 高度关系，消息列表独立滚动，移除重复高度计算 |
| 基础字体与窄屏 | standalone 的默认字体只有 Apple 回退；卡片网格固定最小宽度；自动任务引用了不存在的 auto-row 类 | 补齐 Windows 系统字体；网格允许缩到容器宽度；自动任务窄屏换行；清理进度图中不存在的 CSS 类引用 |
| `pendingWorkspaceFiles` | 同步来的资料没有这台电脑的版本库，而启动时直接访问 HEAD | 首次检查改动前初始化本机版本库；不导入或改写另一台电脑的版本历史 |

## 检查与实际结果

- 全工作区 build、typecheck、lint 通过。没有为 CSS 写文案或常量断言测试。
- 静态核对客户端组件引用的 CSS module 导出：发现 3 处不存在的引用，处理后为 0。
- 连续构建 standalone CSS，输出 SHA-256 一致；本轮固定输出为 `1581f61b52a4fcfae46b9f6880aec4f131ccfeb2894ceb364c82f77d8f0c911d`。
- 新增一个跨设备合成资料回归，修复前复现 `NotFoundError: Could not find HEAD`，修复后整份 history 测试 8 项通过。检查另一工作区的历史没有改变，合成档案内容保留。
- 原生 Windows 窗口完成问问导航、连接 AI 弹窗、内置服务商选择和 API Key / 模型表单的实际点击检查，未输入密钥或发送模型请求。
- 相同 EXE 后端的浏览器界面检查今天、开图健康页、资料、设置、存放位置、AI 连接弹窗；覆盖 1280×720、640×580、360×580、960×480。测量结果无横向溢出，单选项为 18×18，开关为 44×26；短窗口内聊天输入区完整可见。英文设置页在 360px 宽度下也无横向溢出，随后恢复跟随系统语言和默认视口。
- 本轮未改变系统 DPI。原生窗口缩放/拖动操作没有形成有效尺寸变化，不将其计为高 DPI 或原生小窗口验收；响应布局尺寸检查来自浏览器，和原生窗口点击检查分别记录。

## 用户现有工作区

用户明确选择直接沿用 `G:\我的云端硬盘\kaitu`。只设置本机 current-workspace 指针，原配置先备份在本机 LocalAppData/kaitu/backups。

修复后的已安装程序以正常用户环境启动，原生窗口可见四个入口，`/api/sync` 确认 root 与 path 为上述目录、mode 为 drive、provider 为 google-drive，stateDir 位于本机 LocalAppData/kaitu 下。没有搬动、合并或覆盖用户原文记录，没有把测试窗口的新资料带入 Drive。以后正常启动该程序会沿用本机指针。
