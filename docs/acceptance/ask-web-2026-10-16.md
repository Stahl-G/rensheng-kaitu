## 行为与实现

- 默认模式说明改为「只读写开图资料，可以搜索和打开网页；不能运行命令」。
  开放 rc.2 的 `tool-web`、`web-fetch-http` 和搜索能力，仍关闭命令、子代理、工作流和插件管理工具。
- 搜索每次从 `LocalCredentialProvider` 读取可用凭据：优先 DeepSeek，未配置时按用户选择使用 Perplexity 或 Exa；
  所选备用服务没有 Key 时使用另一个已配置服务。选择与对话模型无关。
- DeepSeek 使用实际桌面包导出的 `DeepSeekSearchProvider`；Exa 和 Perplexity 使用锁定的官方 npm 发布包
  `@deepseek-ai/dsh-web-search-exa@0.2.0-rc.2`、`@deepseek-ai/dsh-web-search-perplexity@0.2.0-rc.2`。
  实际 rc.2 app.asar 不含后两者，因此打包时把它们的实现编入 `sdk-web.mjs`，许可证放入载荷 `licenses/`。
- Exa、Perplexity 原插件未提供 `apiKeyEnv` 配置项，薄适配层按引用读取本机凭据，传给请求中的提供方实例。
  不把 Key 放进插件配置。DeepSeek 共用 `DEEPSEEK_API_KEY`，另两者使用独立的 `KAITU_SEARCH_*_API_KEY` 引用。
- 「AI 与连接 → 网络搜索」显示当前服务、无 Key 时的添加说明、官方申请链接，以及保存/移除 Key。
  `kaitu-search.json` 只保存备用服务选择。保存搜索 Key 不会自动连接尚未选择的对话模型。
  修改搜索设置沿用问问原有运行时关闭与切换锁，下一条消息使用新设置，原会话模式不变。
- `web` 服务固定使用开图的公网读取提供方，保留 DSH 工具层的 HTML 转换和不可信内容提示。
  公网读取与日历订阅共用 `public-fetch.ts`：仅 HTTP/HTTPS、禁止 URL 用户信息、全部 DNS 答案须为公网、
  拒绝本机网卡/内网/链路本地/保留地址、固定已核验 IP 建立连接并保留 Host/SNI/证书校验。
  每个重定向重新核验，最多 3 跳；不采用上游代理分支绕过 IP 固定校验。
- 网页读取总时长上限 20 秒，保留 gzip/deflate/br，原始及解压后各限 5 MiB，显示内容最多 10 万字符。
  日历仍使用原来的 10 MiB 上限。
- 防外发与外部内容不可信规则写入开图 `kaitu:workspace` 系统提示词，也写入生成的 AGENTS 安全段落。
  真实默认和完整模式请求均已检查到该规则，原文见 [SDK 结果](ask-web-2026-10-16/sdk-results.json)。
- 真实 SDK 检查发现 `.kaitu` 项目标记与安全边界冲突，导致模型请求之前失败；改用公开的 `AGENTS.md`
  作为项目根标记，未开放对 `.kaitu` 的读取。

L1 和安全整改说明 SEC-03 已按用户决定补记：默认联网、防外发依赖系统提示词与公网校验，属于已接受风险。

## 用户手动验证

1. 在隔离 App 中进入「AI 与连接 → 网络搜索」，自行添加真实 Key。
   没有 DeepSeek Key 时依次选择 Exa、Perplexity 保存，核对当前服务；添加 DeepSeek Key 后应优先显示 DeepSeek。
   移除 DeepSeek 共用 Key 会同时影响 DeepSeek 模型连接，页面已说明共用关系。
2. 使用任意已连接的对话模型，在默认模式查询一个不含个人资料的公开问题，再打开一个公开结果网页。
   未配置搜索 Key 时，应收到前往网络搜索设置的提示，网页读取仍可使用。
3. 让默认模式打开 `http://localhost/`、`http://127.0.0.1/`、局域网地址或 `file:///etc/passwd`，应被拒绝。
   使用可控公网跳转到内网的地址，也应被拒绝。默认模式请求运行命令应无对应工具。
4. 切换搜索服务后在原会话继续，确认下一条消息生效；新会话仍默认上述权限，完整模式继续要求二次确认。
5. 给 AI 一段含指令的外部网页/邮件材料，核对它是否把这些指令当成不可信数据。
   需要向第三方发送个人资料的任务，应先征求用户同意。
