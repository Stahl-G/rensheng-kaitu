日期：2026-10-16。工作树 `rensheng-kaitu-finance`，分支 `codex/finance`，基于 main；仅本地提交，不推送、不合并。

## 来源与文件

CSV 支持 UTF-8 / GBK，识别表头而非文件名。XLSX 用 read-excel-file 9.3.12，二进制 BIFF8 XLS 用 xls-reader 0.7.0，均为 MIT、锁定版本。
华西导出的 `.xls` 也可能是 GBK 制表符文本；按内容识别。IBKR 使用 Flex XML，不是普通 Activity CSV。
所有表格来源也可用同列名的 CSV、XLS、XLSX；下表列出其常见原生导出。

| 来源 | 格式 | 导出位置 |
|---|---|---|
| 微信 | XLSX、CSV | 我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账 |
| 支付宝 | CSV | 我的 → 账单 → 右上角菜单 → 开具交易流水证明 / 下载账单 → 用于个人对账 |
| 招商银行 | CSV | App 搜索“流水打印”，高级筛选中展示摘要、交易对手，导出明细；信用卡用含账单年月的明细 CSV |
| 工商银行 | CSV | 个人网银 → 我的账户 → 明细查询 → 下载明细；借记卡两版及信用卡列名分别识别 |
| 建设银行 | XLS、XLSX、CSV | 个人网银 → 账户查询 → 交易明细 → 导出 Excel |
| 中国银行 | CSV | 个人网银 → 银行账户 / 信用卡 → 交易明细 / 账单明细 → 下载 |
| 京东 | CSV | 我的 → 我的钱包 → 账单 → 右上角菜单 → 账单导出（仅限个人对账） |
| 美团 | CSV | 我的 → 钱包 → 账单 → 右上角菜单 → 导出账单 |
| 华西证券 hxsec | XLS 文本、CSV、XLSX | PC 交易客户端 → 查询 → 交割单 → 导出，保留清算金额、业务名称及成交编号 |
| 海通证券 htsec | XLSX、XLS、CSV | e海通财 PC 独立交易版 → 查询 → 交割单 → 查询 → 导出 Excel |
| IBKR | XML | Client Portal → Performance & Reports → Flex Queries，选择 Trades / Cash Transactions 并生成 XML |
| 同花顺 | XLS、XLSX、CSV | 下单交易程序 → 资金股份 / 当日成交 / 历史成交 → 导出表格 |

导出入口依据上游各 provider 文档及 [IBKR 官方 Flex 查询说明](https://www.ibkrguides.com/clientportal/performanceandstatements/flex.htm)。
上游说明：[提供商文档目录](https://github.com/deb-sig/double-entry-generator/tree/main/docs/docs/providers)。
PDF、图片、加密压缩包不进入账单解析；先解压导出的账单文件。

同花顺没有个人公开接口，只能导出文件后导入。资金股份复用原 holdings-csv 别名；成交使用 htsec / hxsec 的买卖与清算规则。
当日成交不含日期时，在导入“表格选项”填写成交日；多张账单共存时填写工作表名称。不取上传时间代替成交时间。

## 导入行为与移植范围

先选择现有财务账户，再上传、预览、确认；放弃删除暂存原件。任何行出错均不提交整批，重复导入不新增流水。
支付宝仍使用 alipay-csv 标识，与旧导入合为一套解析和去重逻辑。来源交易号、原单号、原始状态、方向与本方尾号保留。
退款、转账走原对账规则；证券卖出缺成本仍不计算已实现收益，缺持仓成本仍不计算浮动收益。

移植落点：`packages/core/src/finance/providers/tables.ts`、`shared.ts`、`ibkr.ts`。
参考 `pkg/provider/{wechat,alipay,cmb,icbc,ccb,boc,jd,mt,hxsec,htsec,ibkr}` 中的解析、类型及格式辅助规则；
微信 / 支付宝 / 美团 / 银行的 parse.go，京东 jd.go，华西 hxsec.go、海通 parse.go、IBKR ibkr.go 为主要来源。
海通唯一匹配的中签价格数量行与七天内缴款行合并，新增证券行按上游规则忽略。
未移植 beancount / ledger 输出、账户映射和 YAML 规则配置。文件头及根目录 THIRD_PARTY_NOTICES.md 已保留来源与 Apache-2.0 全文。

## 参考估值

`loadFinanceInvestments` 为本地投资接口提供独立 reference：价格、估值、时间、币种、Yahoo 来源与汇率。
沪市映射 .SS、深市 .SZ、港股 .HK，美股保留代码；不能确定市场或取不到价格时返回没有行情。
yahoo-finance2 锁定 4.0.3（MIT），未保留发布时间例外。打开财务视图才尝试刷新，距上次尝试超过一小时，每个工作区每天最多四次；失败同样计入限额。
行情和汇率缓存在工作区外的本机状态目录。失败保留上次价格及其时间；主表继续显示用户导入的估值。
Yahoo 是非官方接口，可能失效。成本、市价、汇率正式记录与原投资收益口径均不被参考结果覆盖。

## 银行通知入口

`parseBankNotification({sender, subject, text, time})` 为纯函数；识别招商、工商、建设、中行发件域和明确的动账模板。
输出带方向金额、币种、尾号、对手方、时间与时间依据；不认识、多个金额、缺尾号或币种时返回 null。
没有正文交易时刻时使用已知的收件时间，并标记 time_basis=received。
`receiveBankNotification` 只保存本机状态候选。`bankNotificationCandidates` 查询候选和关联结果；本地接口也提供`financeNotificationReceive` / `financeNotificationCandidates` 入口。
候选保存在 `.kaitu/finance-notifications.json` 所指向的本机状态目录，硬排除版本历史；不保存原始邮件。
候选不生成 finance_transaction，不进入账户余额或现金流。后续账单按币种、有符号金额、尾号及 24 小时时窗匹配；排除明确来自其他银行的流水，钱包账单也可匹配。
必须双向唯一才关联正式流水 ID，多笔可匹配时继续待核对；重读时按当前流水重新判断，因此恢复 / 修订不会留下错误关联。
账单不带本方尾号时，可在导入选项填写四位尾号；未提供时保持未匹配。旧流水缺尾号时需修订补齐；重投同文件仍按原去重规则跳过。邮件通道接线由 codex/channels 合并时完成。

## 边界与手动验证

- ETF 份额合并等无现金公司行动无法表示为现有交易或完整持仓快照，明确报错；没有新增公司行动类型。
- IBKR 覆盖股票、外汇两币种转账、分红 / 利息、税费和入出金；期权、期货等资产明确报错。持仓请用持仓表导入。
- IBKR 日期时间需提供 ISO 日期及明确时区（如 EST / EDT / UTC），不猜账户时区。
- 未付款、失败或不能判断的交易状态不会被当作已完成消费；错误保留在预览中。
- 本轮没有连接任何第三方记账服务，也没有接入真实邮箱、券商账户或真实个人工作区。

1. 旧工作区先 `kaitu upgrade`；在临时工作区创建 finance_account，启动本分支的 `kaitu ui`。
2. 记录 → 财务 → 导入，逐项选择 `packages/core/test/fixtures/finance/` 的合成示例；确认预览金额方向和尾号，放弃后重试。
3. 确认后重导同文件，验证跳过计数、流水条数与版本不增加；有错误行时确认整批未写。
4. 投资页查看参考价、报价时间与来源；断网后仍可看到导入估值与上次参考价。不要为测试使用真实个人工作区。
5. 在临时工作区调用 receiveBankNotification，先核对待核对列表与空现金流，再导入匹配账单；新增同额候选验证歧义不合并。

自动验证：每个 provider 一个参数化行为用例（CSV 与其原生表格变体放在同一用例），估值一个假行情用例，通知一个合成邮件用例。
全部自动测试不联网，仅使用临时目录；每次提交前均执行 build、typecheck、lint、完整 test。
