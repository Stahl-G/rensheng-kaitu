# 性能：全局审查 + 第 8、10 条

## 原因
- 工作区每读写一个文件都对路径逐级 `realpath` + `lstat`，占快照、总览、档案等耗时的 70–90%。外部入口（本机接口 Host/Origin、Agent/MCP 文件工具、模块加载）的检查保留。
- 每读一条记录都重新扫描全部模块并校验 module.json。
- 桌面后端把所有界面请求（包括纯读取）放进同一条串行队列；同一条队列里还有每 60 秒的日历订阅拉取 + 系统日历同步（联网、osascript）、收件箱整理、存版本。写操作前还要先全量存一次版本。
- 确认 / 不用：写 NOW.md → 全量扫描存版本 → osascript 写系统日历，全部做完才返回。

## 改动
- 去掉 Workspace 内部的逐次符号链接检查；模块列表按各 module.json 修改时间缓存。
- 读取不再排队；写入直接执行并返回。只有换存储位置、恢复版本仍等后台任务做完。
- 存版本改为后台去抖（2 秒内的写入合成一个版本，沿用操作说明）；界面写入后不再同步刷新现状，由文件监听在后台刷新。
- 改计划后系统日历在后台同步，完成后经订阅推回界面。

## 实测（合成工作区，本机 SSD，同一脚本）
| | 改前 | 改后 |
|---|---|---|
| 确认日程建议（HTTP 往返） | 659 ms | 7 ms |
| 总览 | 178 ms | 48 ms |
| 资料库 | 61 ms | 16 ms |
| 存版本（无改动） | 1690 ms | 52 ms |
| 刷新现状 | 1142 ms | 35 ms |

真实 App 里改前还要再加上排队等待：日历同步（osascript，上限 60 秒）、日历订阅拉取会挡住期间所有页面请求。现在不会了。
