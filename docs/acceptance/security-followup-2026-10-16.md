## 一、确认的发布阻断与修复要求

### SEC-01：日历订阅可访问本机或内网

位置：基线 `packages/core/src/calendar.ts:45,75`。

订阅地址仅检查部分 URL 格式，随后用会自动跟随重定向的 fetch 获取。初始地址、重定向目标、域名解析均未限制为公网。恶意订阅可让运行开图的机器请求本机/内网服务。前提是订阅被加入并拉取，不是已证实的匿名互联网攻击。

建议：在共用获取入口限制协议、用户信息和地址范围；校验全部 DNS 答案，并将已核验 IP 绑定到实际连接，保留正确 Host、SNI 和证书校验。逐跳检查重定向，限制跳数、总时长及响应体积；覆盖 IPv4 特殊写法、IPv6、转换地址和本机网卡地址。

回归要求：初始本机/内网 URL、域名解析私网、混合 DNS 答案、重定向到本机、DNS 重绑定均被拒绝，且不向受限目标建立连接；正常公网、合法重定向和 IPv6 订阅仍可刷新。若改用 Node http(s)，须保留 gzip/deflate/br 兼容，并限制**解压后**大小。审查草稿曾出现压缩 ICS 无法解析的回归，不能照抄后跳过测试。

### SEC-02：资料导出可借私有项目根链接带出程序状态

位置：基线 `packages/core/src/settings.ts:20,32`。

普通遍历跳过点目录，但导出另行显式遍历 `.kaitu/local-projects`。该根若是指向程序状态的同根符号链接，密钥文件可被当作私有项目资料打入 ZIP。导出还须防范非隐藏状态目录或别名被当作普通资料收集。

建议：导出根与每个子节点采用一致的真实路径策略；排除实际程序状态、密钥、版本库、索引、依赖和符号链接别名。明确备份内容清单。本人主动生成的本地完整备份可以包含私有业务资料，不应因此将其程序凭据一并打包；可分享导出应另按公开规则处理。

回归要求：ZIP 内没有合成密钥、程序配置/历史/索引或越界文件；`.kaitu/local-projects` 根链接、子链接、非隐藏状态别名均不能绕过。正常笔记、附件与合法私有项目仍保留。

### SEC-03：默认内置 AI 的文件与搜索边界仍可触及程序秘密

位置：`packages/desktop/sdk-filesystem.mjs`、`sdk-host.mjs`、`sdk-runtime.mjs`、`environment.mjs`。

旧问题仍需处理：只限制“位于资料工作区内”，没有统一排除 `.kaitu` 等程序状态；官方搜索工具不一定走同一文件服务。新增环境配置还允许把自定义程序 home 放入资料目录的非隐藏子目录，使凭据变成可读资料。

建议：默认 scoped 模式的读取、字节读取、范围读取、目录枚举、metadata、编辑和搜索共享策略，检查请求路径、真实路径及操作时的路径；禁止秘密及安全配置。限制搜索子进程参数，并在执行与结果返回两端检查。保留正常笔记和必要的只读技能。程序 home 与资料目录应有明确的隔离关系。

回归要求：使用实际 DSH rc.2 文件类和搜索实现验证直接路径、同根别名、跨根及悬空链接、遍历搜索、显式搜索都读不到合成密钥；配置不能被模型改写；正常资料读写、搜索、技能和启动仍工作。

**权限模式边界：** 完整 Agent 是产品明确设计的二次授权功能，不能擅自删除，也不能把它当成默认模式意外提权。它提供同一系统用户的命令与文件能力，当前不能声称该模式仍绝对读不到程序凭据。开发方需明确其授权说明；若要求完整模式也保护凭据，需要独立系统隔离等设计，不能只靠提示词或文件工具黑名单。

### SEC-04：共享配置能重定向本机程序状态，新增行情缓存也绕开统一策略

位置：基线 `packages/core/src/workspace.ts:38`、`finance/quotes.ts:40`、`sync-location.ts`。

`state_dir` 来自可共享的工作区配置，主要只验证为绝对路径；后续版本、缓存等操作信任该位置。行情缓存新增了自行读取此配置的分支。仅挡住桌面编辑 `.kaitu`，不足以防共享目录内容从别处被改变。

建议：采用由本机维护的工作区与状态根绑定，或其他等效可信机制。所有状态读写复用同一策略，不允许任意配置重定向。还要防止删除 `state_dir` 后静默退回云盘内 `.kaitu`，导致凭据重新被同步。

回归要求：恶意外部路径、替换后的符号链接、换成另一工作区状态根、删字段/空字段降级均拒绝；拒绝后目标没有读取或写入。正常同步开关、搬迁、换机、历史恢复及旧工作区迁移仍能完成。

兼容要求：草稿采用本机登记和显式 `sync trust-state` 迁移，代价是旧同步工作区需要额外处理；这只是候选方案。开发 Agent 应评估更顺畅且可信的迁移，不能把“无法打开旧资料”作为可接受的最终体验。识别标准云盘路径也不能保证识别任意自定义同步目录。

### SEC-05：私有待办及关联探索仍可通过公开出口或实际同步文件泄露

位置：`tasks.ts`、`projects.ts`、`workbench.ts`、`overview.ts`、`agent-tools.ts`、`exploration.ts`、CLI `mcp/server.ts`，以及实际 JSONL/NOW 文件。

旧审查的私有待办问题仍在。新增复查发现需要同时覆盖：

- `task_list`、通用 `record_list(task)`、公开 status、当前与过期 OVERVIEW。
- NOW 中复制的任务标题、任务 ID、项目路径及公开文件读取。
- 先关联公开项目、再把项目设为私有时，已有方向、尝试、依据及历史时间线的项目引用。
- 修改接口返回的完整记录，不能只过滤查询接口。
- Drive/iCloud **实际文件及全部历史修订**。接口返回为空不意味着云盘没有内容。

建议分两层实施：公开投影统一继承项目可见性，检查直接 project 字段、结构化 references 和父方向/尝试关系；存储层确保私有内容不进入同步目录。失效引用和循环关系应保守处理。不能以更换类型名绕过同一内容的权限。

待批准的最小存储方案见 [私有待办提案](kaitu-private-task-storage-proposal.md)：公开任务维持现路径，私有任务进入既有本机私有库，保留 ID/字段/修订语义；迁移必须包含所有修订和删除标记，先验证本机副本再清除共享原件，并设计中断恢复。关联探索的实际文件也需一起评估，不能任务搬完就宣布全部出口安全。

回归要求：建立一个私有项目及含唯一合成标记的任务、计划、方向和尝试，遍历所有上述公开出口以及同步文件/历史，标记均不出现；本机仍能读写、完成与恢复。覆盖公开转私有、私有转公开、删除和迁移中断。公开化必须有明确语义，不能意外公开旧私有历史。

已上传云端历史、其他设备和备份无法靠本机搬目录保证撤回，应单列清理要求。自由正文中人为复制的秘密也不能宣称可由结构化引用过滤自动识别。

### SEC-06：模块定义与实体路径缺少一致的隔离

位置：基线 `packages/core/src/modules.ts:33,41`、`records.ts:196`、`schema.ts`。

基线未在使用模块定义前统一验证 schema，记录目录直接拼接后枚举。新增代码已将具体记录读取改走 `ws.scanText`，因此不要照搬旧报告、声称原先所有越界读取路径完全不变；但非法模块定义、同工作区链接到财务/程序状态、自定义 schema 路径仍需封闭。

建议：使用定义前验证模块 schema 与目录身份；数据目录、月度文件、自定义 schema 都限定在所属模块的真实路径内，禁止借别名进入其他模块或程序状态。使用统一解析策略，不能只对读操作或类型名做检查。

回归要求：目录穿越定义被拒绝；外部目录、跨模块目录、程序状态目录、月文件和 schema 链接均不能读写；合法自定义模块可正常使用。`validate` 应返回有文件定位的错误，而不是因受限链接导致整次校验崩溃。

### SEC-07：银行通知详情重复进入可同步的普通收件箱

位置：基线 `packages/channels/src/collectors/imap/watcher.ts:198,214`。

流程先把邮件摘录写入普通 inbox，再把通过验证的银行动账通知写入本机候选。即使财务候选本身隔离，金额、卡尾号、商户等仍可能从普通收件箱被同步或被 AI 读取。

建议：对可识别的银行动账通知先分流，认证通过后只进入本机候选；未通过认证时不给候选，也不把相同银行详情重复写入共享摘录，使用固定状态提示用户核对邮箱。候选不能直接作为已确认交易记账。

回归要求：合法通知只生成本机候选，不出现在普通 inbox/公开摘要/同步文件；伪造 Authentication-Results、双 From、非白名单及不完整签名不能获得可信银行身份；无自动记账或回信。普通已授权邮件采集仍工作。

限制：现有解析器只识别部分格式；不能宣传“所有财务邮件都已自动隔离”。历史已采集的银行摘录需另行识别与处理，本轮没有清除真实数据。

### SEC-08：财务 HTTP 提交可绕过上传流程读取本机文件

位置：基线 `packages/cli/src/ui/product.ts:331`。

DSH 财务入口已有上传范围限制，HTTP `financeImportCommit` 未采用同等约束。合成测试可把未上传的本机绝对路径 CSV 导入资料。前提是能调用该受保护的本机接口，不应称为已证实的匿名远程任意文件读取。

建议：HTTP 确认入口只接收本次受控上传产生的标识或路径，统一检查格式、真实位置和关联工作区；不能仅依赖前端给正确路径。

回归要求：未上传的绝对路径、目录穿越、其他工作区上传文件、指向密钥/外部文件的链接被拒绝；经过正常上传和预览的账单可提交，拒绝后不改变资料或读取外部内容。

### SEC-09：完整 Agent 切回受限模式存在并发窗口

位置：基线 `packages/cli/src/ui/ask.ts:215,238`。

切换先检查 busy，随后等待旧运行时关闭，最后才更新模式。在等待期间发送消息可能继续使用旧 Full 运行时。只禁用前端按钮不足以堵住服务端竞态。

建议：将模式切换、配置与会话/工作区变化纳入服务端状态转换；切换开始即拒绝新发送和并发切换，失败后也不能恢复成未明确授权的权限。保留用户主动确认的 Full 功能和新会话默认受限行为。

回归要求：用受控延迟的 close 模拟切换窗口，期间无法调用旧 Full 运行时；切换后消息确实使用 scoped；新会话、跨会话发送、配置变更和失败恢复都不继承错误权限。现有草稿的搬迁门禁只覆盖关闭阶段，开发方还需检查整个搬迁事务。

5. 逐条对照上一轮原文和本清单，给出修复提交、测试、仍存在的限制。标清“确认漏洞”“加固”“产品权限设计”“部署待验”。
