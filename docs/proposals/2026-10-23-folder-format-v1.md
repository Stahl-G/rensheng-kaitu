# 开图文件夹格式 v1：补三份读的视图（2026-10-23，用户已同意方向）

## 目标

开图首先是一种文件夹格式，界面只是看它的一个窗口。检验标准：**拿掉界面，只把文件夹交给一个最便宜、只会读写文件的模型，它也能在一分钟内弄懂“这是谁的资料、他是谁、这阵子怎样、今天做什么”，并且能安全地写进东西。**

依据见 [`docs/research/2026-10-22-folder-format-research.md`](../research/2026-10-22-folder-format-research.md)（论文、成熟记忆系统、纯文本约定、多写者与云盘同步）。

## 现状：七八成已经是成熟做法

| 成熟做法 | 开图现在 |
|---|---|
| 入口是 `AGENTS.md`，`CLAUDE.md` 指向它 | 已有 |
| 记忆：一行一条的索引 + 一主题一文件 + frontmatter（Claude Code、Letta MemFS） | 已有：`memory/MEMORY.md` + `memory/<类>_<id>.md`，带 type / name / created / updated |
| 无工具的 Agent 只往收件处放文件，由一个程序收拢 | 已有：`inbox/agents/` + 每日整理 |
| 原始记录只追加，带 id、来源和删除标记 | 已有：按月 JSONL，`id` / `by` / `rev` / `deleted` |
| AI 只提议，用户采纳才生效 | 已有：proposed / suggested / pending |
| 能认出云盘冲突副本和 iCloud 占位文件 | 已有：体检提示冲突副本，认得 iCloud 占位文件 |
| 生成的文件内容不变就不重写，减少云盘冲突 | 已有：`OVERVIEW.md` 去掉时间后比对，不同才写 |

差的三处都在“读”这一侧：

1. **没有一页画像。** “这个人是谁、这阵子怎样”散在 `me/profile.md`、`me/goals.json`、`me/rules.md`、`me/ongoing.json`、`me/STATUS.md`、`me/data/phases/`、`memory/` 七处。便宜模型读两三个就停了。
2. **按月记录只能裸读 JSONL。** 同一个 id 只有最后一行算数，还有删除行；模型直接读会把旧版本、删掉的也当成现在的（健康页“同一顿饭出现两遍”就是这类问题）。
3. **`AGENTS.md` 第一屏是任务表，默认对方有命令行。** 只能读写文件的 chatbot 不知道先读哪几个文件，也要翻到后面才知道没有工具时怎么写。

## v1 做什么：只加读的视图，不改任何数据格式

### 1. `ME.md`：一页画像

由 App 从上面七处汇总生成，本身**不是数据源**；改动仍写回原文件。

```markdown
---
generated: 2026-10-23T08:00:00+08:00
note: 程序生成，不要直接改。改画像写 inbox/agents/，或在开图里改。
---
# 陈一舟（示例）

## 这个人
住在杭州，做产品，业余写散文。喜欢简洁、具体的中文。（me/profile.md）

## 这阵子（用户确认，2026-10-15 起）
在赶开图的发版，小说先放一放。（me/data/phases/…）

## 想做成的事
1. 两年内出版第一本散文集 · 下一步：改完第三篇（me/goals.json）

## 规矩
23:30–07:30 睡觉；22:00 后不排事。（me/rules.md）

## 记住的事（最近 10 条，全部见 memory/MEMORY.md）
- 喜欢傍晚去健身房（2026-10-20，claude-code）
```

- 上限约 1k token（中文约 1500 字）。超了只保留最近、最常用的，其余靠链接。
- 每条带日期和来源，方便模型判断新旧、用户追溯。
- “这阵子”只显示用户确认过的阶段记录（phase）。Agent 听到“这阵子……”就提一条 suggested 阶段，用户采纳后出现。
- `sensitive` 的记忆不进 `ME.md`。

### 2. 按月记录的 `.md` 当前视图

每个 `<领域>/data/<类>/2026-10.jsonl` 旁边生成同名 `2026-10.md`：每个 id 只留最新版本，去掉已删除的，按时间排，一行一条。

- 规范写明：**读用 `.md`，写用工具或 `inbox/agents/`，不直接改 `.jsonl`。**
- 视图和 `OVERVIEW.md` 一样：不进版本历史，随时可重建；沿用“内容不变不重写”。

### 3. `AGENTS.md` 第一屏改成“先读这三个”

第一屏（约 20 行）只讲：

- 这是谁的什么文件夹；
- 先读 `ME.md` → `NOW.md`，其余按需；
- 目录地图，每个目录一行；
- **没有工具时只做一件事：** 往 `inbox/agents/` 新建一个 `.md`，frontmatter 写 `agent` 和 `date`；改画像、目标、规则一律写成提议；
- 三条会写坏数据的边界。

现在的任务表和细则挪到后面。整个文件控制在 100 行以内（研究显示入口越长越不遵守，多余要求还会降低成功率）。

### 谁来生成

和 `OVERVIEW.md` 同一套：本机 App 在后台、文件变化后生成，内容不变不写。两台电脑都开着时，算出来的内容相同就都不写，不会造冲突副本；内容不同时，建议以每日整理所在的那台为准（实现时确认）。

### 耗时

视图生成放后台，不挡任何界面操作。交审时在合成大工作区（5,000 条记忆、10,000 条记录）上实测首次生成和增量更新，写进 PR 描述。

## 验收：拔掉界面的互通测试

合成一个虚构人物 18 个月的资料，故意埋 3–4 次“改变”（搬家、换目标、换训练安排）。分别交给三档模型：最便宜的只读写文件的 chatbot、Claude Code、Codex。

| 题型 | 例题 |
|---|---|
| 单点事实 | 他住哪？ |
| 跨文件综合 | 哪个目标没有下一步？ |
| 时间推理 | 上周训练了几次？ |
| 知识更新 | 现在的目标是什么？（要用最新那条） |
| 拒答 | 他的护照号？（没有就说不知道） |
| 来源 | 这条记忆是谁、什么时候记的？ |
| 写入 | 记一顿饭、记一句话、提一个待办、提一条“这阵子”、记住一个偏好 |

过关：10 道问答至少答对 9 道；5 次写入都落在 `inbox/agents/` 或正确位置、都是提议状态、没改坏任何文件；全程读的文件不超过 10 个。同时记下读了多少 token。

改格式前后各跑一遍对比；以后每次改格式都跑，加进 Dot 的发版走查。题目、合成资料和脚本放仓库外（AGENTS 第 9 条），结果写 PR 描述。

## v1 不做（以后要改数据格式，需用户另行批准）

| 事 | 为什么以后做 |
|---|---|
| 记忆“作废不删”：改事实时旧的标作废，记“何时为真 / 何时记下” | 要改记忆 frontmatter，属于数据规范 |
| 收件文件名改成 `inbox/agents/<写者>/<ULID>.md`，写者细到“Agent + 机器” | 现在撞名概率低，改动要同步模板与收拢逻辑 |
| 冲突副本自动修复（并集 → 去重 → 重新折叠） | 现在提示用户手动处理，够用 |
| 整数 `rev` 换成 ULID / HLC | 记作已知风险：两台机器可能同时写出同一个 `rev` |
| 新目录用可读短名、本机绝对路径移进 `.kaitu/` | 涉及项目目录和 STATUS 字段 |
| 对外规范 `docs/format/` 标 `format: 1` | 等 v1 视图落地、互通测试过了再写 |
| 实测各家云盘冲突副本命名（含百度网盘） | 交 Dot 在常用的云盘上各造一次冲突 |

## 要用户确认的

1. 加 `ME.md`，App 生成，不当数据源。
2. 每个按月记录加 `.md` 当前视图，不进版本历史。
3. `AGENTS.md` 第一屏改成“先读三个 + 无工具写入一条”，全文 ≤100 行。
4. 互通测试作为格式的验收标准，加进发版走查。

确认后拆成三个小 PR：1 → 2 → 3，排在 0.1.2 发版之后（同时最多三条线）。
