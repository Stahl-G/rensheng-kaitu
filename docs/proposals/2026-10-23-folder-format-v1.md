# 开图文件夹格式 v1：最小只读阅读层（2026-10-23，待用户确认）

## 目标

开图首先是一种文件夹格式，界面只是看它的一个窗口。检验标准：**拿掉界面，只把文件夹交给一个最便宜、只会读写文件的模型，它也能很快弄懂“这是谁的资料、他是谁、这阵子怎样、今天做什么”，并且能安全地写进东西。**

依据：[`docs/research/2026-10-22-folder-format-research.md`](../research/2026-10-22-folder-format-research.md)，以及 Astra 对本提案前一版（3c83ef1）的独立评估。

**本版只加一层“读”的东西，不升级数据结构，也不绑定 0.1.2。** 先证明好读，再考虑扩展。

## 不动的东西

- 按月 JSONL 仍是正本，现有修订号 `rev`、删除标记和手机协议全部保持不变。
- 任何设备照常写正本，不需要指定谁来写。
- 记忆的归档和替换已经有了，直接复用：`archiveMemory` / `replaceMemory` 会写 `ended` 和 `replaced_by`，只能由用户决定；Agent 用 `inbox/agents/*.memory.json` 的 `replaces` 字段提议替换。
- 隐私规则复用 `handoverPack` 那一套：敏感记忆不出工作区，财务按 `agentCanRead` 判断，发出前去掉密钥和本机路径。

## 现状：七八成已经是成熟做法

| 成熟做法 | 开图现在 |
|---|---|
| 入口是 `AGENTS.md`，`CLAUDE.md` 指向它 | 已有 |
| 记忆：一行一条的索引 + 一主题一文件 + frontmatter | 已有：`memory/MEMORY.md` + 每条记忆一个文件 |
| 改事实时旧的不删、标作废 | 已有：`ended` / `replaced_by`，由用户决定 |
| 无工具的 Agent 只往收件处放文件，由一个程序收拢 | 已有：`inbox/agents/` + 每日整理 |
| 原始记录只追加，带 id、来源和删除标记 | 已有：按月 JSONL |
| AI 只提议，用户采纳才生效 | 已有 |
| 认得云盘冲突副本和 iCloud 占位文件 | 已有 |
| 一份去掉隐私的“近况”给别的 AI | 已有：`handoverPack`，但只在界面里复制，不落盘 |

真正缺的两处：

1. **没有落盘的一页画像。** 只会读文件的模型看不到 `handoverPack`。它要从 `me/` 下五六个文件和 `memory/` 自己拼，便宜模型读两三个就停了。
2. **`AGENTS.md` 第一屏是任务表，默认对方有命令行。** 只能读写文件的 chatbot 不知道先读哪几个文件，也要翻到后面才知道没有工具时怎么写。

## v1 做什么

### 1. `ME.md`：可追溯的一页画像

内容和筛选规则与 `handoverPack` 相同：目标、结果、下一步、项目、方向、确认过的“这阵子”、非敏感且未归档的记忆。默认不含财务；只有 `agentCanRead(ws, "finance", …)` 允许时，才加入汇总数字。

```markdown
---
generated: 2026-10-23T08:00:00+08:00
publisher: mac-studio
based_on: 7f3a…   # 来源文件的指纹
note: 程序生成，可能落后于正本；以正本为准。改动写 inbox/agents/，或在开图里改。
---
# 我的近况（示例）

## 想做成的事
1. 两年内出版第一本散文集 · 下一步：改完第三篇（me/goals.json）

## 这阵子（用户确认，2026-10-15 起）
在赶开图的发版，小说先放一放。（me/data/phases/…）

## 记住的事（最近 10 条，全部见 memory/MEMORY.md）
- 喜欢傍晚去健身房（memory/preference_s6b0mn52.md，2026-10-20）
```

- **可追溯：** 每条都写明来自哪个文件，模型和用户都能回到正本核对。
- **只读、不当数据源：** 改动写回原来的文件，或者走收件箱提议。
- **上限：** 约 1k token，超了只留最近、最常用的。
- **新旧：** frontmatter 记下生成时间、生成的设备和来源指纹。来源里只要有一个文件还没从云盘下载，就不重新生成，旧的那份保留并标明“可能过期”。生成时一律跳过 `ended` 的记忆和已删除的记录，删除不会被旧摘要带回来。
- **不碰正本链路：** 不进版本历史，不进备份，不参与“是否已下载”的检查和校验。删掉它，开图照常工作。

### 2. 指定一台发布端

共享的 `ME.md` 只由一台设备生成，避免两台设备同时生成、互相覆盖出冲突副本。

- 默认是每日整理所在的那台电脑，可以在设置里换。
- 发布端记在本机设置（不同步的 `.kaitu/` 或本机状态目录）里，具体位置实现时定。
- 其他设备照常读写正本，只是不写 `ME.md`。
- 没有发布端（比如只有手机），就不生成 `ME.md`，`AGENTS.md` 会说明去哪里看原文件。

### 3. 按需阅读包

不落盘。复用 `handoverPack`，给 MCP / CLI 加一个“给我一份近况”的读取口，Agent 在需要时现取，拿到的永远是当前正本算出来的结果。

### 4. `AGENTS.md` 第一屏改成“先读这几个”

第一屏（约 20 行）只讲：

- 这是谁的什么文件夹；
- 先读 `ME.md`（标了“可能过期”就以正本为准）→ `NOW.md`，其余按需；
- 目录地图，每个目录一行；
- **没有工具时只做一件事：** 往 `inbox/agents/` 新建文件；改画像、目标、规则、替换记忆一律写成提议；
- 三条会写坏数据的边界。

现在的任务表和细则挪到后面。整个文件控制在 100 行以内。这一条只改生成模板的文字，不改任何数据。

## 先不做

- **按月记录的全文 `.md` 镜像（上一版的 `views/`）。** 删除标记所在的分片可能还没同步下来，两台设备也可能同时生成，这两种情况都会让镜像把删掉的旧内容重新带回来。按目录处理隐私（比如财务）、备份和历史也得一一补规则。所以等互通测试证明 `ME.md` 加阅读包还不够，再单独提。
- 收件文件名改成按写者分目录、修订号改用 ULID / HLC、冲突副本自动修复、可读目录名、对外格式规范。这些都要改数据规范，需要你另行批准。
- 实测各家云盘冲突副本的命名（包括百度网盘）。交给 Dot，在常用的云盘上各造一次冲突。

## 验收

**数据安全（必须全过，在合成工作区上做）：**
- 删掉 `ME.md`，所有功能照常。
- `ME.md` 在 iCloud 上被卸载时，正本的写入、修改、删除、恢复、升级都不受影响。
- 已归档的记忆、已删除的记录、敏感记忆都不出现在 `ME.md` 里；没有财务权限时，财务数字也不出现。
- 两台设备同时开着时，只有发布端写 `ME.md`，不产生冲突副本。
- 来源文件没下载全时，不重新生成，旧 `ME.md` 标明“可能过期”。

**阅读效果（拔掉界面的互通测试）：** 合成一个虚构人物 18 个月的资料，埋 3–4 次“改变”，分别交给最便宜的只读写文件的 chatbot、Claude Code、Codex。题型包括单点事实、跨文件综合、时间推理、知识更新、拒答、来源，再加 5 次写入。v1 上线前后各跑一遍，记下答对率、读的文件数和 token 数。改动后要明显更好才算成立，否则撤回。

题目、合成资料和脚本放在仓库外（AGENTS 第 9 条），结果写进 PR 描述。

## 要用户确认的

1. 加 `ME.md`：可追溯、只读，筛选规则与交接包相同，只由一台发布端生成。
2. 给 MCP / CLI 加一个按需取近况的读取口，复用 `handoverPack`。
3. `AGENTS.md` 第一屏改成“先读这几个 + 无工具写入一条”，全文不超过 100 行。
4. 按月全文镜像先不做，等互通测试的结果再决定。

确认后拆成小 PR：1 → 2 → 3。排期按当时同时最多三条线的空位来，不绑定 0.1.2。
