# 设计草案：人生开图——由 Agent 读完资料，为这个人写的一页

状态：草案，第一轮讨论已吸收（2026-11-01）。讨论结束、用户拍板后再交给 Dot 开发。
来源：用户和 Claude 的讨论（AI 实时生成界面的演示、人生资料像代码仓库一样被读懂）。样张：<https://claude.ai/artifact/YGJVkNSXGX1yQx7zpBg7oe>（三个虚构的人：工程师、插画师、转折期的人）。

## 1. 一句话

用户点一个按钮，开图让 Agent 读完他的资料，写出一页 HTML，回答一个问题：**在模型眼里，你的人生长什么样**。版式、颜色、讲什么都由 Agent 为这个人决定，每个数字都能点回原始记录。

## 2. 为什么做

- 开图已经把一个人的生活维护成了一个结构化的「人生仓库」：记录、项目、健康、足迹、相册、笔记，带修订历史和原文出处。写代码的人早就习惯让 Agent 读仓库、画出架构图；同样的事情放到人生这一层，还没有人做好。
- 固定模板的年度报告（一二三四五六条、几个大数字）人人都一样，用户已经看腻了。这一代模型有足够的审美和理解力，能为工程师、艺术家、处在转折期的人写出完全不同的一页。
- 同一个人在第一个月和第一年会得到完全不同的页面。把每次生成都留下来，本身就是一份人生记录。

## 3. 别人做过什么，我们新在哪

| 方向 | 代表 | 做到了什么 | 缺什么 |
|---|---|---|---|
| 读代码仓库画图 | [Archify](https://betterstack.com/community/guides/ai/archify-architecture/)、[CodeGraph](https://github.com/NisargPatel03/CodeGraph)、[GitGraph](https://github.com/terrdv/GitGraph) | Agent 读仓库，节点能点回源文件和行号；Archify 先让 AI 写结构化描述、核对后再渲染 | 只做代码 |
| 个人数据做成设计作品 | [Feltron Annual Report](https://dublin.sciencegallery.com/lifelogging-exhibits/feltron-annual-report)（2005–2014） | 把一个人的一年做成精美报告 | 设计师亲手做，不能给别人用 |
| 健康 App 的年度报告 | Gyroscope | 每年一份个人报告 | 固定模板，人人一样 |
| 把人生存成给 Agent 读的 markdown | [LifeOS-OSS](https://github.com/kcwoodfield/LifeOS-OSS)、[picturpoet/life-os](https://www.mdskills.ai/mcp-servers/life-os) | 长期记忆仓库 | 只存不画；看板是固定表格 |
| 让 AI 凭记忆画出你 | 「画一张代表我人生的图」类提示词、[Life Note Inner Gallery](https://blog.mylifenote.ai/your-inner-gallery-art-that-grows-with-you.md) | 有趣、个性化 | 依据零散，数字无法追溯 |

**新在组合**：长期维护的结构化人生资料 + Agent 像读代码一样读它 + 由模型按这个人决定的设计 + 每个数字能点回原记录 + 给出评价（好在哪、坏在哪、可以怎么改、走到了哪）。这五点同时做到的，我们没有找到。

**这不是壁垒**：有一个 LifeOS 仓库再写一段好提示词，几天就能做出类似的东西。难复制的是开图的资料层：统一的记录格式、各来源的导入、多年修订历史、精确到行的出处。这一页的价值是把这一层展示出来。

## 4. 产品形态（第一版）

- **入口**：「我」或问问里的一个按钮「生成人生开图」。点击后先出一张生成配置卡：
  - **资料范围**：日常、阅读、工作默认勾选；健康、财务默认不勾选。每个范围旁写一句它会给页面带来什么（比如「健康：睡眠、训练和心情之间的关系」），不写「勾选可解锁某某」这类奖励话术。健康、财务属于敏感外发，授权要出于用户的本意。
  - **语气**：「直接」或「温和」两档。
  - **说明**：会调用你在问问里配置的模型，大约耗时多久。
- **过程**：在问问里发出一段提示词，Agent 按第 5 节的流程工作，用户能在问问里看到进度，也能中途追加要求，比如「这次多写写工作」。
- **产物**：工作区里的一个 HTML 文件，用外部浏览器打开。它**不进开图本体的导航**，定位是展示和回看。
- **题目**：
  - **我的人生开图**：总图，按季度或按年生成；
  - **阅读报告**：一年读了什么、划线最多的句子、哪些书之后笔记里出现了新词；
  - **工作报告**：项目、产出、节奏、卡住的地方，可以写成「年度发布说明」；
  - **人生总结**：按用户自己划分的时期写成章节。
  
  用户也可以自由描述想要的题目。

## 5. 生成流程：出处严格，排版放开

借鉴 Archify：**依据先核对，再进页面；页面本身完全交给模型。**

1. **读**：Agent 通过现有 MCP 或 SDK 工具读取用户勾选的范围，不直接扫描私密目录。
2. **写依据清单**：Agent 先输出一份 `claims`，每条是一个要写进页面的数字或事实，带来源（文件路径加行号，或记录 id）以及算法说明（比如「近 90 晚的平均」）。
3. **程序核对**：开图逐条检查。来源存在吗？数字能从来源算出来吗（能复算的复算，复算不了的标成「Agent 推断」）？没通过的条目退回给 Agent 修改或删掉。
4. **写页面**：Agent 自由写 HTML、CSS、JS。页面里的数字只能引用已经核对过的条目。每个数字旁边带一个出处标签，点开显示来源路径和原文片段。
5. **入口检查一次（AGENTS 第 5 条）**：
   - 页面不允许访问网络：外部请求、远程字体、远程图片都不行，只能内嵌；
   - 不能读取页面以外的本地文件；
   - 文件大小有上限；
   - 出处标签必须都能对上依据清单。
   
   通过才保存；不通过就在问问里说明哪里不对，让 Agent 改。
6. **保存**：页面和依据清单放在一起，进版本历史，跟随同步。每次生成都单独保留一份，不覆盖旧的。

## 6. 每一页必须有的，以及不规定的

版式不设模板。除下面五样之外，全部由 Agent 按这个人决定：

1. **封面一句话画像**：比如「在秩序边缘高强度运转的造桥人」，而不是《我的人生开图报告》。
2. **「为什么画成这样」**：用资料里的证据说明为什么选这种风格，比如「你的笔记里『依赖』出现的次数是『感觉』的 9 倍」。这一块是这一页的灵魂，也是对用户的交代。
3. **缺口照实写**：资料少的时期、没有记录的月份，照实留空，并写明这是「记录上的空白」。可以说「这段时间关于朋友的记录是空的」，不能推论成「你不重视朋友」：没记下来，不等于没发生。本次没读取的范围，中性地写「本次未读取」，不画成迷雾或待解锁。
4. **出处能点开**：点开展示的是当时写下的原话或原记录片段，像打开一个时光胶囊，而不是只显示一行文件路径。页面应主动挑出几段有画面感的原话。
5. **封存章**：页面底部写期数、生成时间、读取了哪些范围、基于多少条记录。每次生成都是一期，方便以后并排对比。

内容上优先写**跨领域的关联**：比如「工作最焦虑的那两周，你反而读完了最难的那本书」，不写单项流水账。关联要标出样本数，措辞用「同时出现」而不是「导致」；样本少的明确标成提示。

## 7. 评价部分的规则

- 评价写成三块，不写成「优点、缺点、整改建议」：
  - **高光复利**：在哪件事上展现了持续力或独特品味；
  - **隐性内耗**：什么事情正在耗掉精力却没有结果；
  - **下一个小实验**：基于现有习惯，一个下周就能试的动作，不喊口号。
- 评价属于 AI 的观点，视觉上和事实分开，比如做成批注或侧栏；不写回资料，也不升级成用户事实或承诺（AGENTS 第 12 条）。
- 健康相关内容只描述记录到的变化，不做诊断；涉及就医的，只提醒去核对自己已经写下的复查事项。
- 语气只有「直接」「温和」两档，由用户在配置卡里选。任何一档都不嘲讽、不说教，也不拿这个人和其他人比较；健康和心情相关的内容在任何语气下都只描述，不评价。

## 8. 隐私与外发

- 生成需要把选定范围的资料发给模型，属于外发。按钮前写明会发什么、发给谁（问问里配置的模型）。
- 默认不包含的范围：凭据，以及标记为敏感的记忆。财务、健康默认勾选与否，留给讨论（见第 11 节）。
- 生成的 HTML 是本机文件，不自动上传、不自动分享。用户自己决定要不要发给别人。

## 9. 和现有人生地图的关系（只列问题，不在本草案决定）

现在的人生地图是程序生成的：带着从上游开源项目整个搬进来的地图生成器（约 1.56 万行），以及桌面、iOS 两套显示和同步代码，维护成本高。讨论过的一个方向是：
- 由 Agent 生成地图 SVG；
- 程序只负责把区域变成可点击的入口（区域链接到工作区路径）；
- 入口检查一次，不通过就继续用上一张。

这会动到人生地图的数据和显示方式，需要单独提案、单独确认格式（AGENTS 第 2 条）。本草案的第一版**不碰人生地图**；做完人生开图、看过真实效果后，再决定地图要不要跟着改。

## 10. 不做

- 不做实时生成的界面，不替代今天、开图、资料、问问这些固定页面。
- 第一版不在手机上生成。手机以后可以打开电脑生成好的文件。
- 不做分享平台、模板市场。
- 不为这一页新增数据格式；依据清单是附在页面旁的派生文件。

## 11. 留给讨论的问题

1. **文件放在哪、叫什么。** 候选：`portraits/2026-11-01-我的人生开图.html` 加 `.claims.json`，或者放进 `reports/`。按 AGENTS 第 10 条，先查有没有现成的叫法和格式可以用。依据清单可以先看 W3C Web Annotation、schema.org 的 Claim 是否贴合；本草案还没有核实。
2. **依据清单的粒度。** 每个数字都列，还是只列核心论断？列得越细，核对越可靠，但 Agent 写得越慢。
3. **复算的范围。** 程序能复算的只有统计类数字（平均、总数、次数）；「最常出现的词」「心情最好的月份」这类，算复算还是算推断？
4. ~~财务、健康默认要不要读~~ **已定**：默认不勾选，配置卡写清每个范围会带来什么，见第 4 节。
5. **按钮放在哪。** 放在「我」、问问，还是开图的人生地图旁边？
6. ~~页面里的脚本~~ **已定**：允许内联 JS（动画、交互、在页面内弹出原文片段），一律禁止联网，入口检查同时拦截外部地址和网络接口调用。
7. ~~重新生成的规则~~ **已定**：在问问里局部修正。用户说「十月没写读书笔记是因为在备考」，Agent 把这条背景补进依据清单，只重写受影响的那几块，生成新的一期；想换个画法也是一句话的事。整个重读只在用户明确要求时做。
8. **桌面应用和 DSH 插件都要有吗**，还是先只做一个？

## 12. 已讨论、暂不采纳

第一轮讨论（另一位 Agent 从产品和用户心理角度给的意见）里，下面几条不采纳或推迟，写在这里，免得重复提出：

| 提议 | 结论 | 理由 |
|---|---|---|
| 固定五个模块、四种题目各配一种视觉风格 | 不采纳为结构，只作为给 Agent 的参考示例 | 写成模板就又变回人人一样的年度报告，违背「模型为这个人决定」 |
| 把没授权的领域画成迷雾或「未点亮」 | 不采纳 | 在视觉上暗示用户缺了什么，等于引导交出更多数据；改为中性的「本次未读取」 |
| 「犀利刺痛 / 毒舌」语气 | 不采纳 | 会读到睡眠、心情、财务，也会给到状态不好的人；基于不完整资料的尖锐判断可能错得很有说服力 |
| 配置卡写「勾选可解锁某某分析」 | 不采纳 | 敏感外发不用奖励话术换授权 |
| 从外部浏览器跳回开图本体 | 推迟 | 需要注册 `kaitu://` 链接协议；第一版只在页面内弹出原文 |
| 截图分享 | 推迟 | 要先设计能自动去掉敏感内容的分享版 |

## 13. 怎么算做成（给之后的开发任务用）

- 三份风格迥异的合成工作区（类似样张里的三个人），各生成一页。三页的版式、配色、讲的内容明显不同，并且各自的「为什么画成这样」能对上资料里的证据。
- 每页随机抽 10 个数字，点开出处都能对上原记录；故意塞进一个错误数字的依据清单，会被程序拦下。
- 生成的页面断网能正常打开；页面里写一个外部请求，入口检查会拒绝。
- 每页都有第 6 节要求的五样；所有关联都标了样本数，没有「导致」类的措辞。
- 在问问里提一次局部修正，新的一期只改了受影响的部分，旧的一期保留。
- 在用户受控的资料副本上生成一次，由用户本人评价「像不像我」。这一条是唯一的主观验收，也是最重要的一条。
