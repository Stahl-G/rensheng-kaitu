# 设计草案：人生开图——由 Agent 读完资料，为这个人写的一页

状态：用户已拍板（2026-11-01），可以交给 Dot 开发。第二轮按用户意见大幅简化：娱乐为主，一个按钮，一段提示词。
来源：用户和 Claude 的讨论（AI 实时生成界面的演示、人生资料像代码仓库一样被读懂）。样张：<https://claude.ai/artifact/YGJVkNSXGX1yQx7zpBg7oe>（三个虚构的人：工程师、插画师、转折期的人）。

## 1. 一句话

用户点一个按钮，开图让 Agent 读完他的资料，写出一页 HTML，回答一个问题：**在模型眼里，你的人生长什么样**。版式、颜色、讲什么都由 Agent 为这个人决定，每个数字都能点回原始记录。

定位参考网易云音乐的「年度听歌报告」：好玩、能一页页翻、有音乐，看完想截图。它不是体检报告，也不是绩效评估。

## 2. 为什么做

- 开图已经把一个人的生活维护成了一个结构化的「人生仓库」：记录、项目、健康、足迹、相册、笔记，带修订历史和原文出处。写代码的人早就习惯让 Agent 读仓库、画出架构图；同样的事情放到人生这一层，还没有人做好。
- 固定模板的年度报告（一二三四五六条、几个大数字）人人都一样，用户已经看腻了。这一代模型有足够的审美和理解力，能为工程师、艺术家、处在转折期的人写出完全不同的一页。
- 同一个人在第一个月和第一年会得到完全不同的页面。把每次生成都留下来，本身就是一份人生记录。

## 3. 别人做过什么，我们新在哪

| 方向 | 代表 | 做到了什么 | 缺什么 |
|---|---|---|---|
| 读代码仓库画图 | [Archify](https://betterstack.com/community/guides/ai/archify-architecture/)、[CodeGraph](https://github.com/NisargPatel03/CodeGraph)、[GitGraph](https://github.com/terrdv/GitGraph) | Agent 读仓库，节点能点回源文件和行号；Archify 先让 AI 写结构化描述、核对后再渲染 | 只做代码 |
| 个人数据做成设计作品 | [Feltron Annual Report](https://dublin.sciencegallery.com/lifelogging-exhibits/feltron-annual-report)（2005–2014） | 把一个人的一年做成精美报告 | 设计师亲手做，不能给别人用 |
| 健康 App 的年度报告 | Gyroscope | 每年一份个人报告 | 固定模板，人人一样 |
| 把人生存成给 Agent 读的 markdown | [LifeOS-OSS](https://github.com/kcwoodfield/LifeOS-OSS)、[picturpoet/life-os](https://www.mdskills.ai/mcp-servers/life-os) | 长期记忆仓库 | 只存不画；看板是固定表格 |
| 让 AI 凭记忆画出你 | 「画一张代表我人生的图」类提示词、[Life Note Inner Gallery](https://blog.mylifenote.ai/your-inner-gallery-art-that-grows-with-you.md) | 有趣、个性化 | 依据零散，数字无法追溯 |

**新在组合**：长期维护的结构化人生资料 + Agent 像读代码一样读它 + 由模型按这个人决定的设计 + 每个数字能点回原记录 + 给出评价（好在哪、坏在哪、可以怎么改、走到了哪）。这五点同时做到的，我们没有找到。

**这不是壁垒**：有一个 LifeOS 仓库再写一段好提示词，几天就能做出类似的东西。难复制的是开图的资料层：统一的记录格式、各来源的导入、多年修订历史、精确到行的出处。这一页的价值是把这一层展示出来。

## 4. 产品形态：一个按钮，一段提示词

- **按钮**：问问输入框上方的建议里加一个「生成我的人生开图」。点一下，就把一段固定的提示词发进问问，界面上不做别的改动。
  - 这是可行的：桌面共用的界面里已经有 `onPrompt`，方向、财务、健康等页面就是用它把一段文字送进问问的（`packages/dsh-plugin/src/client/index.tsx`）。新按钮复用它。
  - 不弹配置卡，不做权限确认，不放免责声明。用户自己看的东西，这些没有意义。读取范围沿用问问现有的边界。
- **提示词很短**，只写「按 life-portrait 技能，为我生成人生开图」。真正的说明写成一个 Skill：`templates/kaitu/.agents/skills/life-portrait/SKILL.md`。这样桌面问问、DSH 插件里的问问、外部 Agent（Claude Code、Codex）都能用同一份说明，以后改提示词只改这一个文件。
- **产物**：一个 HTML 文件，写进用户自己的开图工作区。生成后 Agent 在问问里给出文件路径，用户点开就在外部浏览器打开。第一版不内嵌进开图；以后可以从页面链回开图。
- **用户也可以自由点题**：同一个按钮生成总图；用户在问问里说「做一份阅读报告」「做一份工作报告」「把这三年写成一本小书」，Agent 照同一个技能来做。

## 5. 唯一的硬要求：不胡说

用户不需要免责声明，需要的是不出错。明明写了三个月的书，页面却说只写了一个月，这个功能就会被当成胡说八道。所以：

1. **所有数字、日期、时长、次数、排名，都必须来自工具查询的结果**（MCP、SDK 或 `kaitu` 命令），不能凭阅读印象估算。查不到的，就不写这个数。
2. **写完后自查一遍**：保存前，把页面里出现的每个数字逐个重新查询核对，对不上的改掉或删掉。这一步写进技能，作为生成流程的最后一步。
3. **原话一字不改**：引用的原话必须照抄，并带上来源路径。
4. **出处藏在页面里**：每个数字、每段原话都在页面内嵌一份来源（文件路径加行号或记录 id，以及当时的原文片段）。点一下就弹出来，像打开一个时光胶囊。不另外生成文件。
5. **关联只说「同时出现」**：比如「最焦虑的那两周，你读完了最难的那本书」，可以写；不写「因为……所以……」。
6. **空白照实留着**：没记录的月份就留空，不补造，也不借题发挥。

第一版不另做程序核对。如果试用中发现数字还是会错，第二版再加：Agent 先列一份依据清单，由程序复算后再写页面。

## 6. 页面长什么样：交给 Agent，但给它方向

- **像年度报告那样一页页翻**：每一屏讲一件事，配大字、颜色和动画，可以左右滑或者往下滚。
- **可以有音乐**：页面里用 Web Audio 现场合成背景音乐，按这个人的气质作曲。工程师可以是干净的合成器琶音，插画师可以是温暖的钢琴和弦。点一下才开始播放，有静音按钮。不加载任何外部音频文件。
- **轻松、好玩，不严肃**：可以有「你这一年最常写的词」「你最晚的一次记录是凌晨 3:12」「你提到次数最多的人」这类发现。不做「优点、缺点、整改建议」，不说教，不嘲讽。
- **建议包含**（不强制，由 Agent 取舍）：
  - 封面一句话画像；
  - 几个跨领域的发现；
  - 几段原话；
  - 结尾一屏「为什么把你画成这样」；
  - 底部一枚封存章：第几期、生成日期、基于多少条记录。
- **完全离线**：页面里不访问网络，字体、图片、音乐都内嵌或者现场生成。可以有本地脚本。

样张里的三种风格（工程图纸、水彩长卷、等高线地图）只是举例，不是模板。

## 7. 已拍板的问题

| 问题 | 决定 |
|---|---|
| 文件放哪、叫什么 | 用户自己的开图工作区，按现有 `reviews/daily`、`reviews/weekly`、`reviews/monthly` 的惯例，放在 `reviews/portrait/YYYY-MM-DD.html`。同一天生成多次，加 `-2`、`-3` 后缀。旧的不覆盖。 |
| 依据列多细 | 页面里出现的每个数字、日期、时长、次数和每段原话，都要有出处；形容和感受不需要。出处直接内嵌在页面里，不单独存文件。 |
| 程序复算的范围 | 第一版不做程序复算。靠第 5 节：数字只能来自工具查询，保存前逐个重查。试用后数字仍会出错，再加程序复算。 |
| 按钮放哪 | 问问输入框上方的建议里，一个按钮。 |
| 桌面应用和插件 | 都要有。两者共用同一套界面代码，问问在应用里走开图自己的会话，在插件里走 DSH 的会话，按钮用同一个 `onPrompt` 即可。iPhone 第一版不做生成，以后可以打开电脑生成好的文件。 |

## 8. 和现有人生地图的关系（只列问题，不在本草案决定）

现在的人生地图是程序生成的：带着从上游开源项目整个搬进来的地图生成器（约 1.56 万行），以及桌面、iOS 两套显示和同步代码，维护成本高。讨论过的一个方向是：
- 由 Agent 生成地图 SVG；
- 程序只负责把区域变成可点击的入口（区域链接到工作区路径）；
- 入口检查一次，不通过就继续用上一张。

这会动到人生地图的数据和显示方式，需要单独提案、单独确认格式（AGENTS 第 2 条）。人生开图上线、看过真实效果后，再决定地图要不要跟着改。

## 9. 不做

- 不做配置卡、权限确认、免责声明。
- 不做实时生成的界面，不替代今天、开图、资料、问问这些固定页面。
- 第一版不在手机上生成，不内嵌进开图，不做分享。
- 不新增数据格式；生成的 HTML 是普通文件。

## 10. 讨论过、没采纳的

| 提议 | 结论 | 理由 |
|---|---|---|
| 固定五个模块、四种题目各配一种视觉风格 | 只作为参考示例 | 写成模板就又变回人人一样的年度报告 |
| 生成前的配置卡（选资料范围、选语气） | 不做 | 用户要的是一个按钮；读取范围沿用问问现有的边界 |
| 「毒舌」语气、AI 打分 | 不做 | 定位是好玩，不是评判；尖锐判断错了会很伤人 |
| 把没读到的领域画成迷雾、待解锁 | 不做 | 等于暗示用户缺了什么 |
| 免责声明 | 不做 | 对用户没有意义；靠第 5 节保证不出错 |
| 程序先核对依据清单再出页面 | 推迟到第二版 | 先看只靠工具查询加自查，够不够准 |
| 从页面跳回开图、分享 | 推迟 | 需要链接协议和去敏的分享版 |

## 11. 怎么算做成

- 点按钮后，问问里出现那段提示词并开始生成，最后给出 `reviews/portrait/` 下的文件路径；桌面应用和 DSH 插件各走一遍。
- 三份风格迥异的合成工作区各生成一页，看起来明显不同，并且都能离线打开、音乐能播放。
- 每页随机抽 10 个数字和日期，与工作区原记录逐个核对，全部一致。合成工作区里特意放一个「写了三个月的书」的样例，页面不能写错时长。
- 在用户受控的资料副本上生成一次，由用户本人评价「好不好玩、像不像我」。
