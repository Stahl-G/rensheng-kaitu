# 提案：从「数据工作台」到「会跟进结果的行动助手」

- 状态：**待用户确认**（2026-10-15）
- 来源：外部产品审阅（基于孙宇晨访谈，对照 `adeb1d0` 静态审阅）；可核对的几条已在代码中确认。
- 范围：只整理产品改动和需要你拍板的点；P0 展示修正已另开会话处理，不在此列。

## 1. 一句话判断

架构不用换。现在开图擅长「把资料整理好给 AI 读」，缺的是「记得上次建议了什么、后来有没有用、下一轮改什么」。下面的改动都围绕这条闭环：

```
记录 → 建议 → 人确认 → 执行 → 结果 → 改下一轮
```

现状里最弱的是「结果」和「改下一轮」：复盘技能会写，但界面看不到，数据上也没把下一步和目标连起来。

## 2. 改动清单

| # | 改动 | 动数据规范？ | 建议时机 |
|---|---|---|---|
| A | 目标行动卡 | **是**（`goals.json` 加 3 个可选字段，`STATUS.md` 的 next 加 1 个可选字段） | 阶段 2 之后、阶段 3 之前（先落数据和技能） |
| B | 复盘改焦点：评估「做法合不合适」 | 否（只改技能） | 和 A 一起 |
| C | 开图任务：决策档案进入界面 | 否（复用 STATUS 已有的 `title` / `stage`） | 阶段 3 |
| D | 动态转行动 | 否（简报 Markdown 约定 + 技能） | 阶段 3 之后 |
| E | 新手引导改完成标准与文案 | 否 | 阶段 3（引导 PRD 在默认分支） |
| F | 交互细节并入阶段 3 设计输入 | 否 | 阶段 3 |

### A. 目标行动卡（最有价值，需要改 PRD §6.5）

每个活跃目标回答五个问题：想改善什么 / 正在尝试什么 / 实际发生了什么 / 下一步 / 什么时候重新判断。

**数据改动（最少）：**

`me/goals.json` 每项新增三个可选字段：

```json
{ "id": "g1", "title": "6 个月练出薄肌", "area": "health", "status": "active",
  "approach": "隔天练 40 分钟，先固定在晚上",
  "review_at": "2026-10-26",
  "progress": { "label": "已坚持", "current": 3, "target": 24, "unit": "周" } }
```

- `approach`：当前采用的做法（一句话，会随复盘改变）。
- `review_at`：下次回看日期。
- `progress`：目标自己的进度，取代现在借用模块 `STATUS.md.progress` 的做法（根除「同模块目标共用进度」）。

`STATUS.md` 的 `next[]` 每项新增可选 `goal: "g1"`，表示这一步服务哪个目标。

**「实际发生了什么」不新增存储**：由 core 实时计算。统计最近 7 天内 `goal` 指向该目标的 next 有多少条是 done / skipped / 仍 todo，再链接最近一份周复盘里该目标的段落。尝试过程和结果仍写在 Markdown 里，不建实验平台、不打分。

**确认规则（需要你定）：** PRD §7.5 现在规定改 `goals.json` 一律要人确认。建议细分如下：
- 改 `title` / `target` / `due` / `status`：仍要确认。
- 改 `approach` / `review_at` / `progress.current`：Agent 可直接写，存版本、可撤销，并在日报里说明改了什么。

否则每次复盘调整做法都要弹一次确认，闭环就转不起来。

### B. 复盘改焦点

改 `evening-review` / `weekly-review` 技能，不改数据：

- 周复盘对每个活跃目标只答三句：确实推进了什么？哪个安排和现实不匹配？下一轮只改哪一件？然后更新该目标的 `approach` / `review_at`。
- 同一条 next 连续 3 次 skipped 或被顺延：不再自动顺延，在 `NOW.md` 的 `attention` 里放一条，选项为「缩小这一步 / 换时段 / 等条件 / 停止这个目标」。选「停止」就把目标改成 `dropped`（需确认），界面上按正常结果显示，不按失败显示。
- 到了 `review_at` 的目标，早间计划把它放进 `attention`。

### C. 开图任务（不加第五个导航）

`decision` 技能已经覆盖选项、未知数、复议条件，缺的是界面入口和一个「现实小试验」：

- 技能改一处：分析完不止交付报告，至少产出一条「低成本、可撤回的小试验」作为 next（带 `goal`，如有关联）。
- 「我的」页加「正在探索」列表：读 `decisions/*/STATUS.md` 的 `title`、`stage`，以及正文第一段（当前判断）。
- 「今天」继续用已有的 `attention kind: decision` 提示需要拍板的事。

### D. 动态转行动

- `daily-feed` 技能：每天最多挑 3 条，在简报里用固定格式写「这改变了什么 / 和哪个目标或决策有关 / 建议：试一下｜更新判断｜继续关注」，其余条目只读不推。
- 界面上，这 3 条带按钮：「试一下」写成相关模块的 next，「更新判断」打开对应决策，「继续关注」不建待办。
- 依赖阶段 3 的对话抽屉，放在后面做。

### E. 新手引导

引导 PRD（`docs/prd/onboarding.md`，在默认分支）调整：

- 成功标准从「拿到第一份今天计划」改为「**第一次获得实际帮助**」。用户选一个主场景，开图交付「当前最重要的事 / 暂时不做 / 下一步 / 完成后回来告诉我」，其余六类能力稍后再开。
- 「连上助手」不再用「出现过写入记录」判定，拆成三项：已配置 / 最近成功（时间）/ 现在可用。
- 文案删掉「数据只存在你自己的电脑上」（Drive 模式下不成立）和「把数据都给 AI」，改为：「把需要持续跟进的事告诉 AI。开图保存记录、整理下一步，并根据结果帮你调整。资料由你掌握，分享范围由你选择。」

### F. 并入阶段 3 设计输入（只记录，不单独开发）

- 从卡片进入对话时自动带上目标、当前状态和上次决定，用户不用自己复制粘贴。
- 手机消息分三步反馈：「已收到，等待整理」→「已记录训练，另提取一项待办，可撤销」。正常完成的不打扰用户。
- 撤销单条记录和恢复到历史版本分开；恢复前列出影响范围（M4 遗留项）。
- 「今天」默认只突出 3 件事并说明理由，其余折叠，不再把各模块的 next 全部按优先级平铺。

## 3. 明确不做

实验管理平台、证据图谱、评分体系、默认多模型对比、新增导航页、把每条资讯都变成待办。

## 4. 定位文案（可选）

README 和引导首屏可改为：

> 开图，把你分散的个人记录变成持续有用的行动。AI 了解你正在做什么，帮你看清选项、安排下一步，再根据实际结果调整。你保留资料、决定方向，也可以随时更换助手。
