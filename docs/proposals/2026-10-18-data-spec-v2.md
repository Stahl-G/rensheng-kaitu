# 底层架构升级：投入、阶段、尝试与手机读写（数据规范 v2）

状态：用户 2026-10-17 已确认概念（投入的分法、工作日常算长期投入、记录统一标所属投入、尝试可挂在任何地方、阶段由 AI 发现后询问）。本文件把它们落成数据规范，供实现与审查。
落地时同步更新 PRD §6、`schemas/` 与 AGENTS.md 生成模板（AGENTS.md 第 2 条）。所有改动只增不改：旧工作区不迁移也照常可用。

## 1. 投入

开图围绕一个人「正在投入什么」组织资料。投入有两个维度：

- 领域：工作（work）、学习（learning）、个人（personal，爱好也在这里）。
- 形式：长期投入（日常职责、一直在学的方向、一个爱好，没有终点）和项目（有明确结果、会结束）。

| 形式 | 存放 | 说明 |
|---|---|---|
| 项目 | `projects/<slug>/STATUS.md`（已有） | `kind` 从 `work / personal` 扩为 `work / learning / personal`；阶段仍为想法、进行中、暂停、完成 |
| 长期投入 · 学习主题 | `learning/<主题>/STATUS.md`（已有） | 有资料、要点、观念变化的学习方向 |
| 长期投入 · 其他 | `me/ongoing.json`（新） | 工作日常、爱好、轻量的学习方向。每项：`id`（slug）、`title`、`domain`（work / learning / personal）、`status`（active / paused / ended）、可选 `note`、`since`（日期） |

- `me/ongoing.json` 与 `me/goals.json` 同等对待：用户维护，Agent 修改前先提议并等用户确认。没有这个文件等于没有长期投入。
- 爱好在界面上归入个人资料：不显示进度和完成度，只显示最近做了什么；不排进今天，除非用户自己给它加了下一步。

### 1.1 引用与标注

- 引用格式：`project:<slug>`、`learning:<主题目录名>`、`ongoing:<id>`。
- 所有记录可选字段 `investment`，写一个引用，加在 `record-base.schema.json`。原文（收件箱笔记）的 frontmatter 也可写 `investment`。
- 待办已有的 `project`（slug）继续有效，读取时视为 `project:<slug>`；新写入优先用 `investment`。
- 引用不存在时照常保存，由 `kaitu doctor` 提示悬空引用，不拒绝写入。
- core 提供 `listInvestments(ws)`：合并项目、学习主题和 `me/ongoing.json`，返回引用、名称、领域、形式、状态。还提供 `investmentOf(record)` 解析一条记录属于哪项投入。
- CLI 加 `kaitu investments`（`--json`），MCP 与 DSH 加只读的投入列表工具，供 Agent 写记录时选择引用。

## 2. 阶段

一段时间加一个名字（如「常出片期」「清闲工作期」），用来对照不同处境下人的状态。由 AI 从资料变化中发现并提议，用户回答一句回顾或确认后才算数。

- 记录类型 `phase`，放在 me 模块：`me/data/phases/{YYYY-MM}.jsonl`，schema `phase.schema.json`。
- 字段：
  - `title`
  - `start`、可选 `end`（YYYY-MM 或 YYYY-MM-DD）
  - `status`：suggested / confirmed / dismissed
  - 可选 `trigger`（触发这个阶段的变化，如「换了工作」「训练从每周 1 次变 3 次」）
  - 可选 `reflection`（用户自己的一句回顾）
  - 可选 `investments`（引用数组）、`source`
  - 修订沿用记录的追加修订规范
- 规则（在 core 写入入口检查一次）：
  - Agent 只能新建 `suggested` 的阶段、修改自己提议的文字，不能写 `reflection`，不能确认或忽略。
  - 确认、忽略和回顾只由用户写入。
  - 修改要带预期修订号，与方向探索一致。
- 本次只做数据、读写函数和只读工具。发现阶段的提示、每日整理里的询问和界面，随「阶段对照」功能一起做，以免产生用户看不到的建议。

## 3. 尝试与打卡

- `exploration_experiment` 的 `direction_id` 改为可选，新增可选 `investment`。尝试可以挂在方向下、任何一项投入下，或者都不挂。
- 新记录类型 `exploration_checkin`（尝试打卡），放在 explore 模块：`explore/data/checkins/{YYYY-MM}.jsonl`。
  - 字段：`experiment_id`、`date`、`done`（是否按计划做到）、可选 `note`。
  - 通过 `writeExploration` 新增 `create_checkin` 操作写入。
- core 提供纯函数 `completionRate(checkins)`：
  - 返回做到次数、总次数，以及完成率的 80% 区间。区间用 Beta(1 + 做到, 1 + 没做到) 计算，数据越多区间越窄。
  - 只描述「按计划做到的比例」，不算效果、不出因果结论。界面不写成「有效 / 无效」，与「证据强度不以未经校准的百分比展示」一致。
- 进度图的行：没挂方向的尝试暂不进入「接下来往哪走」，回看功能做时再定位置。

## 4. 手机读写（详见 [mobile/architecture.md](../mobile/architecture.md) §3–§4）

- `phone/` 是电脑生成的快照目录（today、week、map、receipts），手机只读。
  - 不当模块，不进本机版本历史，Agent 只读。
  - 格式见 `schemas/phone-*.schema.json`，样例在 `schemas/fixtures/phone/`。
- 手机写入 `inbox/agents/ios-<设备号>-<ULID>.*`：
  - 原文 `.note.md`（`kind: capture`）；
  - 记录 `.records.jsonl`（带 `origin`）；
  - 操作 `.actions.jsonl`（新格式，见 `phone-action.schema.json`）。
- GitHub 备份在连接后始终同步 `phone/`、`inbox/agents/`、`inbox/health/`，不受文字、结构化资料开关影响。
