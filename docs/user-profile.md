# USER.md：整理员写的一页近况

`USER.md` 是任何 Agent 进来先读的一页：用户是谁、在推进什么、这几天做什么、等用户决定什么。它由整理员（任何被用户指定的 Agent）每晚按 `ORGANIZER.md` 重写，正本仍是 `me/`、各模块 `STATUS.md` 和记忆。

- 整理员先把这一页写在当天每日整理的第一节「用户近况」，能覆盖文件的再写成根目录 `USER.md`。只能新建文件的整理员也能用：电脑开着时，比 `USER.md` 新的每日整理会被复制过去。
- frontmatter 与每日整理相同（`organizer`、`date`），正文不超过 1500 字，最后一行是「用户近况到此结束。」。不写健康记录、财务、心情、敏感记忆、Key 和本机绝对路径。
- 电脑开着时在刷新 `OVERVIEW.md` 的同一处核对一次：日期、长度、结尾、引用路径是否存在、是否引用了财务、敏感记忆或健康原始记录。结论写进 `OVERVIEW.md` 和 `AGENT-README.md` 开头；没通过的不复制、不改写，读者改读正本。
- `USER.md` 仍不进版本历史、GitHub 备份、下载检查和格式校验，云盘卸载它不阻断任何写入；本机工具不能写它。

2026-11-26 起不再由电脑生成（原来的 `kaitu profile-publisher` 已移除）：电脑生成的版本只在指定电脑开着时更新，电脑一关就停在旧日期，长条还会截成「节选，须回读」。旧的程序版 `USER.md` 没有 `organizer` 和 `date`，会被核对为未通过，直到整理员写出新的一页。

## 按需查找（读取端 v1）

`phone/library.json` 的可选 `navigation` 扩展由 `userNavigation` 生成。沿用 JSON Schema 的开放对象扩展与现有 `path/title` 命名；没有新增业务记录字段。扩展 `version: 1` 是能力握手，旧手机忽略，缺失或未知版本的手机保留原读工具。机器视图包括 `status`、`modules`（`path/title`）及 `files`（`path/title/updated_at`）；更新时间仅是来源修改时间，不是事实日期。路径复用已有源位置，无稳定 ID 的外部改名在下一次生成中删除旧入口、增加新入口。

这一片只索引 NOW、me 的档案/规则/目标/状态，以及项目、学习、决定的一层 STATUS/log/notes 原文。无摘要仍以标题或路径进入目录。扫描只检查这些文件及其必要祖先，不递归附件目录；无关附件的云占位不会使导航失效。目录不覆盖全文、附件、所有收件箱或记录；没有命中不能解释为没有资料。财务模块（含别名）在标题和数量生成之前按既有 handover 权限排除；记忆与纠正关系不复制到机器目录，仍走现有完整记忆折叠和受控读取。人看的 `items` 不进入 Ask。

文件保存与同步后沿用快照 watcher 的合并更新和每分钟对账；解析复用文件状态缓存。生成在同步函数内完成，没有异步模型摘要可晚到覆盖新正文。库快照原子替换；失败保留上次文件，来源占位时保留上次目录并标 unavailable，手机不使用其命中。App 未运行时不会承诺继续更新。

iOS 在准备时从本机缓存加载这份导航，仅注入范围、截至时间与检索方法；标题和片段必须回读当前允许的原文。每轮准备不再发现全树模块，读取具体文件时核对其模块身份；record_list 仍在需要时完整跨月折叠 id/rev/tombstone，未使用查询月份剪枝。搜索是标题/路径检索，分页原文仅约束模型输出；当前 store 仍可能完整下载一个命中文件，不能宣称减少了它的下载字节。

外部通用 Drive 文件读取不继承 Kaitu 的运行时权限。机器导航只导出上述非财务来源，不导出敏感记忆。给外部 Agent 的 AGENTS 说明指向同一入口，但不承诺所有 chatbot 都遵循。未来 MCP 可映射导航、搜索、证据三项读取能力；本轮不注册工具、不更新 npm。
