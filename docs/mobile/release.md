# 开图 iPhone：上架清单

更新：2026-10-18。范围：iPhone 上 App Store；Mac 走官网下载（第 6 节）。
标「待核实」的是没有读到苹果或监管原文、只来自二手资料的事实，动手前先核对原文。

负责人：**用户**（账号、法务、对外资料）、**Codex**（`kaitu-ios` 代码）、**设计**（我：设计稿、文案、验收）。

## 1. 先定下来的几件事

| # | 事项 | 现状 | 要做的 | 负责 | 状态 |
|---|---|---|---|---|---|
| R1 | 健康数据写进用户自己的 iCloud | 健康同步把 JSON 写进用户选的 iCloud 云盘文件夹。审核指南 5.1.3 有「不得把 HealthKit 数据存进 iCloud」的条款（待核实原文）；但 Health Auto Export 以几乎相同的模式（健康采集 → 用户自己配置的云端）在 App Store 正常销售，说明「用户自己选的存储、开发者看不到」的口径能过 | **不改现有设计。** 审核备注写明：数据只写进用户本人选择的存储（iCloud 云盘文件夹或私有 GitHub 仓库），开发者无法访问，不用于广告；隐私政策和隐私标签同一口径。被拒时的退路：iCloud 方式下不写健康数据，改由电脑导入 | 设计写备注，用户提交 | 保持现状，留退路 |
| R2 | 问问首次使用要明确同意 | 设置页只有一句说明 | 第一次提问前弹出：发给哪家服务、发什么（问题和读到的资料片段）、不发什么（Key、财务、敏感记忆）；用户点「同意」才发。设置里可撤回。新版指南要求向第三方 AI 发个人数据前明确告知并取得同意（待核实条款编号） | 设计画弹窗，Codex 实现（并入 ASK-4） | 待做 |
| R3 | 单独打开就能用（审核员没有电脑和资料位置） | 首次使用要选资料位置，否则空状态 | 加「看看示例」：内置一份合成工作区（与 `schemas/fixtures/phone/` 一致），只读，顶部一直显示「示例资料」；记一下在示例里只存手机本地。审核备注写明入口 | 设计画入口，Codex 实现 | 待做 |
| R4 | 功能单薄（审核指南 4.2） | 只做采集同步的 App 容易被判「功能太少」；Health Auto Export 能过，是因为有统计页和图表 | 不拿 v0.5（纯健康采集）上架，等 v0.6 的今天、开图、资料和确认流齐了一起提交；R3 的示例资料让审核员看到完整产品 | 用户定时间 | 等 v0.6 |

## 5. 中国区

| # | 事项 | 说明 | 负责 | 状态 |
|---|---|---|---|---|
| CN1 | App 备案（ICP） | 2023 年起中国大陆区上架需要备案号；个人可以办，约 1–2 周（来自二手资料，办理时以服务商要求为准）。两个选项：首发不勾选中国大陆区（你自己装 TestFlight 不受影响），或办个人备案再上大陆区 | 用户 | 商业决策：首发是否上大陆区 |

| CN3 | 国区版本 | 稳妥做法：国区先不带问问（入口不显示），其他地区带问问；用服务端无关的地区判断（App Store 地区），不靠 IP | Codex | 待定 |

## 6. Mac（Kaitu.app）

- 不上 Mac App Store：沙盒下很难调用本机的 Codex / CodeBuddy 等命令行 Agent，也难以读写用户任意选的文件夹。
- 用 Developer ID 签名加苹果公证，从 kaitu.si 下载；自动更新走签名校验。
- 负责：用户（证书）、Codex（打包脚本）。

## 7. 上架顺序

1. **v0.6 功能齐（R4）**，R2、R3 实现，A3、A4 页面上线，A6 申报。
   正在跑的 Beta 审核结果就是免费预演，审核员的问题记进本文件。
2. **TestFlight 外部测试**（要过一次 Beta 审核，正好先看审核员对 R1–R3 的反应）。
3. **海外区提交正式审核**：完整版。
4. **国区**：CN1、CN2 有结论后，按 CN3 提交。

## 8. 被拒时

- 先看审核员引用的条款，在本文件对应行记下原文和日期，再改。
- 解释类问题在 App Store Connect 回复，不急着重新提交；需要改代码的，改完在审核备注写明改了什么。
