# 开图 iPhone：产品规范（v0.6，含 v0.7）

更新：2026-10-18。依据 [PRODUCT.md](../PRODUCT.md) 的北极星与默认行为；实现方式见 [architecture.md](architecture.md)。设计稿见 [design/iphone](../design/iphone/README.md)。
iOS 工程在独立仓库 `kaitu-ios`（SwiftUI，现为 v0.5 健康采集器），本文件是手机端的产品依据。

## 1. 定位

- 电脑上的开图负责整理、回看和比较；手机负责随身的「今天」、一秒记下、关键确认，v0.6.1 起加问问。
- **合上管今天，展开看人生。** 窄屏只做今天；宽屏（折叠屏展开、横握大屏 iPhone、以后的 iPad）打开人生进度图。翻开手机就是「开图」。
- v0.6 手机是电脑的伙伴：今天的排序、进度图、一周近况都由电脑按同一套规则算好，手机读取并交回新记录和确认。v0.7 起电脑不在时，可由用户自己的云端 Agent 按同一套规则更新（见 [agent-runner.md](agent-runner.md)），手机界面不因此改。
- 普通 iPhone 是主要适配对象。折叠屏布局是加分项，随 2026-10-23 iPhone Duo 发售一起发布。
- 现有的健康自动同步（HealthKit → 开图）保留，成为手机端「自动积累」的一部分。

## 2. 用户与场景

首批是已经在电脑上用开图的人。典型时刻：

- 通勤时看今天最重要的一件事和待确认的日程。
- 饭后、训练后、冒出一个点子时，随手记一句或拍一张。
- 睡前勾掉做完的下一步。
- 周末展开折叠屏（或横过来），看这一周在工作、学习和个人上做了什么、进度图走到了哪。

## 3. 原则

1. 合上管今天，展开看人生。
2. 规则只有一份：排序、进度、近况按电脑的规则算（电脑，或 v0.7 起用户的云端 Agent），手机不另算一套。
3. 只交新文件，不改资料：手机写下的东西交给电脑处理，不直接改资料文件。
4. 状态如实：分清「已记下，等电脑处理」「已更新」「需要核对」；显示内容是几点生成的；没读到不等于没发生。
5. 不催：只在用户设定或确实需要确认时提醒；不做每日打分。
6. 资料去哪说清楚：存在哪、同步到哪、问问发给哪个 AI。
7. 日常操作 0.1 秒内有反馈、0.3 秒内完成（AGENTS.md）；等网络和电脑的事放后台，界面说明在等什么。

## 4. 界面

### 4.1 窄屏（所有竖握 iPhone、iPhone Duo 外屏）

底部标签：今天、开图；问问在 v0.6.1 加入，资料在 v0.7 加入，之后与电脑一样四个入口。「记一下」按钮在今天、开图、资料页都能点到；问问页底部换成提问框。

**今天**（自上而下）：

- 状态行：「电脑 07:30 更新 · 2 条等电脑处理」，离线时说明已存在手机上。v0.7 起由云端 Agent 更新时写它的名字：「Dot 07:30 更新」。
- 最重要的一件事：与电脑今天页同一条（前三项中的第一项）。可「完成」（v0.6 争取）。来自原文整理的待核对草稿显示「去电脑核对」，v0.6.1 起可在手机上核对。
- 下一步：其余最多两项。
- 待确认日程：时间与标题，可「确认」「不要」（v0.6 争取）。确认后由 iPhone 写进 Apple 日历的「开图」日历，经 iCloud 同步到电脑；电脑不再重复写。
- 你带来的规划：进行中的目标、各自的下一步、记过几次结果。
- 一周近况卡片：本周各项目的字数或提交、训练次数、平均睡眠、记下的原文条数；点开进入开图页的近况。
- 关键问题位：v0.6 预留，不显示。

**开图**（窄屏）：人生进度图（地图在上、「接下来往哪走」在下，线型与电脑一致：实线已经走过，虚线计划或在试，点线还没探索），以及一周近况详情。

### 4.2 宽屏（iPhone Duo 内屏、横握大屏 iPhone、以后的 iPad）

- 侧边栏：今天、开图、资料（v0.7）、问问（v0.6.1）。
- 默认打开「开图」，分两栏：左边约 60% 是人生进度图和一周近况，右边约 40% 是今天（最重要的一件事、下一步、待确认）。不用来回切页面。
- 展开、合上或旋转时保留当前所在页面、选中项和滚动位置；地图不重新加载、不闪白。
- 布局按系统给的宽度类别切换（SwiftUI size class），不针对某一款机型写死尺寸。以后做安卓折叠屏时，按同样的「窄 / 宽」两档对应安卓的窗口宽度类别。
- 预留（v0.7）：分屏时从其他 App 拖文字或图片进来，等同于「记一下」。

### 4.3 记一下

- 文字（多行）；语音（系统语音转文字，优先在设备上识别）；照片（v0.6 只在 iCloud 存放方式下可用，GitHub 等照片同步做完再开）。
- 可选标一项：从快照里的进行中项目和目标里选。投入（工作 / 学习 / 个人）的数据规范落地后，改为选投入。
- 保存后立刻出现在「等电脑处理」；电脑收下后显示为已处理。原文由电脑上的每日整理变成待核对草稿（现有能力），手机不在本地整理。
- 离线也能记，联网后自动交出。

### 4.4 系统入口

- v0.6：HealthKit 自动同步（保留现有）。
- v0.6.1：快捷指令与操作按钮——「记一下」「记一餐」「今天最重要的事」；小组件显示今天的焦点和更新时间。
- 之后：专注或训练进行中的实时活动、待机显示。
- 只使用 Apple 开发者文档里已经写明的能力；iOS 27 和 iPhone Duo 的新接口，核对文档后再用。

### 4.4a 资料（v0.7，只读）

- 列出最近和各分类（项目、健康、原文、我的）的资料，可搜索，点开看详情。不编辑；要改就用「记一下」或问问交进收件箱。
- 按需读：列表和搜索靠电脑（或整理员）生成的轻量目录 `phone/library.json`（标题、类型、日期、相对路径，不含正文），点开哪一项才读那个文件，读过的缓存在手机上。格式见 `schemas/phone-library.schema.json`（2026-10-18 用户确认）；电脑开着时随其他快照一起更新，整理员不写它，电脑不在时手机用上次的目录。
- 分类：项目、健康、财务、原文、我的。财务和标为敏感的记忆也列出，手机是用户自己的设备，功能和电脑一致（2026-10-19 用户决定）；敏感记忆在列表里标「标为敏感」。
- 设计稿：`docs/design/iphone/Library.dc.html`。

### 4.5 问问（v0.6.1）

设计稿：`docs/design/iphone/Ask.dc.html`；实现方案和选型见 [ask.md](ask.md)，任务拆分见 [tasks/](tasks/)。回答下面列出读了哪些资料；建议用卡片给出，「放进待确认」只交待确认建议，不替用户确认。

- 用户自己的 AI 服务 Key：DeepSeek 默认，先支持 OpenAI 兼容的服务（DeepSeek、Kimi、智谱、OpenAI），之后加 Claude、Gemini。费用由用户的 AI 服务收取；Key 只存手机钥匙串，不同步。
- 能读：快照和资料文件，与电脑上的问问相同，读不到 Key 和凭据。能写：只能按手机的写入方式交原文、记录和待确认建议；不能替用户采纳或确认。
- 对话存在手机本地，v0.6.1 不跨设备同步。
- 预留付费版：开图托管的 AI 服务（订阅后不用自己的 Key），与自带 Key 走同一个接口；v0.6.1 只留接口，不实现。
- 没配 Key 时提供「在原来的 AI 里继续」：把资料包分享给手机上的 ChatGPT、DeepSeek 等 App，对应电脑上的剪贴板协议。

### 4.6 设置与首次使用

- 选资料位置，和电脑用同一个：
  - iCloud：选电脑上用的那个 kaitu 文件夹。
  - GitHub：填 `owner/repo` 和只授权这个仓库 Contents 读写的 fine-grained token（v0.6 手动填写；GitHub 登录以后再做）。公开仓库默认不连，与电脑规则一致。
  - Google Drive、坚果云：通过「文件」选文件夹，尽力支持，不作为 v0.6 验收项。
- 状态：电脑上次更新的时间、等电脑处理的条数、最近一次出错的原因。
- 更新来源（v0.7）：电脑和云端 Agent 各自上次更新的时间；「交给 Agent 的说明」一键拷贝，资料仓库和时区自动填好；一句话写明 Agent 会读写这个仓库，读到的内容由它所在的服务处理。电脑开着时总是电脑更新。
- 健康同步设置保留现有内容。
- 还没有电脑生成的内容时：说明「在电脑上打开开图，选同一个存放位置，生成今天的内容后会出现在这里」；记一下和健康同步照常可用。v0.7 起同时给出「让我的 Agent 来更新」，拷贝同一份说明。

## 5. 状态文案

| 状态 | 中文 | English |
|---|---|---|
| 已交出，电脑还没处理 | 已记下，等电脑处理 | Saved, waiting for your computer |
| 电脑已处理 | 已更新 | Updated |
| 电脑处理时发现不对 | 需要核对：原因 | Needs a look: reason |
| 内容生成时间 | 电脑 07:30 更新 | Updated on your computer at 07:30 |
| 离线 | 已存在手机上，联网后交出 | Saved on this phone; will send when online |
| 云端 Agent 生成（v0.7） | Dot 07:30 更新 | Updated by Dot at 07:30 |
| 已交出，等 Agent 处理（v0.7） | 已记下，等 Dot 处理 | Saved, waiting for Dot |

用户写的内容、记录和 AI 回答保持原文，不翻译。界面语言跟随系统，中文或英文。

## 6. 隐私

- 手机只读写用户自己选的资料位置（iCloud 或用户的私有仓库），开图不经手。
- 电脑生成的手机快照不含 Key 和本机路径；财务和记忆照常给手机看，问问发给 AI 时按问问的规则（ask.md §4）。
- 问问发给 AI 服务的内容，与电脑上问问的说明一致；问问发布时同步更新隐私页。

## 7. v0.6 不做

资料编辑（v0.7 起可只读浏览）、财务、方向和尝试的编辑、在手机上整理原文、复杂图表、对话跨设备同步、安卓。

## 8. 版本与时间

- **v0.6.0**（10-22 提交 TestFlight，10-23 随 iPhone Duo 发售）
  - 必须：读取快照（iCloud、GitHub）；窄屏今天和开图；宽屏两栏；记一下（文字、语音）；状态与离线；普通 iPhone 和 iPhone Duo 模拟器截图。
  - 争取：完成下一步、确认日程；照片（iCloud）。
- **v0.6.1**（发售后一到两周）：问问（自带 Key）、快捷指令与小组件、在手机上核对草稿、投入标注（依赖数据规范）。
- **v0.7**：电脑不在也能用——用户自己的云端 Agent 当整理员，白天也更新手机（[agent-runner.md](agent-runner.md)）；尝试打卡与到期回看、关键问题、iPad、拖入、付费版接口评估；资料只读（浏览、搜索、看详情）；从照片找出去过的城市（[tasks/PHOTOS.md](tasks/PHOTOS.md)）。
- **之后：Apple Watch**。手表的数据（心率、训练、睡眠、步数）本来就经健康 App 进 iPhone，现有健康同步已能读到，不为数据单做手表版。手表版只做手腕上更快的几件事：表盘上显示今天最重要的事、抬腕语音「记一下」、尝试打卡一按「做到 / 没做到」、完成下一步。手表不单独连资料位置，写下的东西交给 iPhone，按手机的写入方式进收件箱，不加新格式。

上架准备见 [release.md](release.md)（健康数据与 iCloud、问问的同意、审核用示例资料三件事要先定）。

## 9. 验收

- 冷启动后从缓存显示今天不超过 0.3 秒。
- 合成工作区里，电脑更新后：GitHub 方式在下一次后台同步（每分钟）之后，手机下拉刷新能看到；iCloud 方式在系统同步完成后能看到，未下载的文件不当成没有。
- 离线记一下：保存成功、重启 App 仍在队列；联网后交出；电脑处理后显示「已更新」。
- 宽窄屏切换和旋转保留页面、选中项和滚动位置，地图不闪白。
- 快照版本高于 App 支持的版本时提示更新，不崩溃、不显示错误内容。
- 没有快照时空状态正确，记一下和健康同步可用。
- 中英文界面都能走完上述流程。
