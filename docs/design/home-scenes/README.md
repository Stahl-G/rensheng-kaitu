# 首页需求单：从生活场景开始（桌面与 iPhone 同一套）

日期：2026-10-24（第 2 版，按用户五点意见收紧）。状态：待交审。静态稿见本目录 `index.html`：浏览器直接打开，工具条可切换「第一次打开 / 有资料 / 有待确认」、浅色 / 深色、桌面 1200 / 900 宽；示例人物小林，全部合成。
依据：[BRAND.md](../../BRAND.md)、北极星「让 AI 真正了解你，并能持续接着帮你把人生往前推进」。

## 目标

打开 5 秒内看懂：开图能帮我记吃的、看身体变化、想方向，换个 AI 不用重新介绍自己，聊完的新变化也能留下。待办和日程是辅助，不定义产品。

## 最重要：先讲生活场景，不讲机制

首屏不出现「关于我 / 带给 AI / 留下新变化」这类机制名。它们是背后的资料流程，用户先看到具体场景：

| 场景卡 | 点下去做什么 | 背后的资料流程 | 能力 |
|---|---|---|---|
| 这顿吃得怎么样 | 写一句（复用同一个记录窗口）→ 估算 → 确认后记进饮食 | 留下新变化 | 见下方按端能力表 |
| 看看训练和身体的变化 | 看 30 天训练、睡眠、体重 | 关于我 | 两端已有，不用 AI |
| 除了现在这条路，还可以怎么走（桌面） / 看看去过的地方（iPhone） | 写一个方向、试一小步 / 看足迹 | 关于我 → 带给 AI | 桌面方向已有；iPhone 没有方向页，用已有的足迹 |
| 换个 AI，接着聊 | 勾选近况 → 仅复制所选内容 → 贴回回答 → 确认 | 带给 AI → 留下新变化 | 桌面已有；iPhone 要把旧的两步资料包换成一步 |

### 能力按端列清（只有接通的才显示）

| 能力 | 桌面 | iPhone |
|---|---|---|
| 写一句记下 | 已接通 | 已接通 |
| 语音 | 只有系统听写提示：不显示语音按钮 | 已接通：显示「说」 |
| 拍照记一顿 | 没有相机入口：不显示 | 问问能附照片，完整的「拍照 → 估算 → 确认入饮食」未核实：先不显示 |
| 营养估算 → 确认 → 记进饮食 | 只会跳到问问，确认界面待开发：卡片写「在问问里记这顿」 | 已接通（需接 AI）：显示「记这顿」 |
| 方向 | 已接通 | 没有页面：不显示 |
| 用示例试资料包 | 待开发 | 待开发 |

规则：

1. **每张卡写清**：用户能完成的那个动作、要不要接 AI、资料去哪（一小行，如「存进你的资料」「只发你勾选的」「确认后才算数」）。
2. **能力标注**：交审稿里每张卡标「已有，不用 AI / 已有，需接 AI / 待开发」。产品只上线「已有」的卡；待开发的不显示，不放「即将推出」。需要 AI 但没接时，卡片仍能用：先原样存下，并说明接上 AI 或复制给自己的 AI 可以做什么。
3. **图片**：有资料时只用用户自己的照片（开图相册、餐食照片）和由真实记录画出的图、真实足迹地图；新用户用标了「示例」、来源可查、可商用的插图；不用摆拍图库图。
4. **不做假分析**：数字只来自真实记录，估算一律标「估算」；资料不够写「还没有记录」。不评价人，不做人格、饮食打分；Fortune 等插件的推测结果不进首页。
5. **不催**：不自动轮播，不显示逾期，不用红色，不出现完成率、连续天数。
6. **卡片从数据读**：按用户在开图里保留的模块和顺序；用户隐藏了健康，首页不推健康。最多三张场景卡，加常驻的「换个 AI，接着聊」和一个「记一句」。场景卡里自然的操作（如「记这顿」）可以保留，打开的是同一个记录窗口，不另做记录入口。
7. **一个主按钮**：新用户「写下这一句」；有资料时「选择要带的内容」；有待确认内容时「去确认 N 条」（放到记一句下面，换个 AI 的按钮降为次要）。场景卡都是次要入口。
8. **不设门槛**：新用户不必先写一句，可以直接「用示例试一下」资料包（内容标「示例」，不含用户信息）。

## 资料去哪，固定写在卡上

「换个 AI，接着聊」卡底常驻一行：资料在哪里，按用户实际选的位置和文件夹名显示，不写死 iCloud 或 kaitu-ai-memory。复制按钮旁写「仅复制所选内容到剪贴板，不会自动发给任何 AI」，不用「发送」一类字眼。敏感内容、涉及他人的内容、录音转写默认不勾。MCP、给 Agent 的一句话、云端接力收进「更多连接方式」，首页不出现 MCP、Hook、工作区。

## 推进不能丢

首屏底部固定一行「现在这件事」（完成 / 交给 AI）和「等你确认 N 条」。日程和其余待办放到下方或资料页。

## 新用户

主按钮是「写下这一句（关于自己）」，旁边是「用示例试一下」和「带入已有聊天」，三条路都不设门槛。不用 Key、不用云盘就能完成第一次记录。场景卡内容是示例，标「示例」。

## 桌面与 iPhone

- 桌面：日期与天气 → 记一句 → 三张场景卡横排 → 「换个 AI，接着聊」 → 现在这件事 / 等你确认。
- iPhone：日期 → 记一句 → 第一张场景卡完整展示（带图）→ 其余场景卡 → 「换个 AI，接着聊」（清楚的入口，有资料时是唯一的实心按钮）→ 现在这件事。快捷入口只放已接通的（目前只有语音）。
- iPhone 去掉今天页的「再开一块地图」「档案柜」入口，以及新手流程里提前出现的搬记忆。

## 与现有页面

按本单重排 main 上的 #220 生活首页和设计稿 C 的今天页：保留记一句、资料包、天气；健康和方向从首页大卡变成场景卡（数据从模块读）；日程放到下方；去掉重复的随手记入口。同步修改 PRODUCT.md「今天」的定义。

## 边界

只重组现有前端，不改数据结构。不以「接了 AI」为卖点，不承诺 ChatGPT、Gemini、Claude 能自动写回。Hook 单独验收，没实现就显示手动入口。

## 交审与验收

- 交审附：场景卡对照表（场景名、动作、背后流程、能力标注、图片来源）；新用户和有资料两种状态；桌面两档宽度加 iPhone，浅色、深色各一套。
- 交审稿要覆盖：三种状态 × 浅色 / 深色 × 桌面 1200 / 900 宽和 iPhone（本目录稿已覆盖，开发截图按同样组合交）。
- 小样本理解检查（不是开工门槛）：拿静态稿给几个不太用 AI 的人看，记下他们能否说出其中两件（记吃的、看身体变化、想方向、换 AI 不用重讲），有没有人把首页说成待办清单，用来调文案和顺序。
- 没有 Key、没有云盘：1 分钟内写下第一句并找回。
- 每张卡点一下都能完成一个真实动作。

## 审稿重点

陌生人第一眼会不会仍以为是待办？不用 AI 有没有价值？每张卡能否完成真实动作？用户看不看得懂资料存在哪里、哪些会发给 AI？「这顿吃得怎么样」不接 AI 时是否诚实？图片是不是用户自己的，示例有没有标？
