# 今天页 v4：不是日程表

设计稿：[`index.html`](index.html)，用 `?view=both|desktop|phone&state=new|data|pending&theme=light|dark&width=1180|900` 切换。稿子里可以切换精力档、挑一件事，也可以回答问题。
v3 以及 Gemini 的 v4 方案都把首页做成了按时间排的流水账，本质上还是日程表，本版取代它们。

## 这一页回答什么

日程表回答「几点做什么」。今天页回答的是：**我现在是什么状态？此刻做点什么最值得？** 不会用 AI 的人不用写提示词，也能得到答案。

## 四样东西

1. **镜子**：两三句话，只说数据里查得到的事实，比如「摄影集十天没动了，上次是从 80 张筛到 34 张。训练这个月 12 次，比上个月多 3 次。这周平均晚睡 40 分钟。」
   - 标出的词可以点开，看到它来自哪条记录。
   - 不写评语、建议和分析。
   - 数字由代码算，不由模型生成。
   - 没有足够数据的那一类就不说。
2. **此刻，挑一件就好**：按此刻的状态（有一小时 / 只有十分钟 / 有点累）给 2–3 件小事。
   - 每件都写明「为了：某个目标」，事项来自目标、在试的事、各模块的下一步。
   - 不写几点做，没有截止，不会变红，也不打勾、不统计完成率。
   - 「有点累」这一档里，「什么都不做也行」是正式选项。
   - 挑中一件后变成「在做：……」，下面是「做完了，记一句」和「换一件」。
3. **开图想问你**：每天只问一个问题，随口答一句就行，答案作为原文保存。
   - 没连 AI 时按规则出题：目标很久没动、资料缺了一块、刚定的目标还没说清楚为什么。
   - 连了 AI 后由 AI 出题，仍然每天只问一个。
   - 问题下面不写解释。
4. **随手记一句、带去别的 AI 聊**：
   - 「带去别的 AI 聊」是有资料时唯一的主按钮。点开是侧栏：上面勾选要带的内容（财务默认不勾），下面显示即将复制的原文。
   - 今天记下的流水不放首页，最多一行「今天记了 4 条 · 在资料里」。

## 三种状态

| 状态 | 首页 | 主按钮 |
|---|---|---|
| 第一次打开 | 「开图还不认识你。先从一件事说起。」 + 第一个问题「最近有什么事，是你想改变的？」 + 三个导入入口 | 写下这一句 |
| 有资料 | 镜子 + 此刻 + 开图想问你 | 带去别的 AI 聊 |
| 有建议待看 | 镜子下面用一条淡色虚线列出 AI 留的建议，桌面每条行尾有「确认 / 不用」；iPhone 上，手机原本就能处理的日程建议保留「确认 / 不要了」，其他类型（记忆替换、下一步建议）写「在电脑上确认」 | 不设深色按钮，「带去别的 AI 聊」降为次要 |

## 样子

- 沿用设计 C 的纸色和墨蓝，深色模式同样处理。
- Mac 沿用现在顶部的四个入口（今天、开图、资料、问问）。iPhone 用底部四个标签，加常驻的「随手记一句」输入条。
- 镜子和事项用衬线字，界面文字用系统字。
- 整页只有「开图想问你」一个框，其余靠留白和细线分区。
- 不画插画、不放指标卡、不加进度条，标签不加方括号，不用等宽字体。

## 交给 Codex 的任务

**要做成什么**：一个 P 人打开今天页，十秒内能说出自己最近什么样，并在不看任何时间表的情况下挑一件事开始做；第一次打开的用户不用懂 AI，回答一个问题就开始了。桌面 App、DSH 插件、体验站和 iPhone 都按本稿实现，细节由你决定。

**怎么证明**：
- 用合成工作区，三种状态都要截图：1200 和 900 两种宽度、浅色和深色，外加 390 宽的手机尺寸。
- 找一个没看过开图的人，看首页十秒后，请他说出「这个人最近怎么样」和「他现在可以做什么」，把原话记进 PR 描述。
- 镜子里的每个数字都要能对上来源记录。
- 日常操作在 0.3 秒内返回。

**材料**：
- 本设计稿。
- 现有的目标、在试的事、各模块 STATUS 的下一步、健康记录。
- 体验站源码 `packages/dsh-plugin/src/testsite`。

**不能碰**：`schemas/` 的数据格式。「每天一个问题」的答案先按原文记录保存；如果需要新字段或新记录类型，先停下来问用户。

**这次要新做的**：
- 按精力档挑选事项。精力档只是当天界面上的一个选择，不写进数据。
- 每天一个问题的出题规则。
- 镜子那几句事实的计算。

### 文案规则（必须遵守）

**不要写免责声明，不要写「不代表」。** 产品要做到的事由代码做到，不靠一句话保证。

- 不写「不代表」「不构成」「仅供参考」「仅用于」。
- 不写「不会上传」「不会自动发给任何 AI」「不经过第三方服务器」「查看不会……」「本预览不……」。
- 不加「示例」角标，不加「现有能力 / 待开发」说明条，也不写「只展示已有记录」「不用 AI」这类功能边界说明。
- 不写解释机制的整句话，图表下面也不加「实线为……圆点为……」这类说明。
- 不写打卡、完成率、连续天数、逾期，不出现几点几分的安排。
- 健康页「不做诊断」写进 AGENTS.md 给 Agent 看，不出现在界面上。
- 一个控件旁最多一行短说明，能用一个词就不用一句话。
- 确实需要用户知道的边界，只在用户真正要做那件事的那一步说一次。
