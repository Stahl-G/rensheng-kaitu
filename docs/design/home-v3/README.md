# 首页 v3：去掉 AI 感

> 已被 [home-v4](../home-v4/README.md) 取代：v3 把首页做成了按时间排的流水账，仍然是日程表。下面的文案规则在 v4 继续有效。

设计稿：[`index.html`](index.html)，用 `?view=compare|desktop|phone&state=new|data|pending&theme=light|dark&width=1200|900` 切换。
改前截图：`before-desktop.png`、`before-phone.png`（现在的体验站，有资料状态）。

v2 的原则不变：场景优先、一屏一个主按钮、不加逾期压力和完成率、存放位置按实际配置显示。v3 只改「怎么摆」和「怎么说」。

## 问题

现在的首页是一页功能介绍：三张同样大小的卡片，每张都是插画、标题、一句说明、分割线、带箭头的链接。插画和用户的资料无关，所有块都套着同一种圆角细边框，标题像广告语，真实数字缩在小字里。用户一眼就看出这是生成的。

## 改法

1. **首页是这个人的今天。** 按时间列出今天的真实记录（训练、饮食、随手记），右侧是关键数字，不再放功能卡。
2. **不画插画。** 只用这个人自己的数据，比如体重 30 天折线。没有数据就不画，留白。
3. **少用框。** 用留白和细线分区。新用户只有输入区一个框；有资料时整页没有卡片。
4. **数字放大，用等宽数字。** 数字大，说明小，各块高度可以不一样。
5. **标题写名词。** 今天、身体、在试的事、下一步、去过的地方。不用问句和口号，链接不加箭头。
6. **「带给 AI」不单独占一张卡。** 有资料时，「选择要带的内容」就是日期旁边的主按钮。有待确认时，主按钮换成「去确认 N 条」（iPhone 上是「查看」），原来的主按钮降为次要。
7. **Mac 用左侧边栏。** 今天、开图、资料、问问四项竖排，底部按实际配置写存放位置。iPhone 保持底部四个标签。

### 文案规则（必须遵守）

**不要写免责声明，不要写「不代表」。** 产品该做到的事由代码做到，不靠一句话向用户保证。下面这些一律不加；现有的，在首页、体验站和官网上一并删掉：

- 「不代表……」「不构成……」「仅供参考」「仅用于……」
- 「不会上传」「不会自动发给任何 AI」「不会确认或采纳」「查看不会……」
- 「本预览不……」「此项需要正式 App；本预览不运行 AI……」：改成一个能点的动作，比如「在 App 里打开」，或者直接不显示这个入口。
- 「示例」角标，以及卡片底部写着「现有能力／待开发」的说明条。
- 「只展示已有记录」「不用 AI」这类功能边界说明。
- 解释机制的整句话，比如「这是资料来源标记为需要核对的内容，原文已保存……」。

其他：
- 一个控件旁边最多一行短说明。能用一个词说清，就不写一句话。
- 健康页「只做记录、不做诊断」是给 Agent 的规则，写在 AGENTS.md 里就够了，不要出现在界面上。
- 确实需要用户知道的边界，只在用户真正要做那件事的那一步说一次。比如真正要发送到外部服务时，才弹出确认。
