01 产品定位与范围
Kaitu 开图产品需求文档
版本 1.0 日期 2026 年 10 月 15 日 面向产品 设计与研发
Kaitu 保存、组织和展示用户的长期个人状态，让兼容的 AI Agent 可以接续工作。用户在熟悉的 AI 中记录生活，在开图直接看到项目、健康、财务和人生经历的变化，并探索新的方向。
产品目标
降低重复解释与手工整理成本；让重要数据无需提问即可查看；把建议、尝试和结果放在同一份长期档案中。开放数据、跨 Agent 接续和持续可视化共同构成产品价值，实际留存仍需通过试用验证。
事项本版定义
核心方向统一个人档案、独立可用的可视化界面、兼容 Agent 接续、自动生成真实地图上的地点经历。
目标用户已使用 AI 助手、资料分散且有多个长期项目或生活目标的个人；首批验证对象为愿意导入资料的早期用户。
主要交付Web 工作台与开放数据协议；照片读取和新位置记录通过可选 Mac 或 iPhone 配套组件补充。
首期不做自建通用聊天平台、自动证券交易、替用户决定人生、全量后台定位、与独立财务软件同等复杂的会计体系。
成功体验一次记录被正确处理，用户打开页面看到更新，另一 Agent 读取到同一结果；地图自动生成，用户只需处理少量疑点。
需求状态与决策边界
已明确方向：界面简洁，弃用灰绿主色；地图应允许 Agent 自动标点；尽量利用记忆、历史资料和照片，减少用户维护。建议方案：黑白灰配少量蓝色、探索三层结构、MapLibre、具体数据模型与版本优先级。待验证：Apple 历史定位接口、财务适配器和云端连接器的实际权限。
本 PRD 定义目标行为，不证明仓库已实现这些功能。既有代码、分支和 Drive 接续协议需在实施前核对；新增接口与目录均为建议，不以概念图中的示例数字、记录或日期作为真实需求数据。
02 信息架构与首次使用
入口主要内容首期要求
总览近期变化、进行中项目、下一步、选定指标可追溯，可跳转到来源与明细
探索方向、世界地图、时间线共用经历与探索数据，避免重复建档
项目目标、里程碑、GitHub、作品记录区分开发活动与实际进展
财务总览、收支、投资、账户区分现金流、本金和投资收益
健康训练、饮食、身体指标、习惯明确记录与估算，无综合健康评分
记录原始资料、变更、待核对、交接支持来源查看、纠错与回滚
设置个人档案、连接、权限、同步、导出学习与具体决策首期作为关联对象
FR 01 首次建立档案
用户创建工作区，选择导入记忆文本、导出的聊天记录或资料文件；也可跳过导入。系统预览识别出的经历、地点、目标和项目，自动提交明确内容，将歧义集中列入待核对。不得暗示能无授权读取所有 AI 平台的隐藏记忆或完整历史。
导入保留来源、原始文本、识别时间和解析版本；姓名相同的他人、小说角色及假设案例不得写入用户事实。用户可移除整批导入并看到影响范围。首次进入展示真实数据的空状态，示例数据必须显著标示且与个人数据隔离。
FR 02 个人总览
默认展示近期变化、正在推进的项目与下一步；健康和财务指标仅在有记录且用户选择展示时出现。指标应显示统计区间、单位、截止时间及估算标记，点击进入组成记录。没有数据时显示未连接或暂无记录，不能以零代替未知。
更新流区分用户修改、外部系统同步和 Agent 处理；显示主体、时间、变更摘要与来源。允许隐藏模块、调整顺序和选择关注项目；不以全站聊天框占据主入口。
首次价值与验收
导入一份含明确经历与计划的文本后，系统能够生成档案、项目或地图中的至少一种有效视图；用户能从展示结果回到原文。计划中的旅行必须进入计划层，不能显示为已到访。无模型运行时，已有数据仍可浏览和纠错。
03 多 Agent 读写与交接
FR 03 统一读写契约
本地 Agent 可通过 CLI 或 MCP 接入；云端 Agent 通过实际可用的连接器、受控 API 或收件箱文件接入。对外承诺兼容协议的 Agent 可接入，不承诺所有平台无需配置即可读写。每个连接展示可读、可新建、可更新、可删除的实测能力。
建议提供读取概览、查询记录、提交变更、查询提交结果和写交接五类能力。工具名称与传输方式可以不同，业务对象及操作语义必须一致。只支持新建文件的连接器也可提交变更请求，由处理器更新正式状态。
FR 04 提交与提交结果
每次写入携带 request_id、agent_id、schema_version、来源、操作、目标对象及 expected_revision。新增记录支持幂等键；同一请求重试不得重复入账或重复标点。正式数据由处理器校验并提交，收件箱写入成功不等于业务提交成功。
状态含义与用户反馈
received 或 validating已接收或处理中；展示排队原因与提交编号。
applied已提交正式状态；返回新 revision、受影响对象与更新时间。
needs_review 或 conflict信息不足或并发冲突；保留双方变更，进入待核对。
failed明确错误类型与可重试性；不假装已更新，不无限循环等待。
FR 05 并发与恢复
采用工作区级单写入队列或等效的原子事务控制，配合版本比较。Drive 上一个 LOCK.json 的读后写不能自动构成可靠互斥；如保留锁文件，只作为协议状态展示，互斥由支持原子操作的协调层保障。锁必须带 owner、有效期和租约信息，超时可恢复。
已由用户修正的字段不得被较旧同步自动覆盖。冲突发生后 Agent 写入未决事项，并返回明确结果；不要求用户反复询问进度。处理器崩溃后可从持久化队列继续，部分失败须能识别已提交与未提交部分。
FR 06 交接记录
交接包含处理者、时间、读取的 revision、做了什么、未完成原因、下一步及关联 request_id。新 Agent 先读当前概览与近期相关交接，必要时查原始记录；以当前状态为准，不能仅凭旧交接覆盖新事实。
04 云端同步与数据来源
FR 07 电脑关闭时仍可接续
核心数据浏览、云端请求提交、验证和状态更新不依赖个人电脑常开。建议使用持久化作业队列、处理器和版本存储；Google Drive 作为用户持有资料及开放文件的同步载体。权威版本、外部直接编辑及冲突规则须统一，禁止两个独立主库静默分叉。
核心模块数据采用可导出的 JSON 或 JSONL，摘要与交接可用 Markdown；概览是可重建的派生结果。读取端展示最后成功处理时间与来源新鲜度。处理器不可用时保留上次有效状态及待处理队列。
来源接入方式状态边界
记忆与聊天用户导入文本或导出文件；支持的连接器读取授权范围内处理；没有连接不声称已获取
Google Drive连接器读取及提交请求，云端处理器合并分别验证列目录、读取、新建、更新能力
GitHub官方 API 获取指标，缓存或云端定时任务AI 分析与数据抓取分离
照片图库可选原生组件读取元数据；或导入原始照片本地组件离线时暂停新增同步，已有页面可用
账单与持仓文件上传，预览、映射、去重后提交文件格式版本、币种与期间均需检查
日历和行程授权连接器或用户导出资料预订和日程先记为计划，不直接当成到访
FR 08 导入作业与失败反馈
所有批量导入先建立作业，记录文件哈希、解析器版本、识别记录数、新增数、重复数、冲突数与失败原因。支持断点恢复、取消、查看问题行和撤销整批；源文件内容按资料处理，不能执行其中的指令。
连接失效时引导重新授权，不删除既有记录。数据不足时给出具体缺项；对持续失败设置有限重试和退避，并提供可理解的失败摘要。
部署候选与验收
Cloudflare Worker 等云端任务或 Google Apps Script 可作为原型候选，最终取决于认证、执行时长、队列及并发能力，不在 PRD 中提前绑定。验收必须包含个人电脑关机后两名 Agent 的连续提交、状态回读与冲突处理。
05 项目与 GitHub 集成
FR 09 项目基本对象
项目保存目标、当前状态、里程碑、障碍、下一步、作品和关联方向；可绑定远程仓库、本地仓库或文稿。项目进度由明确里程碑或用户定义任务计算，展示分子、分母及范围变化，不用提交数量推算完成率。文稿字数作为产出指标，不作为质量评分。
FR 10 GitHub 自动同步
用户粘贴仓库 URL，系统解析 owner/repo 并核验；公开数据优先直接 API 读取，私有仓库使用最小范围授权。GitHub 提供数据，开图保存状态与历史，Agent 解释变化；抓取基础指标不需要 Agent Runtime。[1][2]
数据产品展示规则
Star 与 Fork展示最新总量、查询时间和历史快照；新增事件与净总量变化分开。
Issue 与 PR分开统计，避免把包含 PR 的开放计数当作纯 Issue 数；处理分页。
Commit 与 Release展示近期活动和最新发布，允许按分支与时间段过滤。
CI展示目标分支最近运行及结果；未配置、无权限、失败分别显示。
Milestone 与 Projects后续映射真实计划状态；GitHub Projects 读取作为独立验证项。
流量及克隆仅在相应权限和数据窗口可用时显示；不作为首期依赖。
历史与限流
从首次同步开始保存定时快照；没有历史数据就标明开始日期，禁止绘制虚构历史曲线。此前提及的星数历史专用端点不作为已确认依赖，补历史需另外核验当前官方接口与数据语义。
使用缓存和条件请求；授权仓库可评估 webhook。按官方限流响应退避，避免前端重复刷新引发请求风暴；GitHub 官方说明未认证和认证请求额度不同，应用应读取实际限流头而非把额度写死。[2]
验收
公开仓库首次绑定后可显示真实 Star、Fork 与同步时间；API 失败时保留旧数据并标过期。仓库改名、归档、删除或权限撤销可识别。两次相同同步不产生重复活动；Star 下降必须允许显示，不能强制增长。
06 统一财务模块
FR 11 四种财务视图
财务总览展示现金、投资资产、负债和净资产；收支页展示收入、消费与结余；投资页展示持仓、成本、估值、分红与收益；账户页展示币种、余额、关联交易及同步状态。总资产与净资产分别命名，避免混淆。
FR 12 账单与持仓导入
支持微信、支付宝、银行账单及同花顺投资账本或券商实际可导出的持仓、交易文件。解析前检测格式和列结构，显示预览、字段映射及期间；若平台没有所需官方导出，则接受实际可用文件，不承诺某种 Excel 一定存在。截图识别为增强能力，金额、日期及证券代码需保留识别疑点。
业务情形必须遵守的统计口径
银行卡转入证券账户账户间转账，不算消费；配对转出与转入，避免双算。
卖出证券卖出款拆分本金及已实现收益；全部卖出款不能作为工资类收入。
分红及手续费分红、税费、交易成本独立记账；说明收益计算是否已扣费。
退款与借贷退款关联原交易；借款本金和偿还本金独立于消费，利息另记。
多币种估值保留原币金额，显示折算币、汇率来源和日期；无汇率时标缺失。
持仓快照仅有快照时不能可靠还原全部现金流或期间收益；未知项不填零。
FR 13 对账与收益
去重采用来源交易 ID 与内容特征；疑似转账进入待核对。记录实际收入、消费、投资资金流及收益四类口径。收益金额需区分已实现与未实现，收益率须明确算法和所需数据；现金流不完整时仅显示可计算的估值变化。所有总数可下钻到原始记录。
接入路径与复用候选
默认云端文件导入，无需电脑常开；本地增强可研究 dsh-ths-holdings 或 opencli-plugin-tzzb 的登录会话读取。Bookkeeping、AutoCoin、chicang、THSDK、AKShare 均仅为前文讨论的候选组件，集成前逐项验证仓库可用性、许可证、格式和数据权限。A-Stock Studio 暂不列为可依赖组件。
行情与持仓接口分开；登录 Cookie、证券交易密码不进入共享工作区。第一阶段只记录、查询和分析，不提供下单权限。验收包含重复账单、跨账户转账、退款、多币种与缺少成本数据的持仓。
07 个人档案与生活记录
FR 14 个人档案
集中维护经历、能力、兴趣、价值偏好、目标、时间与现实约束。事实、用户表达的偏好和 AI 推测分别保存；推测有依据及待验证状态。重要变化采用追加或版本更新，不能把历史偏好直接当成永久属性。
FR 15 健康与习惯
支持通过自然语言记录训练项目、组次、重量、距离、时长、饮食以及用户提供的身体指标。单位标准化并保留原始表达；缺失重量或时间允许为空。饮食热量如由 AI 估算，必须明确估算与依据，不冒充测量值。
健康页显示周月训练频率、运动量和各身体指标的独立趋势；不将体重、心情、财务等不同量纲放进同一条“生活质量”曲线。下一步支持新增、改期、完成、取消，保留修改者与历史。
FR 16 学习 作品与具体决策
学习记录关联课程、阅读、笔记、技能证据与下一步；作品记录关联文稿、照片、代码及成果。首期可嵌入项目与记录视图，后续根据使用频率决定是否升为一级入口。
具体决策对象保存问题、选项、约束、依据、用户选择及复盘。探索模块管理尚未明确的问题和发展方向，具体决策管理有边界的选择，两者通过关联 ID 互通，不复制原始资料。
FR 17 待核对与纠错
将歧义地名、重复交易、冲突时间及无法解析的字段集中处理，支持批量接受、修改、忽略。明确记录可自动提交；仅当歧义会改变关键结果时请求用户判断。用户修改后记录 corrected_by_user，并防止旧来源重新导入覆盖。

输入或操作预期结果
深蹲 3×12 60kg结构化为训练、组数、次数和重量；重复提交不重复记。
跑步 5 公里 用时 30 分钟保存距离与时长；派生配速注明计算来源。

另一 Agent 接手读到最新记录与下一步；能区分已提交、待核对和处理失败。
08 探索模块的三层体验
FR 18 第一层 方向总览
探索首页展示正在研究的问题和方向，以作品缩略图、资料摘要、当前状态、最近发现与下一步组成横向内容条目。方向可以是“这个产品是否有人持续使用”，无需全部预先设为职业、财务等固定分类。支持收藏、暂停和归档。
右侧显示与关注方向相关的新发现，每条附来源、时间和与用户的关系。AI 提出的新方向标为建议，用户可忽略；不以虚构匹配分数、人生成功概率或能力排名促使用户接受。
FR 19 第二层 方向详情
默认展示动机、假设、已有依据、反面证据、仍未知、正在尝试和认识变化。相关资料、项目和具体决策以引用关联；区分“我希望”与“AI 推测”。支持资料、尝试、变化记录三个子视图。
实验记录问题、行动、投入上限、期限、观察标准与结果。完成行动不自动代表假设成立；结果可支持、反驳或仍不足。用户最终决定继续、改变或暂停方向。
FR 20 第三层 探索轨迹
以已发生的经历与证据按时间串联，当前尝试可延伸少量条件分支；节点展示真实资料或作品缩略图。实线表示已发生，虚线表示尚未验证。没有可证实关系的事件不强行连因果线。画布是按需使用的辅助视图，不作为首页唯一交互。
FR 21 主动探索与复盘
建议提供可开关的每周机会发现、每月个人变化回顾、每季度方向复盘。首次不自动创建通知任务；用户启用后选择频率、来源范围和是否通知。只推送新增且相关的变化，重复内容合并，无实质变化不制造日报。
每个机会包含外部来源、发布时间、适用地点或远程属性、与个人情况相关的解释、未知条件及低成本下一步。机会失效或截止后标记过期。健康和财务数据是否参与某次分析由授权范围决定。
验收
从一个方向可追溯到依据、实验及结果；一次负面反馈能改变或暂停方向而不删除历史。无地理属性的创作与产品目标仍能完整呈现，不要求绑定城市。
09 真实地理人生地图
FR 22 地图作为探索主视图之一
探索入口支持方向、世界地图、时间线切换，三者共用数据。地理地图展示与用户有实际关联的地点；用户不需要反复手工插图钉。Agent 提交结构化地点经历，地图根据保存的数据自动标点。
图层内容判定规则
走过的地方求学、生活、工作、旅行及相关照片需要可追溯到访依据；时间精度如实保留。
现在的生活当前居住、工作与持续参与的地点当前状态应有时效，不因一张照片推断常住。
计划与机会已计划行程、用户收藏、AI 推荐地点计划与建议分别标识，不能混入已到访层。
FR 23 浏览与时间
地图为主区域，地点卡片与地图双向定位；点击标记打开经历详情、来源、照片、关联项目和纠错入口。缩小时按城市聚合，放大后按许可精度显示地点。同一地点的多次访问在详情中按时间区分。
底部时间轴支持年份和日期区间，含持续经历与跨期事件。时间未知的记录进入独立筛选，不强制排到当前日期。只有确有迁移或行程关系时显示连线；连线表示地点关系，不冒充实际 GPS 路径。
FR 24 自动生成与用户控制
明确事实自动加入；模糊地名先解析城市或区域，候选冲突进入待核对。模型不得直接猜经纬度；地理编码服务返回坐标、匹配精度与候选。仅知道城市时显示城市级标记，不使用城市中心冒充具体到访点。
用户可改地点、时间、分类、封面或隐藏记录；支持撤销批次与排除来源。默认私人可见，敏感地点可降精度；任何分享前展示将包含的范围，家与工作精确地址不默认公开。
地图渲染与验收
推荐评估 MapLibre GL JS 与 GeoJSON，另选可用底图、地名检索和地理编码服务，满足署名、费用和地区覆盖要求。[3] 需标记坐标参考系，避免不同来源坐标混用。
验收：重复访问不丢失；计划不变成到访；城市级记忆与精确照片能正确关联但不强制合并为同一次访问。地图瓦片不可用时仍可用列表查看经历，数据不因地图服务故障消失。
10 自动重建历史与 Apple 接入
FR 25 记忆与资料提取
提取人、地点、起止时间、活动、事实状态和依据；使用原始消息时间及其时区解析“昨天”等相对日期。区分记录时间与事件发生时间。“预计毕业”“准备出差”“想去”保留计划语义；小说场景与转述他人经历不得写为用户到访。
FR 26 照片辅助重建
授权后的 Mac 或 iPhone 组件通过 PhotoKit 读取可访问资产的定位和创建时间；iCloud Photos 同步图库可以成为该路径的数据来源。[4][5] 默认先读元数据，缩略图与原图使用单独控制；不给云端 Agent 整个图库访问权作为前提。
按时间邻近与地理邻近聚合为候选经历，阈值可配置；保留每个原始资产引用。截图、转存照片、他人共享照片、缺少 GPS 或时钟异常的资产降低可信度或排除。没有拍照的时间段不推断连续停留，照片位置不自动等于用户位置。
支持增量扫描、来源删除后的处理规则、批次撤销和有限图库授权。用户导出原始照片后也可读取可用元数据；Apple 提供导出未修改原件的路径，但具体定位字段是否存在须逐文件检查。[6]
FR 27 Apple 位置数据能力分层
能力产品承诺
iCloud Photos通过授权原生图库组件补充元数据；不承诺一个通用云端 iCloud 登录即可读取全部资料。
苹果地图去过的地点官方说明支持查看且端到端加密，并有地区限制；第三方批量读取尚未验证，不作为首期依赖。[7]
历史位置 APIrequestHistoricalLocations 已有文档条目；系统版本、权限、回溯范围及可用性需独立实机验证，不承诺多年轨迹。[8]
接入后的新访问可评估 Core Location 访问事件，获得近似位置及到达离开时间；由授权和系统调度决定，不保证实时或每次到访均捕获。[9]
实施顺序与验收
先用记忆生成城市级骨架，再以照片补历史，再接日历及行程，最后评估新访问监测。原生组件停机只影响新增同步。验收覆盖定位缺失、照片转存、夏令时、仅年份日期、重复同步、有限授权和权限撤销。
11 统一数据模型与开放协议
以下为建议逻辑模型；正式目录与现有仓库协议对齐。个人数据只保存一份，地图、概览和 Agent 摘要均由同一批业务对象派生。
对象主要字段与规则
Source来源类型、定位符、内容哈希、采集时间、授权范围；可回到原文。
Place稳定 ID、标准名称、坐标、坐标系、地理精度、地理编码提供者与候选。
Experienceplace_id、事件类型、开始结束、日期精度、时区、事实状态、source_ids；同地可多次。
Direction 与 Opportunity问题、动机、假设、依据、未知、有效期、相关地点或远程属性。
Experiment 与 Decision问题、行动、投入、期限、判断标准、结果、用户决定和复盘。
Project 与 MetricSnapshot目标、里程碑、来源绑定；指标名、值、单位、口径与观测时间。
Account 与 Transaction账户、原币金额、交易类型、对手账户、交易 ID、转账配对和对账状态。
HoldingSnapshot 与 Valuation证券标识、数量、成本、价格、汇率及日期；缺失成本不能估算为零。
HealthRecord 与 Action项目、单位、原始表达、是否估算；下一步时间、状态、关联对象。
ChangeRequest 与 Handoff请求 ID、操作者、预期版本、操作、处理状态、结果；交接关联请求。
公共字段与状态
业务对象共用 id、schema_version、revision、created_at、updated_at、source_ids、visibility、created_by、corrected_by_user。事实状态 observed、user_reported、inferred、planned、suggested 分开；证据强度不以未经校准的百分比分数展示。
时间字段允许空值、年份、月份、日期或精确时间；time_precision 与 timezone 必须同时表达语义。金额保留原币精度；时刻可存 UTC 并保存原时区，全天事件不得因 UTC 转换跨日。
Agent 接口建议
read_overview、query_records、resolve_place、submit_changes、get_change_status、write_handoff。新增地点经历属于 submit_changes 的一种业务操作；返回 applied 后再刷新 GeoJSON。接口支持字段级更新、expected_revision 与 idempotency_key，拒绝未经校验的全库覆盖。
建议将探索结果放在 explore/，经历与地点记录分开保存；已有 me/、projects/、health/、finance/、learning/、decisions/ 通过 ID 关联。路径为建议，迁移需保留旧 ID、版本与导出兼容性。
12 界面与交互规范
视觉方向
采用冷白、墨黑、中性灰为底，少量蓝色用于选中、主操作和当前路线。建议色值：背景 #FAFAFC、表面 #FFFFFF、次级区域 #F2F3F5、主文字 #202124、强调色 #5260E8。该配色为试验方向，尚未作为最终视觉定稿。
弃用大面积灰绿、米白养生感、泛滥渐变和装饰性等高线。以文字层级、留白、真实作品和来源建立吸引力；减少重复卡片边框。界面默认不出现 Token、schema、锁租约等实现细节，必要时在诊断页提供。
参考产品的使用边界
参考 Linear 的目标、项目和更新层次，Are.na 的内容集合与关联浏览，Obsidian Canvas 的资料画布，以及 AFFiNE 的文档与白板切换。[10–13] 参考交互原则，不复制品牌或将其功能描述为开图已实现能力。
页面默认交互
总览一眼看到变化与下一步；点击指标进入记录，来源与日期始终可查。
探索首页方向列表搭配真实资料缩略图；近期发现独立呈现，允许暂停方向。
方向详情以可读档案为主；依据、实验、结果形成关联，按需进入轨迹画布。
世界地图地点列表与地图联动；图层与时间筛选常驻，详情按选择展开。
手机布局列表或地图单视图切换，详情使用底部面板，避免桌面三栏强行压缩。
同步和纠错集中显示待核对与失效来源；普通使用不要求用户理解并发机制。
可访问性与异常状态
状态不能只靠颜色区分；提供图标和文字。地图标记与关键操作支持键盘导航，列表是等价替代。加载、空数据、无权限、过期、部分成功与失败分别有状态；用户可关闭动画，地图缩放不阻断阅读。
概念稿处理
既有生图只用于探索布局，图片内生成的日期、星数、访谈、链接和文字均不进入真实产品数据。真实地理地图尚需独立原型验证；不把被否定的中心节点式人生树作为实现基线。
13 版本规划与成功指标
优先级为建议排期，不代表已承诺的人力或发布日期。首先验证数据接续与地图自动生成，再扩展来源和深度分析。
阶段交付范围进入下一阶段的条件
P0 可用闭环个人档案导入；总览；项目与公开 GitHub 基础指标；健康记录；云端提交与交接；记忆生成城市地图；基础方向详情；账单和持仓文件各一种已验证格式。两名不同 Agent 接续成功；电脑关闭仍可处理；无重复入账、无静默覆盖；地图有来源可纠错。
P1 数据与体验照片元数据配套组件；地图时间轴与详情；财务对账和多币种；私有 GitHub；探索实验与轨迹；自定义总览。来源撤销、增量同步、批量撤销可靠；试用用户能独立完成关键任务。
P2 持续探索日历与行程接入；可选新访问记录；主动机会研究与复盘；更多行情和账单适配器；高级学习与决策视图。明确留存价值；成本、授权与数据完整性达到约定要求。
衡量指标
首次价值：从开始导入到出现第一份可追溯有效视图的时间。接续成功率：已接受的有效请求中，成功提交并被另一 Agent 正确读回的比例。自动整理正确率：抽检自动提交记录中地点、时间、类型均正确的比例。纠错负担：每 100 条导入记录需用户处理的疑点数。
使用价值：首次使用后 7 日与 30 日回访、查看来源及纠错完成率、实验结果记录率。项目 Star 是用户项目指标，不作为开图产品留存的替代。避免把导入条数、模型调用次数当作核心成功指标。
质量与性能建议目标
发布前门槛：核心回归集不得出现静默覆盖、重复财务入账、无依据精确标点。建议初始性能预算：正常网络下缓存概览 P95 在 2 秒内显示、轻量写入 P95 在 60 秒内返回业务结果，批量导入异步展示进度；正式阈值经目标设备与部署压测确认。
以不少于 1 万条经历与 5 万个元数据条目的测试数据验证聚合、分页和导入恢复；记录测试环境，达不到预算时减少首屏数据或分页，不删除用户记录。
14 端到端验收清单
编号场景通过条件
AC 01导入含真实经历、计划和小说的记忆正确区分主体与状态；小说不成为到访；每条经历有来源。
AC 02Agent A 记训练，Agent B 改下一步第二 Agent 读到已提交最新状态，交接包含处理结果。
AC 03重试同一变更和同一账单结果幂等，无重复记录；不同来源的同一交易可标为候选重复。
AC 04两 Agent 同时改同一字段成功串行处理或显式冲突；任何一方变更不静默丢失。
AC 05电脑关闭及处理器中断恢复云端功能继续工作；恢复后可查请求结果，不重复提交。
AC 06GitHub 限流与权限撤销保留最后有效值并标过期；合理退避，不能显示为零 Star。
AC 07转账、卖出、退款、汇率缺失按定义计入；不能把本金算收益，缺少数据不生成虚假收益率。
AC 08照片时间与记忆冲突保留不同证据；不随意覆盖，进入待核对。
AC 09城市级经历和同城多次访问地点共用，经历分开；时间未知如实展示，标记精度可辨。
AC 10照片无 GPS 或是转存资产允许跳过或成为候选；不能仅靠画面猜到访事实。
AC 11用户纠错后重复同步保留修正；旧数据不重新覆盖。删除或忽略记录不自动复活。
AC 12计划旅行取消与机会过期保持计划历史并更新状态；不计入已走过地点。
AC 13停止连接与导出迁移停止后续采集；可导出数据、来源关系和版本，凭据不随数据导出。
AC 14实验失败或方向暂停保留依据与结果，更新方向状态；不把行动完成视为假设成立。
AC 15地图不可用与移动端使用可用列表读同一经历；主要操作与来源详情可访问。
验收方法
采用脱敏或合成样本建立预期结果，再用用户主动提供的数据验证体验。每次验收记录输入、预期、实际、版本与失败原因；示例数据不得混入正式工作区。外部连接器按能力矩阵分别验收，不能由一个 Agent 的权限推断所有 Agent 都能写入。
15 实施依赖与待决事项
事项现阶段决定或下一步
既有仓库与协议实施前核对当前默认分支、模块、CLI/MCP、Drive 协议与测试；本 PRD 不替代代码审计。
权威存储与协调层明确正式记录、Drive 文件与缓存的主从关系；先验证原子提交及外部编辑检测。

金融适配器逐一验证许可证、维护状态、真实导出样本及行情使用条件；先保证计算口径。
GitHub 历史与 Projects基础指标可先做；历史 Star 补齐及 Projects 字段另行验证，不沿用未经核验的端点。

数据与权限边界
按工作区、来源和数据类别控制访问；只向执行某项任务的 Agent 提供必要数据。照片原图、财务明细与精确位置可分别关闭。用户可查看连接、撤销授权和删除或导出记录；删除需说明衍生摘要与备份的保留策略。
凭据放在服务端密钥存储或设备安全存储，不放共享 Markdown、JSON 或日志。导入文本及网页不是系统指令；解析器与 Agent 不执行来源文件要求的越权动作。默认不公开个人地图。
实现评审应产出的结论
确认 P0 的最小格式集合、存储和提交路径、地图数据供应商、两种真实可用 Agent 接入方式以及云端运行预算；以第 14 节验收用例拆分工作项。每项未知接口需有验证结论或可用替代路径，再进入开发承诺。
