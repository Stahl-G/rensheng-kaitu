# 小说工作台与科幻校对：本地试用

两个独立 DSH 插件包：`kaitu-novel-workspace`、`kaitu-sf-consistency`。当前为本地开发版，未发布到市场。科幻插件通过 Cordis 的 `kaituNovelData` 服务依赖小说插件；关闭科幻插件后，作品资料、交接和候选稿仍可用。

## 用法

在 DSH 中打开“小说工作台”，点“让 Agent 整理”，或直接在会话里说：

> 整理这部小说。自己找当前正文和世界书，导入设定，再检查低重力动作。

Agent 使用 DSH 已有的文件读取和 grep。插件提供作品索引、资料存储、世界书导入、校对记录和本机计算，不替代宿主文件工具。已关联项目的目录就是入口；版本说明和 README 用来区分当前稿、工作稿和归档。

作品默认只读。要续写时可以切换“续写候选 → 允许保存续写候选与合稿”，或明确让 Agent 启用续写模式。Agent 先读原稿样本、世界书与交接，保存独立候选。用户要求合稿时可以接到 Markdown/TXT 原文末尾，保留原文备份和撤销；DOCX 先导出候选 Markdown，交给原编辑器合稿。

## 安装到隔离 DSH

构建后将两个包的 `dist/index.js` 加入 DSH profile 的 patch（参考 `packages/novel-plugin/cordis.example.yml`）。配置 `workspace` 指向已有开图工作区。省略时沿用开图默认工作区定位。无需模型 Key 即可浏览、改状态、保存手工交接、审阅已有结果；Agent 整理与续写用 DSH 已配置的模型。

插件市场以 npm 包安装；本轮只制作本地包，不执行发布。安装名及包配置已准备，市场下载需要后续发布授权与实际注册。

## 数据与范围

- 复用开图现有项目 ID、目录链接及当前 React 视觉样式。
- 索引、资料、世界书和续写数据位于本机项目状态目录 `novels/<project>/`，不插入原稿 ID。
- 小说数据 `novel.json`；科幻数据 `science.json`；合稿备份位于 `source-backups/`。停用插件保留这些文件。
- 按文件或标题建立场景；读取 Markdown、TXT，DOCX 复用开图已有的文本提取器。DOCX 引用行号为提取文本位置。
- 世界内时间、叙述顺序和真实写作时间分别记录。未定义日期不自动补成写作日期。
- 世界书导入保留原文及出处，候选标题保留待定状态；AI 新推断与原文资料分开。
- 现实月面重力用 NASA 常用近似值 1.62 m/s²，直接作为科学参考；作品的人工重力、时期和局部例外另行判断。
- 字数口径 v1：汉字逐字，连续其他语言字母／数字按词，排除 YAML、代码块和 Markdown 标记；字符数单列。

## 复用核查

2026-10-16 读取了 [Novalist](https://github.com/Drommedhar/novalist-official) 的 package.json（3.3.0）、MIT 许可证及第三方许可清单。它使用 Electron、React 与 .NET，直接引入会重复宿主和正文编辑器，本轮未复制其代码或运行其应用。

[Novel Word Count](https://github.com/isaaclyman/novel-word-count-obsidian) 的 package.json 为 5.0.0，LICENSE 为 MIT，构建依赖 Obsidian API。本轮未复制其代码或引入 Obsidian 运行时。仅借鉴目录汇总的交互方向，字数口径单独公开。

Write Like Me 当前环境提供风格参考的检索与写作流程，未发现可直接嵌入 DSH 的同名 SDK。本插件采用“先读作者指定样本，再依据其叙述视角、句式、对白和节奏续写”的流程，没有调用或复制其私有后端。

## 给外部 chatbot 续写（2026-10-17）

在“续写候选”填写本次要求，点击“整理外部续写提示词”。按钮把整理任务放入 DSH 聊天草稿；发送后，本地 Agent 自行读取当前正文、相关世界书与作者样本，输出一份可复制到 Gemini 等外部模型的完整 Markdown 资料包。资料包应包含接点原文、前情、人物状态、有效设定、伏笔、文风样本和写作要求，不能用本地路径或工具调用代替内容。整理资料包在只读模式也可使用。“在 DSH 中续写”保留原有本地续写流程。

本轮验证：类型检查、构建和打包通过；内置浏览器实测作者要求、场景、目录及交接进入聊天草稿，点击按钮不会自动发送。本轮未向 Gemini 提交书稿，也未实测外部模型的成稿质量。
